::: testing
Whether you know what a variable **is** at the hardware level: a name for a fixed number of bits in memory, interpreted as a type. The interviewer is checking that you can:

1. List the basic types (integer, character, floating point, boolean, pointer) and say what each is for.
2. Give sizes and ranges, and know that sizes can depend on the platform (so firmware uses fixed-width types).
3. Explain signed versus unsigned, two's complement and overflow behavior.
4. Explain floating-point precision limits, and why `0.1 + 0.2 != 0.3`.
5. Compare static typing in C with dynamic typing in Python.
6. Avoid classic pitfalls such as mixing signed and unsigned or multiplying in too narrow a type.
:::

::: why
Every bug involving "the number is wrong" comes back to a variable's type: an ADC reading overflows a 16-bit intermediate, a sensor value goes negative because it was stored as unsigned, a timer count wraps, an accumulated float stops increasing. Hardware engineers read and write registers of exact widths, store sensor data in limited memory, and do arithmetic on microcontrollers where an `int` may be 16 bits. Knowing the types, their ranges and their failure modes is what makes firmware and test scripts correct, and it is the base for later questions on strings ([[q0969]]) and `volatile` ([[q0970]]).
:::

::: concepts
- **Bits and bytes**: $n$ bits hold $2^n$ distinct values; a byte is 8 bits. See [[q0893]].
- **Two's complement**: how signed integers are stored; range $-2^{n-1}$ to $2^{n-1}-1$. See [[q0893]].
- **Fixed-width types**: `int8_t`, `uint16_t`, `uint32_t` from `<stdint.h>` have the same size on every platform.
- **IEEE 754 floating point**: sign, exponent and mantissa; limited precision and range.
- **Pointers**: variables holding addresses; their size is the address width of the platform. See [[q0942]].
- **Endianness**: byte order of multi-byte values in memory. See [[q0875]].
- **Static vs dynamic typing**: C fixes the type at compile time, Python attaches types to values at runtime.
:::

::: answer
"The basic types are integers, characters, floating-point numbers, booleans and pointers. In C, an integer type like `int` or `short` stores a whole number in a fixed number of bits, signed or unsigned. A `char` is a small integer, usually 8 bits, used for characters. `float` and `double` store real numbers in IEEE 754 format, 32 and 64 bits. `bool` holds true or false, and a pointer holds a memory address.

The important thing for hardware is size. The size of `int` depends on the platform, 16 bits on some microcontrollers and 32 on most others, so in firmware I use fixed-width types like `uint8_t`, `uint16_t` and `int32_t`. An 8-bit unsigned goes from 0 to 255, a 16-bit from 0 to 65,535, a 32-bit up to about 4.29 billion. Signed types use two's complement, so int8 goes from minus 128 to 127.

Two things bite people. Overflow: an unsigned 8-bit 250 plus 10 wraps to 4, and signed overflow is actually undefined in C. And floating point: a float has about 7 decimal digits of precision, so `0.1 + 0.2` isn't exactly `0.3`, and a float can't count above 16.7 million in steps of one. In Python, types belong to values and are checked at runtime, integers have arbitrary size, and `float` is a 64-bit double."
:::

::: technical
**Integer types and ranges** (two's complement for signed):

| Type | Bits | Range |
|---|---|---|
| `int8_t` | 8 | −128 to 127 |
| `uint8_t` | 8 | 0 to 255 |
| `int16_t` | 16 | −32,768 to 32,767 |
| `uint16_t` | 16 | 0 to 65,535 |
| `int32_t` | 32 | −2,147,483,648 to 2,147,483,647 |
| `uint32_t` | 32 | 0 to 4,294,967,295 |
| `int64_t` | 64 | about ±9.22 × 10¹⁸ |

An $n$-bit unsigned type holds $0\ldots 2^n-1$; a signed one holds $-2^{n-1}\ldots 2^{n-1}-1$.

**Standard C types.** `char` (at least 8 bits; signedness is implementation-defined), `short`, `int`, `long`, `long long`, `float`, `double`, `_Bool`/`bool`, pointers, `enum`, `struct`, `union`. The standard guarantees only minimum sizes; on a typical 64-bit Linux machine the sizes of `char/short/int/long/long long/float/double` are 1/2/4/8/8/4/8 bytes, but 16-bit microcontrollers have a 2-byte `int`.

**Floating point (IEEE 754).** `float`: 1 sign, 8 exponent, 23 mantissa bits; $\epsilon = 2^{-23} \approx 1.19\times10^{-7}$ and about 6 to 7 significant decimal digits; maximum about $3.4\times10^{38}$. `double`: 1 + 11 + 52 bits; $\epsilon = 2^{-52}\approx 2.22\times10^{-16}$, about 15 to 16 digits. Most decimals like 0.1 are not exactly representable in binary: `0.1f` is stored as 0.100000001490116...

**Overflow behavior.** Unsigned arithmetic wraps modulo $2^n$ (defined). Signed overflow is undefined behavior in C. Converting an out-of-range value to a signed type is implementation-defined (typically wraps), e.g. `int8_t b = 127; b = b + 1;` gives −128 on common compilers.

**Python.** Dynamic typing; `int` is arbitrary precision, `float` is a 64-bit double, `str`, `bool`, `list`, `tuple`, `dict`; types are attached to objects, not variables.
:::

::: long
"At the lowest level a variable is just a name for some bits in memory, and the type tells the compiler how many bits and how to interpret them.

The main categories: integers, characters, floating point, booleans and pointers. Integers come in several widths, and in embedded code I use the fixed-width ones from `stdint.h`, `uint8_t`, `int16_t`, `uint32_t`, because the plain `int` has a platform-dependent size: 16 bits on some microcontrollers, 32 on most. An unsigned n-bit value holds 0 to 2 to the n minus 1, so 8 bits is 0 to 255 and 16 bits is up to 65,535. Signed integers use two's complement, so 8 bits gives minus 128 to 127. A `char` is really a one-byte integer used for characters. A `float` is 32-bit IEEE 754: one sign bit, eight exponent bits and 23 mantissa bits, about seven digits of precision. A `double` is 64-bit with about 16 digits. Pointers hold addresses, so their size is the address width.

Then the pitfalls. Unsigned overflow wraps: 250 plus 10 in a `uint8_t` is 4. Signed overflow is undefined behavior. Mixing signed and unsigned in a comparison converts the signed value to unsigned, so `-1 < 1u` is false. Intermediate arithmetic has to be wide enough: with a 12-bit ADC reading of 4095, multiplying by 3300 to convert to millivolts gives 13.5 million, which overflows 16 bits, so I cast to `uint32_t` first.

Floating point has its own traps. 0.1 isn't exactly representable in binary, so you compare with a tolerance. A 32-bit float can only represent integers exactly up to 16,777,216, so adding 1 to it does nothing.

In Python the type belongs to the value, integers have unlimited size, and floats are 64-bit doubles. That makes it forgiving, but it means the same precision issues for floats and no wraparound to warn you."
:::

::: terms
- **Variable**: a named region of memory holding a value of a particular type.
- **Fixed-width integer**: type with exact bit width (`uint8_t`, `int32_t`), independent of platform.
- **Two's complement**: signed integer representation where the MSB has weight $-2^{n-1}$.
- **Overflow / wraparound**: a result exceeding a type's range; unsigned wraps modulo $2^n$.
- **IEEE 754**: standard floating-point format (sign, exponent, mantissa).
- **Machine epsilon**: the smallest relative spacing between floats (about $1.19\times10^{-7}$ for float32).
- **Integer promotion**: C rule that small types are converted to `int` in expressions.
- **Pointer**: a variable holding a memory address.
- **Static / dynamic typing**: type fixed at compile time versus carried by values at runtime.
- **Implementation-defined / undefined behavior**: what the C standard leaves to the compiler versus places no requirements on.
:::

::: mistakes
- **Assuming `int` is 32 bits everywhere.** On many 8- and 16-bit microcontrollers it is 16 bits. Use `<stdint.h>`.
- **Computing in a type that is too narrow.** `uint16_t adc = 4095; adc * 3300` overflows if the arithmetic is 16 bits wide (13,513,500 mod 65,536 = 13,084). Cast to `uint32_t` first.
- **Mixing signed and unsigned.** `int i = -1; unsigned u = 1; i < u` is false because `i` converts to a huge unsigned number.
- **Comparing floats with `==`.** `0.1 + 0.2 == 0.3` is false; compare with a tolerance.
- **Thinking `char` is always signed.** Its signedness is implementation-defined; `char c = 200;` prints -56 on common platforms with signed `char`.
- **Using `float` for counters or accumulators.** Above 16,777,216 adding 1 has no effect in a 32-bit float.
:::

::: deep
## Variables are bits plus an interpretation

Memory stores only bits. The type tells the compiler (a) how many bits to use and (b) what operations make sense on them. The same eight bits `1100 1000` mean 200 if read as `uint8_t`, −56 if read as `int8_t`, and a particular character if treated as an extended-ASCII `char`.

You can explore that with the base converter: set 8 bits and the value `0xC8`, and compare the unsigned and signed readings.

```sim
{"id":"base-converter","value":"0xC8","bits":8}
```
Figure: The same 8-bit pattern 0xC8 reads as 200 unsigned and −56 in two's complement. Change the bit width to 16 or 32 and watch how the signed value changes meaning when the sign bit moves. This is exactly what `char c = 200;` printing -56 means on a platform with signed `char`.

## Integers: ranges and wraparound

For $n$ bits there are $2^n$ patterns. Unsigned types use them for $0\ldots2^n-1$. Two's complement gives the top bit weight $-2^{n-1}$, so the range is $-2^{n-1}$ to $2^{n-1}-1$ with one more negative than positive value.

| Bits | Unsigned max | Signed range |
|---|---|---|
| 8 | 255 | −128 … 127 |
| 12 (typical ADC) | 4,095 | n/a |
| 16 | 65,535 | −32,768 … 32,767 |
| 32 | 4,294,967,295 | −2,147,483,648 … 2,147,483,647 |
| 64 | 1.8 × 10¹⁹ | ±9.22 × 10¹⁸ |

**Wraparound** is arithmetic modulo $2^n$. A `uint8_t` at 250 plus 10 gives $260 \bmod 256 = 4$. This is *defined* for unsigned types, and is exactly how a free-running hardware timer counter behaves, a feature you use when computing elapsed time with `now - start` even across a wrap. Signed overflow, by contrast, is undefined behavior in C: the compiler may assume it never happens and optimize accordingly, so an overflow check written as `if (x + 1 < x)` can be deleted.

**Integer promotion and mixed arithmetic.** Small types are promoted to `int` in expressions, and when signed and unsigned of the same rank meet, the signed value is converted to unsigned. So:

```c
int i = -1; unsigned u = 1;
if (i < u) { ... }      // false: i becomes 4294967295
```
The expression evaluates to 0. Compilers warn about this with `-Wsign-compare`; turn the warning on.

## A worked firmware example: ADC to millivolts

A 12-bit ADC with a 3.3 V reference returns `adc` in 0 to 4095. The voltage in millivolts is $\frac{adc\times3300}{4095}$.

- Done in 32 bits: $4095\times3300 = 13{,}513{,}500$, divided by 4095 gives 3300. Correct.
- Done in 16 bits (an AVR-style 16-bit `int`, or an explicit `uint16_t` cast): $13{,}513{,}500 \bmod 65{,}536 = 13{,}084$, so the intermediate product is 13,084 instead of 13,513,500 and the final "voltage" is garbage (3 mV instead of 3300).

The fix is `(uint32_t)adc * 3300u / 4095u`. Note the order: multiply first (in the wide type) and divide last, to keep precision with integer division. For mid-scale, `2048 × 3300 / 4095 = 1650.4`, which truncates to 1650 mV in integer arithmetic.

## Floating point: structure and limits

A 32-bit float has 1 sign bit, 8 exponent bits (biased by 127) and 23 stored mantissa bits (with an implied leading 1). Value $= (-1)^s\times1.m\times2^{e-127}$.

Figure: The 32 bits of the float nearest to 0.1. The exponent field 123 means a power of $2^{-4}$, and the mantissa $1.6000000238\ldots$ repeats the binary pattern 1001 1001... and is rounded at 23 bits, which is why the stored value is slightly above 0.1.

Key consequences:

- **Relative precision** is $\epsilon = 2^{-23}\approx1.19\times10^{-7}$ for `float` (about 7.2 decimal digits: $\log_{10}2^{24}=7.22$) and $2^{-52}\approx2.22\times10^{-16}$ for `double` (about 15.95 digits).
- **Exact integers** are only guaranteed up to $2^{24}=16{,}777{,}216$ for `float`: `16777216.0f + 1.0f` is still `16777216`. For `double` the limit is $2^{53}$.
- **Decimal fractions** such as 0.1 repeat in binary, so they are rounded: `0.1f` is 0.100000001490116, and in double `0.1 + 0.2` is `0.30000000000000004`, so `== 0.3` is false.
- **Range**: float32 up to about $3.4\times10^{38}$; beyond that, infinity.

For sensor data, an accumulator that integrates tiny increments in a `float` can stall once the sum is large relative to the increment (adding 1e-3 to a total near 1e5 is below the spacing between floats there). Use `double`, integer fixed-point, or Kahan summation.

## Characters, booleans, enums, pointers

- **`char`** is a one-byte integer (a character in ASCII). It may be signed or unsigned depending on the platform; use `uint8_t` for raw bytes. See [[q0969]] for strings.
- **`bool`** (`<stdbool.h>`) is one byte in practice (`sizeof(bool)` is 1 on common compilers), not one bit. A single flag stored in a register is a bit; a `bool` variable is a byte.
- **`enum`** is an integer type with named constants (typically 4 bytes, the size of `int`, though the compiler may choose another size).
- **Pointers** store addresses: 8 bytes on a 64-bit machine, 4 bytes on 32-bit MCUs, 2 on some 16-bit ones. See [[q0942]].
- **`struct` and `union`** combine types; padding can make a struct larger than the sum of its members, and endianness decides the byte order of multi-byte members in memory ([[q0875]]).

## Python's different model

Python variables are names bound to objects; the type lives on the object. `int` has arbitrary precision (`(2**100).bit_length()` is 101), so there is no wraparound, which is convenient but hides bugs if the code is later ported to C. `float` is a 64-bit double, so it has the same 0.1 issue. `7 // 2` is 3 but `-7 // 2` is −4 (floor division). Dynamic typing means a type error appears only when the line runs.

> [!TIP]
> A good habit for firmware: write the type next to the units. `uint16_t temp_decic;` (tenths of a degree) or `int32_t accel_mg;` prevents unit mistakes, and `static_assert(sizeof(x) == 4)` catches wrong assumptions at compile time.

## Debug checklist when a value is "wrong"

1. Print or inspect it in hex to see the raw bits.
2. Check the type's range against the largest value in the calculation, including intermediates.
3. Look for signed/unsigned mixing in comparisons and shifts.
4. Check byte order if the value came from a bus or file.
5. For floats, check magnitude: is the increment smaller than the spacing between floats at this value?

::: applications
- **Register access in firmware**: `uint32_t` for 32-bit peripheral registers, `uint8_t` for byte-wide ones, with masks and shifts.
- **ADC and sensor scaling**: choosing a wide enough type for intermediate products (the 12-bit ADC example).
- **Timers and counters**: unsigned wraparound makes `now - start` safe across a counter rollover.
- **Communication protocols**: packing fields into fixed-width structures with defined endianness.
- **DSP and control on small MCUs**: fixed-point (`int16_t` Q15) arithmetic instead of floating point to save cycles and power.
- **Test scripts in Python**: arbitrary-precision ints for bit manipulation and doubles for analysis, with attention to rounding.

::: assumptions
- **Typical ABIs.** Sizes shown (1/2/4/8 bytes for `char/short/int/long`, 8-byte pointers) are for a common 64-bit Linux system with GCC; embedded targets differ, which is the reason for fixed-width types.
- **Two's complement** is used for signed integers in practice (and required from C23); older standards allowed other representations.
- **IEEE 754** floating point is assumed; some small MCUs lack an FPU and emulate floats in software, or use non-standard formats.
- **`char` signedness** varies with compiler and target (commonly signed on x86, unsigned on some ARM ABIs).
- **Python** means CPython 3; other implementations vary in details but not in the basic model.

::: followups
### What's the difference between `signed` and `unsigned`, and how are negative numbers stored?
Unsigned uses all $n$ bits for magnitude (0 to $2^n-1$). Signed two's complement gives the top bit weight $-2^{n-1}$, so in 8 bits `1111 1111` is −1 and `1000 0000` is −128. To negate a value, invert the bits and add 1. The advantage is that addition and subtraction use the same hardware for signed and unsigned values.

### Why is `0.1 + 0.2 == 0.3` false?
0.1 and 0.2 have infinite repeating binary expansions, so each is rounded to the nearest representable double, and the rounding errors do not cancel: the sum is `0.30000000000000004`. Compare floats with a tolerance, such as `fabs(a - b) < 1e-9 * max(1, fabs(a))`, or use integers (for example work in millivolts).

### You add 1 to a `float` holding 16,777,216 and nothing happens. Why?
A 32-bit float has a 24-bit significand (23 stored bits plus the implied 1), so above $2^{24}$ the spacing between representable numbers is 2. Adding 1 rounds back to the same value. Switch to `double` (exact to $2^{53}$), use an integer counter, or restructure the accumulation.

### What happens if you multiply two `uint8_t` values in C?
Both are promoted to `int` first, so `200 * 200 = 40000` computes correctly in `int` (if `int` is 32 bits). Storing it back in a `uint8_t` truncates to $40000 \bmod 256 = 64$. On a platform with a 16-bit `int` the promoted multiplication still holds 40000 only if it fits in the signed 16-bit range (max 32,767), which it does not, so it overflows: another reason to cast to a wide type explicitly.

### How big is a `bool`, and can you store 8 flags in one byte?
A `bool` variable is at least one byte, so it wastes 7 bits. To pack 8 flags into one byte, use a `uint8_t` with bit masks (`flags |= (1u << n)`), or a bit-field in a struct (though bit-field layout is implementation-defined, so avoid it for hardware registers or protocols).

### What if the same 4 bytes are read on a big-endian machine instead of little-endian?
A `uint32_t` 0x12345678 is stored as bytes 78 56 34 12 on little-endian and 12 34 56 78 on big-endian. Casting a byte buffer from a network or file to an integer pointer therefore gives different values. Convert explicitly with shifts (`(b[0]<<24)|(b[1]<<16)|...`) or the `ntohl`-style functions. See [[q0875]].
