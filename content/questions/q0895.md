::: basics
### In plain words
A K-map (Karnaugh map) redraws a truth table as a grid so you can spot, by eye, groups of 1s. Each group lets you write a shorter expression, which means fewer gates in the circuit. It is a hand method for simplifying small logic functions.

### Picture it
Imagine a wall of lamps in a grid, with some lit. A big rectangle of lit lamps can be described with a short rule, like "the whole top row". A single lit lamp needs its full address. The K-map is arranged so that lamps next to each other differ in only one input, so a rectangle of lit lamps means those inputs do not matter. One difference from a normal wall: the edges wrap around, so the left edge touches the right edge.

### Words you need
- **Truth table**: a list of every input combination and its output ([[q0894]]).
- **Gray order**: the label order 00, 01, 11, 10, in which each step changes only one bit.
- **Group**: a rectangle of 1s whose size is 1, 2, 4 or 8 cells. Bigger groups give simpler terms.
- **Product term**: an AND of some of the inputs, such as $A \cdot B'$ (the apostrophe means "not").

### The simplest example
Take two inputs, A and B, with output 1 for A B = 10 and A B = 11, and 0 otherwise. On the map, those two 1s sit side by side, in the row where A = 1. They differ only in B, so B does not matter: the output is 1 whenever A = 1. The group of two removed one input, so $f = A$.

That is the whole idea: neighbors that differ in one input merge into a shorter term. The rest of this page does a 4-input example with the wrap-around corners, covers don't-cares (cells that can be 0 or 1, whichever helps), and grouping zeros instead.
:::

::: testing
Whether you can turn a truth table into **minimal logic** with a repeatable method, and do it out loud without losing track. Specifically:

1. You lay out the map in **Gray code** order, so neighbouring cells differ in exactly one variable.
2. You group 1s in rectangles of size 1, 2, 4, 8 or 16, as large as possible, including **wrap-around** across the edges.
3. You read each group as a product term by keeping only the variables that don't change.
4. You use don't-cares well, and you check that you have not left a 1 uncovered.

Strong candidates also know when to stop using K-maps (more than 4 or 5 variables) and mention tools.
:::

::: why
Even though synthesis tools minimize logic automatically, K-maps are the quickest way to see what minimal logic looks like, to hand-optimize a critical decode, to spot hazards, and to sanity-check a tool's output. In interviews, "here's a truth table, give me the simplest circuit" is a standard on-the-whiteboard test of whether you can combine Boolean algebra and structured thinking. It is also a gentle intro to what logic synthesis really does: find large groupings of adjacent minterms (prime implicants) and choose a cheap set that covers all the 1s.
:::

::: concepts
- **Truth table to minterms**: the K-map is the truth table folded into a grid. See [[q0894]].
- **Gray code ordering**: rows and columns are labelled 00, 01, 11, 10 so adjacent cells differ in one bit, which is what makes algebraic simplification visible.
- **Adjacency**: two cells that differ in one variable combine by $XY + XY' = X$. Edges wrap around (the map is a torus).
- **Implicants**: any rectangle of 1s; **prime implicant**: one that cannot be enlarged; **essential**: the only cover for some 1.
- **Don't-cares**: cells marked X can join a group if it helps, but need not be covered.
- **Logic gates**: AND/OR/NOT realize the final SOP. See [[q0891]], [[q0892]].
:::

::: answer
"Sure. I'll take a four-variable one as an example, say $f = \sum m(0,1,2,5,8,9,10)$. First I draw a 4 by 4 grid with the variables A, B down the side and C, D across the top, and I label both axes in Gray code, 00, 01, 11, 10, so that neighbouring cells differ by only one variable. Then I drop a 1 in each cell whose minterm is in the function.

Now I circle groups of 1s in powers of two: 1, 2, 4, 8, as big as I can, and I'm allowed to wrap around the edges. The four corners (minterms 0, 2, 8, 10) form one group, and B and D are 0 there, so that's $B'D'$. The top and bottom rows' left two columns (0, 1, 8, 9) form another group where B and C are 0, so $B'C'$. That leaves minterm 5, which can only pair with 1, giving $A'C'D$.

So $f = B'D' + B'C' + A'C'D$. I check by making sure every 1 is covered and no 0 is. With don't-cares, I treat them as 1s if they let me make a bigger group, and ignore them otherwise. If I needed product-of-sums, I'd group the 0s instead and complement."
:::

::: technical
**Layout.** For 4 variables use a $4\times4$ map with $AB$ on the rows and $CD$ on the columns in Gray order $00,01,11,10$. A cell with row label $AB$ and column label $CD$ is minterm $m_{8A+4B+2C+D}$. The cell numbers are therefore not in count order across the map: the top row is $m_0,m_1,m_3,m_2$, the second $m_4,m_5,m_7,m_6$, then $m_{12},m_{13},m_{15},m_{14}$, then $m_8,m_9,m_{11},m_{10}$.

**Rule.** A group of $2^k$ adjacent 1s eliminates $k$ variables: the variables that take both values within the group drop out; the variables that are constant stay (true if constant 1, complemented if constant 0).

**Procedure.**
1. Fill the map from the truth table (1s, 0s, Xs).
2. Mark cells that have only one possible largest group (these lead to essential prime implicants) and take those first.
3. Cover remaining 1s with the fewest, largest groups. Overlap is fine.
4. Write one product term per group and OR them.
5. Verify: each 1 is in some group; no group contains a 0 (Xs are allowed).

**Worked function.** $f=\sum m(0,1,2,5,8,9,10)$ gives
$$f = B'D' + B'C' + A'C'D \quad (\text{3 terms, } 2{+}2{+}3 = 7 \text{ literals}).$$
Minterm 9 is only covered by $B'C'$, minterm 5 only by $A'C'D$ (it needs to pair with 1), and minterms 2 and 10 only by $B'D'$, so all three are essential.

**Product of sums.** Group the 0s instead (3,4,6,7,11,12,13,14,15), which gives $f' = BD' + AB + CD$, and so $f = (B'+D)(A'+B')(C'+D')$. Same function, and here the POS is actually one literal cheaper (6 vs 7), so it pays to check both forms.

**With don't-cares.** $f=\sum m(1,3,7,11,15)+d(0,2,5)$: the group $\{3,7,11,15\}$ gives $CD$ and $\{1,3,5,7\}$ gives $A'D$ (using don't-care 5), so $f = CD + A'D$. Using don't-cares 0 and 2 instead gives $f = CD + A'B'$; both are minimal, so minimal solutions need not be unique.

**Limits.** K-maps get unwieldy past 4 variables (5 and 6 need layered maps). For larger functions use Quine-McCluskey or Espresso-style heuristics, which find prime implicants algorithmically.
:::

::: short
"I lay out the K-map with the variables in Gray code so neighbouring cells differ in one bit, fill in the 1s from the truth table, and circle the biggest rectangles of 1s in powers of two, wrapping around the edges. Each group becomes one product term containing just the variables that don't change within it. OR the terms together and I have a minimal sum of products. Don't-cares can be used to enlarge groups, and I always check that every 1 is covered."
:::

::: long
"Let me walk through it with a four-variable example, $f = \sum m(0,1,2,5,8,9,10)$.

I draw a 4 by 4 grid: A and B on the rows, C and D on the columns, and both axes labelled in Gray code, 00, 01, 11, 10. That ordering is the whole trick, because it makes cells that are next to each other differ by exactly one variable, and two cells that differ in one variable can be combined with $XY + XY' = X$. The map also wraps around, so the left and right edges are neighbours and so are the top and bottom.

I fill in 1s for minterms 0, 1, 2, 5, 8, 9, 10. Then I look for the biggest groups, always a power of two. The four corners, minterms 0, 2, 8 and 10, are a group of four. B and D are both 0 across that group while A and C change, so it's $B'D'$. Next, minterms 0, 1, 8 and 9, the left two columns of the top and bottom rows, are a group of four where B and C are 0, giving $B'C'$. Minterm 5 is left, and its only neighbour is minterm 1, so I make a pair: A is 0, C is 0, D is 1 and B changes, so $A'C'D$.

Putting it together, $f = B'D' + B'C' + A'C'D$. To verify, I tick off every 1, and I check no group touches a 0.

If there are don't-cares I treat them as wildcards: I include them in a group if it makes the group bigger, but I don't need to cover them. And if the problem asks for product-of-sums, I group the zeros, write the SOP of the complement, and apply De Morgan.

Past four variables I'd stop doing this by hand and use Quine-McCluskey or just let synthesis do it."
:::

::: terms
- **K-map (Karnaugh map)**: a truth table arranged in Gray code so adjacent cells differ in one variable.
- **Gray code**: sequence where successive values differ in one bit (00, 01, 11, 10).
- **Implicant**: a product term that implies the function, i.e. a rectangle of 1s.
- **Prime implicant**: an implicant that cannot be enlarged without including a 0.
- **Essential prime implicant**: a prime implicant that is the only one covering some 1; it must appear in every minimal cover.
- **Don't-care (X)**: a cell whose value is unspecified; free to be 0 or 1.
- **SOP / POS**: sum of products / product of sums.
- **Literal**: one variable or its complement appearing in a term; a common cost metric.
:::

::: exceptional
**An average answer** fills the map and circles some groups, sometimes with the wrong axis order or missed wrap-around.

**An exceptional answer**:
- States the Gray-code ordering *and why* (one-variable adjacency).
- Uses wrap-around and the four-corner group without being prompted.
- Explains the reading rule (variables that change drop out) rather than pattern-matching.
- Identifies essential prime implicants first, then covers the rest.
- Uses don't-cares deliberately and notes that minimal covers are not always unique.
- Verifies the result against the table, and mentions hazards (adding consensus terms) or that tools do this for large functions.
:::

::: mistakes
- **Using binary order (00, 01, 10, 11) on the axes.** Then neighbours differ in two bits and your groups are wrong. It must be 00, 01, 11, 10.
- **Groups of 3, 5 or 6.** Groups must be 1, 2, 4, 8 or 16 cells, rectangular, aligned in the Gray-coded sense.
- **Forgetting wrap-around.** The four corners are adjacent. Missing that gives a more complex expression.
- **Reading the wrong variables.** Keep the ones that are constant in the group; complement the ones that are constant 0. The ones that change disappear.
- **Treating don't-cares as required.** Xs may be covered but never have to be, and covering an X *only* to make a smaller group is the point; don't circle a group of only Xs.
- **Not checking.** Skipping the verification step is how a stray 0 sneaks into a group.
:::

::: deep
## Why Gray code makes minimization visible

The identity behind everything is $XY + XY' = X(Y+Y') = X$. Two minterms that differ in exactly one variable merge into a term with one fewer literal. On a plain truth table those pairs are scattered (minterms 1 and 5 differ only in $B$ but are three rows apart). The K-map reorders rows and columns so that every pair of neighbouring cells differ in one variable: that is exactly what the Gray-code sequence does.

For four variables, the column order $CD = 00,01,11,10$ means going 0→1 flips $D$, 1→3 flips $C$, 3→2 flips $D$, and wrapping 2→0 flips $C$. Same on the rows. Because the last Gray code (10) differs from the first (00) in one bit, the map wraps around; topologically it's a torus.

Now a block of $2^k$ cells that is a union of such adjacent pairs, pairs of pairs, and so on, is a subcube of the Boolean hypercube: $k$ variables take both values, the other $n-k$ are fixed. That is why groups must be powers of two and rectangular: they are exactly the subcubes.

## Using don't-cares

Don't-cares are free wildcards. Consider $f=\sum m(1,3,7,11,15)$ with $d(0,2,5)$. Without Xs, minterm 1 can only pair with 3 ($A'B'D$), costing more. With the don't-cares, cells 1, 3, 5, 7 form a group of four: $A$=0 and $D$=1 constant, giving $A'D$; and 3, 7, 11, 15 form $CD$. So $f=CD+A'D$, two terms of two literals. The alternative use of the Xs at 0 and 2 gives $A'B'$ instead of $A'D$ and is equally small, which is a reminder that a minimal solution may not be unique.

The *risk* again is hardware reality: if the don't-care input actually occurs, the circuit will do whatever the Xs were resolved to. That is fine for BCD digits that cannot occur but dangerous when "can't happen" can happen after a glitch or radiation upset. If that matters, specify those rows or add a detector.

## Product of sums

Group the 0s instead. For the worked function the 0s are minterms 3, 4, 6, 7, 11, 12, 13, 14, 15. Groups: $\{4,6,12,14\}$ is $BD'$, $\{12,13,14,15\}$ is $AB$, $\{3,7,11,15\}$ is $CD$. That gives $f'=BD'+AB+CD$. Applying De Morgan:
$$f=(BD'+AB+CD)'=(B'+D)(A'+B')(C'+D').$$
Counting literals: the SOP has $2+2+3=7$ literals; the POS has $2+2+2=6$ literals. POS is slightly smaller here, which is a good reminder to look at both when you have the time, and that mapping gives you POS for free once you can read SOP.

## Hazards and the consensus term

A minimal SOP is not always glitch-free. If two groups are adjacent but not overlapped by a third, then when the input moves from one group to the other, both product terms can be momentarily 0 and the output glitches to 0. On a K-map this is visible: two circles that touch edge-to-edge without overlapping. Adding the redundant "consensus" group that spans the boundary removes the static-1 hazard at the cost of an extra gate. In synchronous designs flip-flops sample after the logic settles, so you usually ignore hazards; in asynchronous logic, clock gating, or anything driving a clock or reset line, you cannot.

## Five and six variables, and what tools do

Five-variable maps are two 4×4 maps stacked (E=0 and E=1), where cells in the same position are also adjacent. Six variables need four maps. Beyond that it becomes error-prone, and the systematic alternative is **Quine-McCluskey**: list minterms, merge pairs that differ in one bit repeatedly to get all prime implicants, then pick a minimum cover (a set-cover problem, which is NP-hard in general). Real logic synthesis (Espresso-style two-level minimizers, and multilevel optimization in tools like Yosys/ABC and commercial synthesis) uses heuristics, and also exploits shared logic across outputs and technology mapping to the actual cell library, which a flat K-map cannot capture. A 2-level minimal expression is not necessarily the smallest circuit: a 4-bit parity function has an expensive SOP (8 product terms of 4 literals) but is just three XOR gates.

## Real hardware note

Gate count is not the only cost. A minimal SOP may have high fan-in gates (a 3-input AND feeding a 4-input OR) that are slower in CMOS than a deeper tree of 2-input gates, because series transistor stacks in NAND/NOR gates lose drive strength. The right target depends on the library: counting NAND2-equivalents and logic depth is closer to what physical designers care about than counting literals.

::: applications
- **Seven-segment display decoders**: each segment is a 4-input function of the BCD digit with six don't-cares, a textbook K-map problem.
- **Address decoding and chip-select logic**: minimizing the glue logic that selects memory-mapped peripherals.
- **ALU control logic**: mapping opcode bits to select lines and flags.
- **State-machine next-state and output logic**: after state assignment, each next-state bit is a function you can minimize ([[q0896]]).
- **Hazard analysis**: finding the consensus terms needed to make asynchronous or clock-gating logic glitch-free.
:::

::: assumptions
- **Two-level (SOP/POS) implementation.** "Minimal" here means fewest terms and literals in two-level logic. Multilevel, XOR-heavy or shared logic can beat it.
- **Cost model.** Fewest literals is a proxy. Real cost depends on library cells, fan-in, delay and area.
- **Up to 4 (maybe 5) variables.** Beyond that you use algorithmic minimizers.
- **Don't-cares truly never occur.** Otherwise the minimized logic's behavior on those inputs is arbitrary.
- **Static behavior.** The K-map ignores glitches unless you check adjacent groups for overlap.

Alternative valid answers: if the interviewer asks for NAND-only logic, convert the SOP by double inversion ($f=((B'D')'(B'C')'(A'C'D)')'$); if they ask for a mux implementation, Shannon-expand on one variable.
:::

::: followups
### Simplify $f=\sum m(1,3,5,7)$ for 3 variables A,B,C.
Minterms 1, 3, 5, 7 are all the cells where $C=1$ (001, 011, 101, 111). They form a group of four with A and B changing, so $f=C$. No gates needed; it's just a wire.

### How do you handle don't-cares?
Mark them X. When forming groups, include an X in a group if it lets the group get larger, since each doubling removes a literal. You do not have to cover any X. After choosing groups, note which Xs were taken as 1 and document it, because the hardware will output 1 for those inputs.

### What is an essential prime implicant?
A prime implicant (a maximal group) that is the only one covering at least one 1-cell. It must be in any minimal cover. In the worked example all three groups are essential: minterm 9 only fits $B'C'$, minterm 5 only fits $A'C'D$, and minterm 2 and 10 only fit $B'D'$ once you account for the wrap. Finding essentials first is the fast way to solve a map.

### How would you do this for a 6-variable function?
By hand I wouldn't. I'd use Quine-McCluskey or a tool. With 6 variables there are 64 minterms, and finding the minimum cover is a set-cover problem. In RTL I'd just write the behavior and let synthesis (Espresso/ABC-style) optimize for area and timing against the real cell library.

### Your minimized circuit glitches when one input toggles. Why, and how do you fix it?
The two groups that the toggling input moves between are adjacent but not overlapped, so there is a moment when neither product term is 1. This is a static-1 hazard. Add the consensus term covering both neighbouring cells, e.g. for $f=AB+A'C$ add $BC$. That gives you an extra redundant gate, which synthesis tools will delete unless you protect it.
:::

::: interpretations
"Do the K-map for a given truth table" assumes the interviewer will hand you a table, typically 3 or 4 variables. If they give you the table with outputs for several functions (like a 7-segment decoder), do one output at a time. If they ask for "the simplest circuit", ask whether they want SOP, POS, NAND-only, or minimal gate count; the answer differs. The truth-table basics are in [[q0894]].
:::

::: rubric
- Lays out the map with Gray-code axes :: Without it, adjacent cells don't differ by one bit and the groupings are invalid.
- Fills the map correctly from the truth table :: Transcription errors are the commonest source of wrong answers; minterm numbers don't run in order across the map.
- Forms maximal groups of 1, 2, 4, 8 with wrap-around :: Bigger groups mean fewer literals; missing the wrap-around leaves non-minimal logic.
- Reads each group by keeping the constant variables :: This is the mechanism that turns circles into product terms.
- Uses don't-cares only to enlarge groups :: Shows you understand they are optional.
- Verifies that all 1s are covered and no 0 is included :: Catches the typical errors before the interviewer does.
- States the final expression and optionally the gate implementation :: The question asks for the circuit, not just circles.
:::
