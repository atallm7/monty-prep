::: testing
Whether you can explain the **fully parallel** idea: a resistor ladder makes every threshold, a bank of comparators checks the input against all of them at once, and a thermometer-to-binary encoder produces the code. Beyond the block diagram, the interviewer wants to see that you understand the *cost*: $2^N-1$ comparators means area, power and input capacitance that double with each bit, and comparator offset must be smaller than an LSB. That cost is why flash is limited to about 6 to 8 bits and why folding, interpolating and subranging variants exist. It's also a test of whether you can compare it with SAR ([[q0810]]) in one sentence: flash trades hardware for time.
:::

::: why
Flash is the speed benchmark of data conversion. It sits inside oscilloscopes, high-speed serial receivers, radar and RF front ends, and as the building block inside pipeline and delta-sigma converters (their internal quantizers are small flash ADCs). Being able to draw one and say why it stops at about 8 bits shows that you understand the area, power and matching trade-offs behind a datasheet's "resolution versus speed" chart. It also reinforces comparators ([[q0127]]) and resistor dividers ([[q0008]]), the two simplest analog blocks an interviewer can build a question from.
:::

::: concepts
- **Comparator**: an open-loop op-amp or latch whose output is high when $V_+>V_-$. See [[q0127]].
- **Resistor ladder (string)**: $2^N$ equal resistors in series between $V_{ref}$ and ground, a divider with $2^N-1$ taps. See [[q0008]].
- **Thermometer code**: the comparator bank outputs $k$ ones followed by zeros when the input is above $k$ thresholds.
- **Priority encoder**: digital logic converting a thermometer code to binary.
- **Quantization**: the output has $2^N$ levels, $V_{LSB}=V_{ref}/2^N$. See [[q0808]].
- **Comparator offset**: input-referred mismatch that shifts thresholds. It must stay well below an LSB.
:::

::: answer
"A flash ADC finds the answer in a single step by checking every possible level at the same time. You put a resistor ladder across the reference, with $2^N$ equal resistors, which gives you $2^N-1$ evenly spaced threshold voltages. Each threshold goes to the inverting input of its own comparator and the input signal goes to all the other inputs.

If the input is, say, 1.9 V on a 3-bit, 3.3 V converter, the thresholds are 0.41, 0.83, 1.24, 1.65, and so on, so the first four comparators output high and the rest low. That's called a thermometer code, like mercury rising. A priority encoder turns it into binary, here 100, which is 4.

The big advantage is speed: one comparator delay plus encoding, so you get giga-samples per second. The downside is cost. An 8-bit flash needs 255 comparators and 256 resistors, and each extra bit doubles all of it: area, power, and the capacitive load on the input. Comparator offsets also have to be much smaller than one LSB, which is hard when there are hundreds of them. So flash is limited to about 6 to 8 bits. For higher resolution at speed people use folding, interpolating or pipelined converters, and SAR for slower, higher-resolution jobs."
:::

::: technical
**Architecture.** A reference ladder of $2^N$ equal resistors $R$ from $V_{ref}$ to ground produces tap voltages

$$V_k=\frac{k}{2^N}V_{ref},\qquad k=1,\dots,2^N-1$$

Comparator $k$ compares $V_{in}$ with $V_k$ and outputs $T_k=1$ if $V_{in}>V_k$. The outputs form a thermometer code $T_{2^N-1}\dots T_1$ with exactly $\text{code}=\lfloor V_{in}/V_{LSB}\rfloor$ ones. A priority encoder (or ones-counter) converts that to $N$ bits. The comparators usually have a clocked latch so that all outputs are captured at one instant.

**Hardware cost.**

| Bits $N$ | Comparators $2^N-1$ | Ladder resistors $2^N$ |
|---|---|---|
| 4 | 15 | 16 |
| 6 | 63 | 64 |
| 8 | 255 | 256 |
| 10 | 1023 | 1024 |
| 12 | 4095 | 4096 |

Power scales roughly as $2^N f_s$ and input capacitance as $2^N$, both with the comparator count. A bigger input capacitance means the driver has to be stronger for the same bandwidth.

**Speed.** Conversion time is one comparator decision plus encoder logic, independent of $N$ in first order, so flash is the highest-speed architecture (up to several GS/s in modern processes, as sub-blocks in interleaved or hybrid designs).

**Accuracy limits.**
- *Comparator offset*: a threshold error of $V_{os}$ shifts a code edge. To keep DNL under about ½ LSB, $\sigma_{V_{os}}\ll V_{LSB}/2$. At 8 bits and 3.3 V, $V_{LSB}=12.9$ mV, so offsets must stay at the few-mV level, which forces large input transistors or offset calibration.
- *Ladder mismatch and loading*: resistor mismatch bows the thresholds (INL), and comparator input bias currents load the taps.
- *Reference and clock skew*: the input reaches 255 comparators through a distributed RC, so arrival times differ. This is why fast flash often has a track-and-hold in front.
- *Bubbles and metastability*: a comparator that is almost balanced can resolve wrongly and create an out-of-order 0 inside the ones ("sparkle code"). Encoders use bubble correction (for example, a 3-input majority filter).

**Variants.** *Subranging/two-step*: a coarse flash picks the segment, a second flash resolves the residue. *Folding and interpolating*: fold the input range so fewer comparators suffice and interpolate between preamplifier outputs for the intermediate thresholds. *Time-interleaving*: several slower ADCs take turns.

> [!UNCERTAIN]
> The practical resolution ceiling for pure flash (6 to 8 bits) and the maximum speeds quoted depend on the process and on whether calibration is used. Treat the numbers as typical, not a rule.
:::

::: short
"A flash ADC compares the input against every possible threshold at once. A resistor ladder makes $2^N-1$ evenly spaced reference voltages, one comparator per threshold. The comparators output a thermometer code, ones up to the input level, and an encoder turns that into binary. It's the fastest ADC architecture, one comparator delay, but the comparator count, area and power double with each bit and offsets must be below an LSB, so it's limited to around 8 bits."
:::

::: long
"A flash ADC is the brute-force, fully parallel converter. The idea is: if I want to know which of $2^N$ levels the input is in, just check them all at once.

Take a reference voltage and put a ladder of $2^N$ equal resistors across it. The taps give me $2^N-1$ thresholds, evenly spaced, at $k/2^N$ of full scale. Each tap goes to one comparator. The input signal feeds all the comparators in parallel. Each comparator outputs a high if the input is above its threshold.

So if I have a 3-bit, 3.3 V converter and the input is 1.9 V, the thresholds at 0.41, 0.83, 1.24 and 1.65 are below it, and the rest are above. The comparator outputs are 0001111, a thermometer code. A priority encoder, which is just combinational logic, turns that into the binary code 100.

The upside is speed. The conversion takes one comparator delay plus the logic, with no iteration, so you can run at gigasamples per second. That's why it's in oscilloscopes and high-speed link receivers.

The downside is that everything scales as $2^N$. Eight bits is 255 comparators, ten bits is 1023. Each comparator burns power and loads the input, so the input capacitance grows and the driver has to work harder. And the comparators' offsets have to be well below an LSB or the thresholds get out of order, which gets harder as the LSB shrinks.

So pure flash is limited to around 6 to 8 bits. To go beyond that at speed you'd use a subranging or folding architecture, or a pipeline where each stage is a small flash. And if speed isn't critical, a SAR does the same job with one comparator, in $N$ clock cycles."
:::

::: terms
- **Thermometer code**: an output with $k$ contiguous ones for input level $k$; easy to generate in parallel and robust to a single wrong bit.
- **Resistor string / ladder**: equal resistors in series creating evenly spaced reference taps.
- **Priority encoder**: logic that outputs the binary index of the highest-numbered high comparator.
- **Sparkle code / bubble**: an out-of-order comparator output (a 0 within the ones) caused by offset or metastability.
- **Comparator offset**: input-referred error, $V_{os}$, that shifts a threshold.
- **Kickback**: charge injected back to the input when a comparator latches, disturbing the driver and neighbouring comparators.
- **Subranging / two-step ADC**: a coarse flash plus a fine flash, trading a little speed for far fewer comparators.
- **Folding / interpolating**: techniques that reuse comparators across the range or generate intermediate thresholds electronically.
:::

::: exceptional

**An exceptional answer**:

- Explains **why it stops at about 8 bits**: exponential area, power and input capacitance, and the offset requirement shrinks with the LSB.
- Names a fix, such as **subranging, folding/interpolating, pipelining** or offset calibration, and says which problem each solves.
- Mentions bubble errors and why a track-and-hold or latch timing matters.
- Compares explicitly with SAR: flash trades hardware for time, SAR trades time for hardware.
:::

::: mistakes
- **Saying $2^N$ comparators.** You need $2^N-1$ thresholds. The extra resistor is because $2^N-1$ taps need $2^N$ segments.
- **Saying flash is "accurate because it's parallel".** It's fast. Accuracy is limited by comparator offsets and ladder matching, and those get worse as the LSB shrinks.
- **Forgetting the encoder.** The comparator bank outputs a thermometer code, not binary.
- **Forgetting the input loading.** 255 comparator inputs in parallel mean a large, signal-dependent input capacitance. A weak driver will distort the signal.
- **Putting the input and the reference on the wrong pins.** If the tap goes to the + input, the thermometer inverts. Whichever you choose, say what each comparator output means.
- **Claiming it needs no sample-and-hold.** At high frequency, the signal reaching different comparators at slightly different times creates errors, so a track-and-hold is often used ([[q0814]]).
:::

## The core idea: one comparator per level

Suppose I want a 2-bit converter with $V_{ref}=3.3$ V. There are four codes (00, 01, 10, 11) and three boundaries between them, at 0.825 V, 1.65 V and 2.475 V. The simplest possible hardware is three comparators, each watching one boundary. A comparator's output is high if the input is above its boundary. The resistor ladder generates the boundaries, because a string of four equal resistors between 3.3 V and ground has taps at 3/4, 1/2 and 1/4 of $V_{ref}$ ([[q0008]]).

## Scaling up: what the numbers say

Generalising to $N$ bits means $2^N-1$ comparators. For a 3.3 V, 3-bit converter ($V_{LSB}=0.4125$ V) and $V_{in}=1.9$ V, the thresholds are 0.4125, 0.825, 1.2375, 1.65, 2.0625, 2.475 and 2.8875 V. Four are below 1.9 V, so the thermometer code is 0001111 and the binary output is 100 ($=4$). That matches $\lfloor1.9/0.4125\rfloor=4$.

Each extra bit doubles the comparators:

| $N$ | 4 | 6 | 8 | 10 | 12 |
|---|---|---|---|---|---|
| Comparators | 15 | 63 | 255 | 1023 | 4095 |
| Relative power at same $f_s$ | 1× | 4× | 17× | 68× | 273× |

The power row follows from $(2^N-1)/15$ and is only an order-of-magnitude scaling, since real designs spend power differently across the preamps, latches and ladder.

## Why it stops near 8 bits

Three effects compound as $N$ grows:

1. **Comparator count** grows exponentially in area and power.
2. **Input capacitance** adds up. If each comparator input presents about 50 fF (an illustrative number), 255 comparators load the source with about 13 pF; 4095 comparators would load it with 200 pF. The driver bandwidth falls or its power rises.
3. **Offset must shrink with the LSB.** At 8 bits and 3.3 V, one LSB is 12.9 mV, so a comparator whose offset has a standard deviation of 2 mV is already perturbing thresholds by 15% of an LSB. At 12 bits one LSB is 0.8 mV, and sub-mV offsets across 4095 comparators need big input transistors (mismatch falls roughly with the square root of the device area) or calibration.

The ladder itself is also a design problem. For the 8-bit example with 256 resistors of, say, 10 Ω, the ladder current is $I=V_{ref}/(256R)$, so 3.3 V across 2.56 kΩ is 1.29 mA (4.3 mW). Comparator input currents are small, but kickback from latching comparators bounces the taps, so ladders often use decoupling capacitors and a lower-impedance string.

## Practical circuit details

- **Latched comparators.** Each comparator has a preamp (to amplify the small difference and reduce offset) and a regenerative latch (to snap to a full logic level) strobed by the sample clock. The strobe defines the sampling instant.
- **Thermometer-to-binary.** A ones-counter is too slow in a GS/s design, so designs use a ROM or a Gray-code intermediate. Bubble correction compares each output with its neighbours so that a lone 0 inside a run of 1s is fixed.
- **Reference ladder centring.** To centre the transfer curve, many designs use R/2 resistors at the ends so that each code edge falls at $(k-\tfrac12)V_{LSB}$ and the error becomes symmetric (±½ LSB) instead of 0 to $-1$ LSB.
- **Metastability.** If the input is almost exactly on a threshold, the comparator may not resolve in time. At flash speeds that happens often enough to matter and causes sparkle codes.

## Cutting the cost

*Subranging (two-step).* Use a 4-bit coarse flash (15 comparators) to find which of 16 segments the input falls in, then subtract that segment (with a DAC) and amplify the residue by 16 into a second 4-bit flash. Eight bits using 30 comparators instead of 255, at the cost of two conversion phases and the need for a precise subtraction.

*Folding and interpolating.* Fold the input range several times so that one comparator effectively checks several thresholds, then use a resistor interpolation network between preamplifiers to create extra thresholds without more preamps.

*Pipeline.* Chain small flash stages, each resolving 1 to 4 bits and passing an amplified residue to the next stage. Throughput stays at one sample per clock with extra latency, and resolution reaches 10 to 16 bits.

## Flash versus SAR in one table

| | Flash | SAR |
|---|---|---|
| Conversion time | 1 comparator delay | $N$ clock cycles |
| Comparators | $2^N-1$ | 1 |
| Power | High, grows with $2^N f_s$ | Low, grows with $N f_s$ |
| Typical resolution | up to about 8 bits | 8 to 18 bits |
| Typical sample rate | up to GS/s | kS/s to a few MS/s |
| Latency | about 1 clock | about $N$ clocks |
:::

::: applications
- **High-speed oscilloscopes**: front-end ADCs, often time-interleaved 8-bit flash or folding converters at several GS/s.
- **Serial-link receivers (ADC-based SerDes)**: low-resolution (about 6 to 8 bit) converters digitising the received signal at tens of GS/s so DSP can do the equalisation. These are usually time-interleaved arrays, built from flash or SAR sub-ADCs depending on the design.
- **Radar and RF receivers**: wideband digitisation where speed matters more than resolution.
- **Video digitisers**: classic 8-bit flash converters, now mostly replaced by pipeline ADCs.
- **Sub-blocks of other ADCs**: the first stages of pipeline converters and the quantizer in many delta-sigma modulators are 1 to 4-bit flash ADCs.
- **Zero-crossing and window detection**: a 1-bit "flash ADC" is just a comparator, a close cousin used in power supplies and microcontroller analog comparators.
:::

::: assumptions
- Ideal comparators: no offset, hysteresis or delay variation; real parts need $V_{os}\ll V_{LSB}$.
- Equal ladder resistors with negligible comparator input current; otherwise the thresholds bow and INL grows.
- A single reference: the input and reference are DC-accurate. In high-speed designs the reference ladder bounces with kickback, so decoupling is part of the design.
- "Flash" here means the pure single-step converter. Hybrid names (folding, interpolating, subranging) include some of these ideas and answer the area problem differently.
- An embedded interviewer is unlikely to expect transistor-level detail, but may ask "when would I use a flash ADC in a system?" Honest answer: rarely as a discrete part; it appears in high-speed or integrated sub-blocks. Most MCU designers use SAR.
:::

::: followups
### How many comparators and resistors does a 10-bit flash ADC need?
1023 comparators and 1024 resistors. With $V_{ref}=3.3$ V, $V_{LSB}=3.22$ mV, so the comparator offsets need to be well below about 1 to 1.5 mV. That's why you'd never build a 10-bit pure flash. You'd use subranging or pipelining.

### Why is flash the fastest architecture?
There is no iteration and no feedback loop. All comparisons happen in parallel, so conversion time is one comparator decision plus encoder delay, independent of the number of bits to first order. SAR needs $N$ sequential comparisons; delta-sigma needs many samples and a filter.

### What is a thermometer code, and why use it?
It is a code in which output $k$ is high for all thresholds below the input. It's the natural output of a parallel comparator bank and has a useful property: a single faulty comparator creates a bubble that can be corrected by neighbour logic, whereas an error in a binary MSB is catastrophic.

### How would you build an 8-bit ADC at high speed without 255 comparators?
Use a two-step (subranging) ADC: a 4-bit coarse flash with 15 comparators, a 4-bit DAC subtracting the coarse estimate, an amplifier with gain 16 on the residue, then a second 4-bit flash. That is 30 comparators instead of 255, but you need an accurate DAC and amplifier. A folding or interpolating converter reduces the count another way.

### What breaks if one comparator has a 20 mV offset in an 8-bit, 3.3 V flash?
$V_{LSB}=12.9$ mV, so one threshold moves by about 1.5 LSB. If the offset is large enough to move a threshold past its neighbour, the thermometer code has a bubble and the output is non-monotonic. With an encoder lacking bubble correction the output can be wrong by many codes.

### Harder: at what input frequency does the flash ADC itself, not the input driver, limit accuracy?
Because the input must arrive at all comparators at nearly the same instant, skew $\Delta t$ gives an error of up to $2\pi f V_{pk}\Delta t$. For an 8-bit, 3.3 V full-scale sine you want that under half an LSB (6.4 mV): with $V_{pk}=1.65$ V and $\Delta t=5$ ps, $f<6.4\text{ mV}/(2\pi\cdot1.65\cdot5\text{ ps})\approx123$ MHz. This is why wideband flash ADCs need careful clock and input distribution or a track-and-hold.
:::
