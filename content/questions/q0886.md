::: testing
Whether you can define a register precisely (a group of flip-flops sharing a clock that stores a multi-bit value) and then show you understand the *different things the word means* in hardware work: a pipeline register in logic design, a CPU register, a shift register, and a memory-mapped peripheral register that firmware reads and writes. Good answers mention load enable, reset, and what a register looks like in RTL.
:::

::: why
"Register" is the most overloaded word in hardware. In RTL it is a bank of flip-flops; in a CPU it is fast storage the ALU operates on; in firmware it is an address that configures a peripheral. Mixing these up causes confusion in interviews and in real bring-up work, where you spend a lot of time reading and writing registers and decoding fields ([[q0876]]).
:::

::: concepts
- **Flip-flop**: one bit of edge-triggered storage ([[q0882]], [[q0881]]).
- **Word width**: a register stores $N$ bits in parallel, one flip-flop per bit.
- **Clock and enable**: all bits load together at an edge when enabled ([[q0884]]).
- **Reset**: forces a known initial state (synchronous or asynchronous).
- **Bit fields and byte order** when software accesses it ([[q0876]], [[q0875]]).
- **Registers versus memory**: registers are few, fast and parallel-accessible; memory is dense ([[q0883]]).
:::

::: answer
"A register is a group of flip-flops that share a clock and hold a multi-bit value together. If I have an 8-bit register, it's eight D flip-flops: each bit's D input comes from a data bus, they all share the clock, and on the active clock edge, usually if a load-enable is asserted, all eight bits capture their inputs at the same time. Between edges it just holds. Usually there's also a reset to put it in a known state.

The same word shows up at different levels. In digital design, registers are the state elements between blocks of combinational logic, so they're how you build pipelines and state machines. In a CPU, the register file is a small, very fast set of registers the instructions operate on, like R0 to R31. A shift register is a register that also moves its bits over by one position each clock, which is how you do serial-to-parallel conversion.

And for an embedded engineer the other meaning is peripheral registers: addresses in the memory map where you write to configure a timer or UART, or read status bits. Under the hood, those are still flip-flops, just with a bus interface so software can access them. So when I say register I mean a clocked, multi-bit storage element, and I'd clarify which of those contexts the interviewer has in mind."
:::

::: technical
**Structure.** An $N$-bit register $=N$ D flip-flops with common CLK. Parallel load: $Q[N-1:0]\leftarrow D[N-1:0]$ at the active edge.

**Load enable.** Either (a) a recirculating 2:1 mux per bit, $D_i'=\text{EN}\cdot D_i+\overline{\text{EN}}\cdot Q_i$ ([[q0888]]), or (b) clock gating of the whole register. Flip-flops with built-in enable exist in standard-cell and FPGA libraries.

**Reset.** *Synchronous*: reset acts only at a clock edge (extra gate in D path). *Asynchronous*: forces Q immediately regardless of clock; release must meet recovery/removal timing (like setup/hold) to avoid metastability ([[q0887]]).

**Variants.** *Shift register*: $Q_i^+=Q_{i-1}$, serial in, serial or parallel out. *Counter*: register plus incrementer. *Pipeline register*: placed between combinational stages. *Register file*: array of registers with read/write ports and decoders. *Memory-mapped register*: register with an address decode and bus interface (read/write strobes, access type RO, RW, W1C).

**RTL example.**
```
always @(posedge clk or negedge rst_n)
  if (!rst_n)      q <= 8'h00;
  else if (en)     q <= d;
```
**Costs.** An 8-bit register is 8 flip-flops: roughly 160 to 200 transistors in static CMOS (about 20 to 25 per flip-flop); area and clock load grow linearly with $N$.

**Timing.** Output valid $t_{cq}$ after the edge; inputs need setup/hold to the edge ([[q0880]]).
:::

::: long
"A register is a bank of flip-flops that share a clock and store a multi-bit value. An 8-bit register is eight D flip-flops side by side. Each flip-flop's D input is one bit of a data bus, they share a clock, and when the clock edge arrives, if I've asserted the load-enable, all eight bits capture their inputs at once. Between edges the register just holds the value on its outputs. There's usually also a reset, either synchronous or asynchronous, that puts it in a known state at startup.

For the enable, I can either put a 2:1 mux in front of each flip-flop that feeds the output back when the enable is low, or gate the clock to the whole register. Many libraries have flip-flops with a built-in enable.

The word covers a few related things. In digital logic design, registers are the state elements that sit between blocks of combinational logic, which gives you pipelines and state machines. In a processor, the register file is a small, very fast set of registers like R0 to R31 that instructions operate on. A shift register is a register where each bit moves to the next position every clock, used for serial-to-parallel conversion, like in an SPI peripheral or a UART.

And for an embedded engineer, peripheral registers are the interface to hardware: each configuration or status register lives at an address in the memory map, and writing to it sets bits in flip-flops that control the peripheral. Those are still flip-flops, with address decode and bus logic around them, and with access types such as read-only status bits or write-one-to-clear flags.

So: a register is multi-bit clocked storage, built from flip-flops, and which kind I mean depends on the context."
:::

::: terms
- **Register**: bank of flip-flops sharing a clock that stores a multi-bit word.
- **Load enable**: control signal that allows the register to capture new data.
- **Reset (sync/async)**: input that forces the register to a known value.
- **Shift register**: register whose bits shift by one position each clock.
- **Register file**: addressable array of registers with read/write ports.
- **Pipeline register**: register inserted between logic stages.
- **Memory-mapped register**: peripheral register accessed at a bus address.
- **Access types (RO, RW, W1C)**: read-only, read-write, write-one-to-clear fields.
- **Width**: number of bits ($N$) in the register.
:::

::: exceptional
**An average answer** says "a register stores data" or "a bunch of flip-flops".

**An exceptional answer**:
- Defines it as $N$ flip-flops with a shared clock (and enable) that load in parallel, and draws or describes it.
- Distinguishes the contexts: pipeline/state register, CPU register file, shift register, memory-mapped peripheral register.
- Explains enable implementation (feedback mux or clock gate) and reset styles with the recovery/removal caveat.
- Mentions access types and bit fields for peripheral registers and how software uses them.
- Notes cost and the trade-off against memory arrays (registers are fast and multi-port, but dense memory is smaller per bit).
:::

::: mistakes
- **"A register is memory."** It is storage, but distinct from a RAM array: it has direct parallel access and is built from flip-flops, not a dense cell array.
- **Confusing latch and register.** A register of latches is not edge-triggered; registers are normally flip-flops ([[q0881]]).
- **Forgetting the enable.** Without an enable or gated clock, a register reloads every cycle.
- **Releasing an asynchronous reset asynchronously.** The deassertion can violate recovery timing and cause metastability; synchronize it ([[q0887]]).
- **Treating peripheral registers as ordinary memory.** Reads can have side effects (clear on read), bits can be write-1-to-clear, and the compiler may need `volatile` in C.
- **Mixing the CPU register with the peripheral register meaning** without clarifying.
:::

A shared clock is the key property: all bits change together, so the register behaves as one $N$-bit value rather than $N$ independent bits.

## Adding load enable and reset

Without an enable, the register reloads $D$ every clock. Most designs need "load only when told". Two ways:

1. **Feedback mux**: each flip-flop's D comes from a 2:1 mux that selects either the new data (EN=1) or the flip-flop's own Q (EN=0), which recirculates the old value ([[q0888]]). Costs one mux per bit.
2. **Clock gating**: a gating cell stops the clock to the entire register when EN=0, so nothing changes and no dynamic power is burned. Costs one gate for the whole register and saves power for wide registers ([[q0884]]).

**Reset.** On power-up flip-flops have random state. A synchronous reset adds an AND gate in front of D so the register clears at the next clock edge; an asynchronous reset uses a flip-flop with a dedicated reset pin that forces Q immediately. Asynchronous reset is fast and doesn't need a running clock, but *removal* of the reset near a clock edge is a timing check just like setup/hold: if reset releases inside the recovery/removal window, the flip-flop can go metastable ([[q0887]]). The usual practice is to assert reset asynchronously and release it synchronously through a small synchronizer.

## What kinds of register exist

**Pipeline register.** Sits between two pieces of combinational logic to cut the critical path ([[q0884]]). No enable; it just captures every cycle.

**State register of an FSM.** Holds the current state encoding; its D input is the next-state logic.

**Shift register.** Each flip-flop's D takes the previous flop's Q: $Q_i^+=Q_{i-1}$.

Walk an 8-bit shift register receiving the serial bits 1,0,1,1 (MSB first) from a SPI-like line: the contents go $0000\,0000\to0000\,0001\to0000\,0010\to0000\,0101\to0000\,1011=0x0B$. After eight clocks a full byte has been assembled, which is how SPI and UART receivers turn serial into parallel ([[q0876]] for bit order).

**CPU register file.** A small array (for example 32 registers of 64 bits) with two read ports and one write port so an instruction can read two operands and write one result per cycle. Because registers are built from flip-flops/latches with dedicated multiplexing, access is fast (about one cycle or less) but the area per bit is much larger than SRAM. Hence the memory hierarchy: few fast registers, bigger cache, even bigger DRAM ([[q0883]]).

**Memory-mapped peripheral register.** Flip-flops with address decode and bus logic.

## The register that software sees

For a peripheral, a register is defined by its address, width, reset value and for each bit field its access type:

| Access | Meaning | Example |
|---|---|---|
| RW | read and write | timer period, mode select |
| RO | read-only status | busy flag, FIFO level |
| WO | write-only | command register |
| W1C | write 1 clears the bit | interrupt flags |
| RC | cleared by reading | some error/status flags |

Firmware writes `TIMER->CTRL = (mode << 4) | EN;` and the bits land directly in flip-flops that control the hardware. Note for C programmers: peripheral registers can change by themselves (status) or have side effects when read (clear-on-read), so the pointer must be `volatile`, and read-modify-write sequences on registers with W1C bits can accidentally clear flags. Also, the byte order of a multi-byte register on a bus matters ([[q0875]]).

## Worked example: configuring a peripheral register

Suppose a timer's control register `CTRL` is 32 bits with fields `EN[0]`, `MODE[3:1]`, `PRESC[11:4]` and reset value 0x0000_0000. You want EN=1, MODE=0b101 (5) and PRESC=0x3F (63).

Build the value with shifts: $\text{MODE}\ll1=5\ll1=0b1010=0x0A$; $\text{PRESC}\ll4=0x3F\ll4=0x3F0$; $\text{EN}=1$. Combined: $0x3F0+0x0A+0x01=0x3FB$. In C: `CTRL = (63u << 4) | (5u << 1) | 1u;` giving `0x3FB`.

To change only MODE to 2 without disturbing the others, use read-modify-write: `CTRL = (CTRL & ~(0x7u << 1)) | (2u << 1);` The mask `0x7 << 1` is `0xE`, so `~0xE` clears bits 3:1; OR-ing `2 << 1 = 0x4` sets the new mode. From 0x3FB this gives $(0x3FB\ \&\ \sim0xE)=0x3F1$, then $0x3F1|0x4=0x3F5$.

Why this works physically: each bit is a separate flip-flop, and the bus write strobe is the "clock enable" for those flip-flops. A byte-lane write enable can load only some bytes of the register, which is why some MCUs let you write a single byte or half-word of a 32-bit register. A write-1-to-set / write-1-to-clear register pair (like `SET` and `CLR` aliases) avoids the read-modify-write race when an interrupt handler also modifies the same register.

## Timing view: what the next stage sees

A pipeline register between stage A and stage B launches data $t_{cq}$ after the edge and stage B must settle before the next edge. If $t_{cq}=0.35$ ns and stage B logic is 1.2 ns with $t_{su}=0.1$ ns, the stage fits a period of $0.35+1.2+0.1=1.65$ ns (606 MHz) before skew. The register therefore *adds* 0.45 ns of overhead per stage in exchange for isolating the stages: that is the price of registering, as in [[q0884]].

## Registers versus memory

A flip-flop-based register costs 20 to 25 transistors per bit. An SRAM cell costs 6 ([[q0883]]), a DRAM cell 1 plus a capacitor. A 32 x 64-bit register file in flip-flops is $2048\times\approx22\approx45{,}000$ transistors before read multiplexers; as 6T SRAM it would be about 12,300. Registers win where you need many simultaneous ports, immediate access with no precharge/sense cycle, and every bit visible to logic (flags, counters); memory wins on density.
:::

::: applications
- **CPU register file** (R0 to R31) feeding the ALU each cycle.
- **Pipeline registers** in processors, FPGA datapaths and DSP chains.
- **Shift registers** such as 74HC595 for output expansion or SPI/UART receiver deserializers.
- **Peripheral control/status registers** in MCUs: timers, GPIO, ADC, UART configuration.
- **FSM state registers** in controllers and protocol engines.
:::

::: assumptions
- Edge-triggered D flip-flop based registers; latch-based registers (used in some custom designs) are a variant ([[q0881]]).
- Transistor counts are typical static CMOS estimates; actual cells vary with features (scan, reset, enable).
- "Register" in the software sense assumes a memory-mapped architecture; port-mapped I/O on some architectures differs.
- The shift-register example assumes MSB-first serial input and a right-to-left shift into bit 0.
:::

::: followups
### What is the difference between a register and a latch?
A register is an array of flip-flops: edge-triggered, one capture per clock. A latch is level-sensitive and transparent while enabled, so a register made of latches would pass changing data for the whole enable phase. Registers are built from flip-flops (each being two latches) precisely to avoid that ([[q0881]]).

### How do you build an 8-bit register with enable out of basic D flip-flops?
Eight D flip-flops with a shared clock; each D pin driven by a 2:1 mux selecting between data (EN=1) and its own Q (EN=0). Or gate the clock with a latch-based gating cell controlled by EN. Add a reset input to initialize.

### Why is an asynchronous reset released synchronously?
Reset removal must meet recovery/removal timing relative to the clock edge. If it deasserts near an edge, some flops may exit reset on that edge and others on the next, giving an inconsistent state and possible metastability. A two-flop reset synchronizer makes deassertion clock-aligned ([[q0887]]).

### A peripheral status flag clears itself, or never clears, when you handle it in firmware. What do you check?
The register's access type: clear-on-read (RC) flags clear when read, W1C flags need writing a 1 to that bit (and writing back a read value with a read-modify-write can clear other flags). Check the reference manual and use direct writes of only the bits you mean to clear.

### How many flip-flops does a 64-bit, 32-entry register file need, and why aren't register files usually larger?
$64\times32=2048$ bits, so 2,048 storage elements plus read/write multiplexers and decoders. They stay small because every added entry increases the read-mux depth, wire length and delay, and a flip-flop-style bit costs about 4 times the area of an SRAM bit; bigger storage belongs in cache or RAM.
:::
