::: basics
### In plain words
RAM is working memory that you can both read and write, where any location takes about the same time to reach. There are two main kinds. SRAM stores each bit in a small circuit that holds its value while power is on. It is fast but takes a lot of space, so it is used for caches. DRAM stores each bit as a tiny electric charge. It is smaller and cheaper, so it is used for main memory, but the charge leaks away and must be topped up.

### Picture it
SRAM is a light switch. Once you set it on or off, it stays there. DRAM is a bucket with a slow leak: a full bucket means 1 and an empty one means 0. You must refill the full buckets every so often, before they run dry. Checking a DRAM bucket's level drains it a little, so it is refilled after each read.

### Words you need
- **Volatile**: loses its contents when power is removed.
- **Transistor**: a tiny electrically controlled switch.
- **Capacitor**: a tiny part that stores electric charge, like a very small bucket.
- **Refresh**: reading and rewriting every DRAM row regularly, before its charge leaks away.
- **Sense amplifier**: a circuit that detects a tiny voltage change and boosts it to a clear 0 or 1.

### The simplest example
Compare 1 MB of each. 1 MB is 8,388,608 bits. An SRAM cell uses 6 transistors, so the array needs about 50 million transistors. A DRAM cell uses 1 transistor and 1 capacitor, so it needs about 8.4 million of each. That is why DRAM packs far more bits into the same area. The price is refresh, which happens every 64 ms or so, and slower access. That is the whole idea. The rest of this page shows how each cell is read and written, how small the DRAM signal is, and what refresh costs.
:::

::: testing
Whether you can go beyond "RAM is the computer's memory". The interviewer is checking:

1. The definition: **random-access, read/write, usually volatile** memory ([[q0940]] covers what "random access" really means).
2. The two main types, **SRAM** (6-transistor latch) and **DRAM** (1 transistor + 1 capacitor), and why each exists.
3. Circuit-level knowledge: how a bit is stored, read and written; refresh; sense amplifiers.
4. The trade-offs: speed, density, power, cost, and where each is used (caches/registers vs main memory).
5. Awareness of variants (SDRAM/DDR, pseudo-static, MCU SRAM) and failure modes (leakage, soft errors).
:::

::: why
RAM is the working memory of every digital system. Choosing between on-chip SRAM, external DRAM and flash drives cost, power, bandwidth and latency in every SoC and embedded design. DRAM refresh and timing parameters decide real bandwidth; SRAM leakage dominates standby power in many chips; and SRAM/DRAM cells are the canonical examples of analog behavior in a digital circuit (charge sharing, sense amplifiers, noise margins), which is why memory is a favorite topic in VLSI interviews.
:::

::: answer
"RAM is random-access memory, the read/write working memory of a system. 'Random access' means any location can be read or written in roughly the same time, regardless of address, and it's usually volatile, so it forgets everything when power is removed.

There are two main kinds. SRAM, static RAM, stores each bit in a six-transistor cell: two cross-coupled inverters that hold the value as long as power is applied, plus two access transistors that connect it to the bit lines. It's fast, needs no refresh, and is used for CPU caches, register files, and the on-chip memory of microcontrollers, but a cell is large.

DRAM, dynamic RAM, stores a bit as charge on a tiny capacitor, with a single access transistor. That's about a sixth of the transistors, so it's far denser and cheaper per bit, which is why main memory is DRAM. But the charge leaks away in tens of milliseconds, so every row has to be periodically refreshed, and reading is destructive, so the sense amplifier has to write the value back. It's also slower.

So the trade is speed versus density: SRAM for the small, fast levels, DRAM for the large main memory."
:::

::: technical
**Definition.** RAM: memory in which any word can be accessed in (approximately) constant time independent of its address, supporting both read and write; typically volatile.

**SRAM 6T cell.** Two cross-coupled CMOS inverters (4 transistors) form a bistable latch with nodes $Q$ and $\overline{Q}$; two NMOS access transistors, gated by the word-line (WL), connect $Q$/$\overline{Q}$ to the bit-line pair BL/$\overline{\text{BL}}$.
- *Read*: precharge BL and BL̅ high, assert WL, the side storing 0 pulls its bit-line down slightly; a differential sense amplifier detects a difference of tens of mV. Cell stability needs the cell ratio (pull-down vs access strength) $\beta = W_{PD}/W_{AX} > 1$ so the read does not flip the cell.
- *Write*: drive BL/BL̅ to the new value with strong drivers and assert WL; the access transistor must overpower the pull-up (pull-up ratio).
- Static power = leakage of the latch; no refresh.

**DRAM 1T1C cell.** An access NMOS plus a storage capacitor $C_s \approx$ 10 to 30 fF. Writing: WL high, BL driven to $V_{DD}$ or 0 charges/discharges $C_s$. Reading shares charge with the much larger bit-line capacitance $C_{BL}$ (precharged to $V_{DD}/2$):
$$\Delta V = \frac{V_{DD}}{2}\,\frac{C_s}{C_s + C_{BL}}.$$
With $V_{DD}=1.2$ V, $C_s=25$ fF, $C_{BL}=100$ fF, $\Delta V = 0.6\times 25/125 = 120$ mV. The sense amp amplifies it, restores the cell (read is destructive), and the row stays latched in the row buffer.

**Refresh.** Leakage (junction, sub-threshold) discharges $C_s$; every row must be refreshed within the retention time. JEDEC DDR devices use a 64 ms refresh window (32 ms at high temperature) in 8192 refresh commands: $t_{REFI} = 64\,\text{ms}/8192 \approx 7.8\ \mu s$. Refresh blocks a bank for $t_{RFC}$ (hundreds of ns for multi-Gb dies): e.g. 350 ns/7.8 µs ≈ 4.5% overhead.

**Comparison.**

| | SRAM | DRAM |
|---|---|---|
| Cell | 6T | 1T1C |
| Density | low (~100+ F²) | high (~6 F²) |
| Speed | ~1 ns on-chip | ~50 to 100 ns random access |
| Refresh | no | yes |
| Process | standard logic CMOS | special capacitor/array process |
| Use | cache, register files, MCU RAM | main memory |
:::

::: long
"RAM stands for random-access memory: a memory you can read and write, where any location takes about the same time to access regardless of its address, and which is generally volatile.

There are two main implementations. SRAM, static RAM, stores each bit in a six-transistor cell. Four transistors form two cross-coupled inverters, a latch with two stable states, and two more NMOS transistors connect it to a pair of bit lines when the word line is high. To read, you precharge the bit lines, raise the word line, and a sense amp sees the small differential. To write, you drive the bit lines hard and overpower the latch. It holds its value as long as power is on, no refresh, it's fast and built in the normal logic process, which is why caches and the on-chip RAM of microcontrollers are SRAM. The downside is area: six transistors per bit, and the leakage of all those cells adds up.

DRAM, dynamic RAM, uses one transistor and one capacitor per bit. The bit is charge on the capacitor. That's very dense, so we can have gigabytes for cheap, which is why main memory is DRAM. But the capacitor is only tens of femtofarads, so reading shares charge with the long bit line and gives only about 100 millivolts, which a sense amplifier has to amplify and then write back, because the read is destructive. And leakage drains the capacitor, so every row has to be refreshed, roughly every 64 milliseconds, which costs a few percent of bandwidth. It's also slower, 50 to 100 nanoseconds to start an access.

So SRAM is the small, fast, power-hungry-per-bit memory near the CPU, and DRAM is the big, cheap one further away. Both lose data when power goes off, unlike flash."
:::

::: terms
- **RAM**: read/write memory with (approximately) uniform access time to any address.
- **SRAM (static RAM)**: bistable-latch cell (6T); holds data without refresh while powered.
- **DRAM (dynamic RAM)**: capacitor-based cell (1T1C); needs periodic refresh.
- **Word-line / bit-line**: row-select and column data lines of the array.
- **Sense amplifier**: differential amp that resolves the small bit-line signal.
- **Refresh**: periodic read and rewrite of every DRAM row to restore leaked charge.
- **Precharge**: setting bit-lines to a known level (e.g. $V_{DD}/2$) before an access.
- **SDRAM / DDR**: synchronous DRAM with clocked interface; DDR transfers on both clock edges.
:::

::: exceptional
An average answer says "RAM is memory that is fast and volatile; SRAM is faster than DRAM". An exceptional answer:

- Defines "random access" precisely (uniform access time) and mentions volatility.
- Draws or describes the **6T** and **1T1C** cells and explains how a bit is read and written in each.
- Does the **charge-sharing** calculation ($\Delta V = \frac{V_{DD}}{2}\frac{C_s}{C_s+C_{BL}}$ gives ~100 mV) and explains why reads are destructive and refresh is needed.
- Quantifies refresh overhead (~64 ms window, 8192 commands, ~7.8 µs interval, a few % bandwidth).
- Connects the cell choice to hierarchy and process: SRAM in logic CMOS, DRAM with dedicated capacitor processes.
- Mentions failure modes: soft errors, leakage and temperature, SRAM stability (read/write margins).
:::

::: mistakes
- **"RAM" means "main memory only."** SRAM caches, register files and MCU RAM are also RAM.
- **"Random" means unpredictable.** It means uniform-time access to any address, as opposed to sequential media. See [[q0940]].
- **Saying SRAM is non-volatile** because it needs no refresh. It still loses data when power is removed.
- **Forgetting that DRAM reads are destructive**, so the sense amp must restore the data.
- **Confusing RAM with flash storage.** Flash is non-volatile, block-erased, and not random write.
- **Believing SRAM uses less power.** It has no refresh power, but in large arrays, leakage can make it the dominant standby power.
:::

::: deep
## Why two different cells?

A memory is an array: rows selected by word-lines, columns by bit-lines. A cell must (1) store one bit, (2) be selectable, (3) be readable and writable. The two ways to hold a bit physically are **positive feedback** (a latch actively holds its state) or **stored charge** (passive, leaks).

Figure: Two cross-coupled inverters (the outputs Q and QB feed each other's input) hold one bit; the word line WL turns on both access NMOS transistors so the bit-line pair BL/BLB can read or overwrite the latch.

**Stability constraints.** During a read both bit-lines are high and the access transistor on the "0" side forms a voltage divider with that side's pull-down NMOS. The internal node rises to
$$V_{read} \approx V_{DD}\frac{R_{PD}}{R_{PD}+R_{AX}}$$ (roughly, both in linear region). If $V_{read}$ exceeds the other inverter's trip point, the cell flips: a *read disturb*. So the pull-down must be stronger than the access device (cell ratio $\beta = W_{PD}/W_{AX}\approx 1.5$ to 2). During a write the opposite is needed: the access NMOS (pulling the "1" node down through the bit-line driver) must beat the PMOS pull-up, so the pull-up is made weak. Those two opposing constraints define the SRAM design window and why low-$V_{DD}$ SRAM is hard (variation in $V_t$ closes it, so designers use 8T cells, read/write assist, and Vmin margins).

Figure: The storage capacitor Cs holds the bit as charge; when WL turns the access transistor on, Cs shares charge with the much larger bit-line capacitance C_BL (orange), so the read signal is only a small fraction of V_DD.

**Charge sharing, worked.** Precharge BL to $V_{DD}/2 = 0.6$ V ($V_{DD}=1.2$ V). Cell stores 1.2 V (a "1"). After WL opens, charge conservation:
$$V_{final} = \frac{C_s V_{cell} + C_{BL}V_{pre}}{C_s + C_{BL}} = \frac{25\times1.2 + 100\times 0.6}{125} = 0.72\ \text{V},$$
so $\Delta V = +120$ mV (or $-120$ mV for a stored 0). With a longer bit-line, $C_{BL}=200$ fF, the signal falls to $0.6\times 25/225 = 67$ mV. This is why DRAM arrays are divided into sub-arrays with short bit-lines: the signal margin scales as $C_s/(C_s+C_{BL})$. The sense amp (a cross-coupled latch) amplifies the difference to full rail and drives the bit-line, which also *rewrites* the cell: the read is destructive but self-restoring.

**Leakage and refresh.** Leakage current of even 1 fA from a 25 fF capacitor changes its voltage at $I/C = 40$ mV/s, so a 0.2 V drop takes 5 s; real cells have worse worst-case leakage, with the weakest cells (due to defects, temperature, variable retention time) defining a retention time of tens of ms at 85 °C, and refresh must cover them all. JEDEC DDR uses 64 ms (32 ms in the extended temperature range) with 8192 refresh commands:
$$t_{REFI} = \frac{64\ \text{ms}}{8192} = 7.8\ \mu\text{s},\qquad \text{overhead} \approx \frac{t_{RFC}}{t_{REFI}} \approx \frac{350\ \text{ns}}{7.8\ \mu\text{s}} \approx 4.5\%.$$
(Representative for a multi-gigabit DDR4 die; exact $t_{RFC}$ depends on density and generation.)

## How it looks on a real chip

- **SRAM** uses the same transistors as logic, so it is embedded on the SoC (caches, scratchpad, MCU RAM). A cell is on the order of 100+ F². In advanced nodes, SRAM stops scaling as well as logic and uses a large share of die area.
- **DRAM** uses a dedicated process with deep trench or stacked capacitors. A cell is ~6 F² (very dense), so a single die holds 8 to 32 Gbit, but the process is not good for fast logic, hence DRAM is a separate chip (DDR DIMM, LPDDR package-on-package, HBM stack).
- **Access protocol**: DRAM is accessed in bursts: ACTIVATE (open a row into the row buffer), READ/WRITE column, PRECHARGE (close). A row-buffer hit is much faster than a miss. See [[q0940]] for how that complicates "random".

## Variants worth knowing

| Type | Idea | Where |
|---|---|---|
| SDRAM / DDRn | clocked DRAM, data on both edges | PC/server main memory |
| LPDDR | low-power DDR, narrower, aggressive power states | phones, laptops |
| GDDR / HBM | very high bandwidth DRAM | GPUs, accelerators |
| Pseudo-SRAM | DRAM cell with hidden refresh, SRAM interface | small embedded systems |
| FRAM / MRAM | non-volatile RAM-like | low-power data logging |
| eDRAM | DRAM embedded on a logic die | some large last-level caches |

## Failure modes

A DRAM cell stores ~$C_s V = 25\,\text{fF}\times1.2\,\text{V} = 30$ fC, which is only about 190,000 electrons. A radiation particle or leakage can corrupt that, so ECC is standard in servers (see [[q0944]]). SRAM cells store charge on node capacitances of ~1 fF scale, so critical charge shrinks with scaling and single-event upsets matter for SRAM too. Temperature raises leakage in both: SRAM standby power and DRAM refresh rate (hence the 32 ms refresh at high temperature).

> [!UNCERTAIN]
> Cell capacitance, bit-line capacitance, $t_{RFC}$ and retention times depend on the DRAM generation, density and vendor. The numbers here are representative orders of magnitude for DDR4-class devices.

## Worked comparison: 1 MB of each

Cell counts: 1 MB = 8,388,608 bits. SRAM at 6 transistors per bit is ~50 million transistors for the array alone (before peripherals). DRAM at 1 transistor + 1 capacitor is ~8.4 million transistors and 8.4 million capacitors. Even though a DRAM cell is ~20x smaller in area than a 6T SRAM cell, it needs sense amps, refresh logic and a different process, which is why small DRAMs are not integrated in cheap MCUs and why MCUs top out at a few hundred KB to a few MB of SRAM.
:::

::: applications
- **CPU caches and register files**: SRAM in the same process as the cores.
- **MCU on-chip RAM**: 2 KB to several MB of SRAM for stack, heap and buffers; no refresh and simple access.
- **PC/server main memory**: DDR4/DDR5 DIMMs.
- **Phones**: LPDDR packages stacked on the SoC.
- **GPUs and AI accelerators**: GDDR or HBM stacks of DRAM for bandwidth.
- **Network/FPGA line buffers**: block RAM (SRAM) and external QDR/SRAM for low-latency tables.
:::

::: assumptions
- "RAM" means semiconductor read/write memory; some textbooks use RAM loosely for any read/write memory including flash, which is not what interviewers usually mean here.
- DRAM numbers (64 ms, 8192 refreshes, $t_{RFC}$) are for DDR3/DDR4-class parts; LPDDR and HBM differ in detail (per-bank refresh, temperature-compensated refresh).
- SRAM design margins assume a planar or FinFET process; at low $V_{DD}$ designers add assist circuits or use 8T cells.
- If the interviewer is from an embedded background, "RAM" may mean the MCU's SRAM; the answer is the same with emphasis on SRAM and the stack/heap layout ([[q0934]]).
- An alternative valid framing is by function: RAM vs ROM vs flash, which the first sentence of the answer covers.
:::

::: followups
### Why is SRAM faster than DRAM?
The SRAM cell actively drives its bit-line through a transistor (and the latch restores it), so a read just needs a small differential, while DRAM must do charge sharing with a large bit-line capacitance, amplify ~100 mV, and restore the cell, plus a precharge afterwards. DRAM also has to be accessed row-by-row (activate, column, precharge) with larger arrays.

### Why does DRAM need refresh but SRAM doesn't?
The DRAM capacitor leaks, and the stored charge decays within tens of milliseconds, so rows must be read and rewritten periodically. SRAM's cross-coupled inverters continually regenerate the stored value from the supply, so as long as power is on the data persists.

### How much bandwidth does refresh cost?
With 8192 refresh commands per 64 ms and each blocking a bank/rank for $t_{RFC}\approx 350$ ns, overhead is about $350/7800 \approx 4.5\%$ of time. It grows with die density (larger $t_{RFC}$) and with temperature (refresh twice as often above 85 °C).

### What happens to a DRAM read if the bit-line capacitance doubles?
The sense signal $\Delta V = \frac{V_{DD}}{2}\frac{C_s}{C_s+C_{BL}}$ shrinks: from 120 mV (100 fF) to 67 mV (200 fF) with $C_s=25$ fF. Sensing becomes slower and less noise-tolerant, which is why arrays are split into short sub-arrays and why $C_s$ must stay ≥ ~20 fF as cells shrink.

### Harder: could you build a bigger SRAM cache instead of using DRAM main memory?
Area and cost: SRAM cells are ~20x larger, so 16 GB of SRAM would need hundreds of cm² of silicon, and it would be slower anyway because of wire delay, plus it would leak huge standby power. DRAM's density is the only way to reach GB at reasonable cost. HBM and 3D stacking attack the bandwidth gap instead.
:::
