::: testing
Whether you can give a **number and justify it**. "Two wires" and "three wires" are both defensible; the interviewer wants to hear which wires, why ground counts, and what extra wires appear in real systems (flow control, RS-485, power). It also tests whether you can compare against I2C (2 signal wires, shared) and SPI (4+, one chip select per device).

Hidden sub-skills: understanding that a signal needs a reference, that TX and RX are one direction each, and that "UART" and "RS-232/RS-485" have different wire counts.
:::

::: why
Pin count decides connector size, cable cost and how many peripherals fit on a small MCU. UART is popular partly because it needs so few: a three-pin header is enough for a debug console. Knowing the extras (RTS/CTS, DE/RE for RS-485) also stops you from designing a board where the module needs hardware flow control but you only routed two wires. Interviewers use the question to check that you think in terms of what each wire *does*.
:::

::: concepts
- **TX and RX**: one wire per direction, so data flows in both directions at the same time. See [[q0776]].
- **Common ground**: logic voltages are relative to a reference; without it the receiver has no meaning for "high".
- **Hardware flow control (RTS/CTS)**: two more wires that let the receiver say "stop".
- **RS-232 / RS-485 variants**: same framing, different wire counts (differential pairs).
- **Point-to-point**: UART links two devices, so wire count does not grow with the number of peripherals the way SPI chip-selects do. See [[q0765]].
- **Wiring**: which pin goes where is in [[q0774]].
:::

::: answer
"Minimum useful UART is three wires: TX, RX and ground. TX carries data from device A to device B, RX carries data the other way, so you get full duplex. Ground is the shared reference, because the logic levels are voltages measured against it, so I always count it even though it isn't a signal.

If you only need one direction, say a GPS module that just streams data to the MCU, you can get away with two wires: the module's TX to the MCU's RX, plus ground.

In real designs you'll sometimes see five: add RTS and CTS for hardware flow control, so that a module with a small buffer can tell the host to pause. A full RS-232 port uses nine pins, but most of those are modem-control legacy.

And if it goes over RS-485, the two data lines become a differential pair, so you've got A and B for half-duplex, or two pairs for full duplex, plus a ground reference or shield.

Compare that with SPI, where you need four wires plus one extra chip select per device, or I2C, where two wires are shared by the whole bus."
:::

::: technical
**Signal wires (TTL-level UART).**

| Configuration | Wires | Notes |
|---|---|---|
| Simplex (one direction) | 2 | TX to RX, plus GND |
| Standard full duplex | 3 | TX, RX, GND |
| With hardware flow control | 5 | adds RTS and CTS (crossed) |
| Full modem control (RS-232 DB-9) | 9 pins | RX, TX, GND plus DTR, DSR, DCD, RI, RTS, CTS |
| RS-485 half duplex | 2 + ref | one differential pair A/B (plus ground or shield) |
| RS-485 full duplex | 4 + ref | two pairs |

**Power is separate.** A module's VCC is not a UART signal wire, but a "4-pin UART header" (VCC, TX, RX, GND) is common on hobby parts.

**Why ground counts.** The receiver's input threshold is defined relative to its own ground. With only TX and RX connected, the two ground references float with respect to each other, so a "high" can read as anything. In practice, even a single TX wire without a ground return picks up whatever return path exists (through the PC's USB shield, for example), which may seem to work and then fail.

**Differential variants.** RS-485 carries each direction on a twisted pair with $|V_A - V_B| > 200$ mV recognised as a valid level, which allows long runs and noise rejection. Connectors usually add shield or ground. RS-232 uses single-ended lines at about plus/minus 3 to 15 V, so wire count matches TTL UART but levels differ ([[q0774]]).

**Pin count vs. device count.** UART is point-to-point, so connecting a second peripheral needs another UART's worth of pins (2 per extra device), unless you use RS-485 multi-drop or an addressed protocol ([[q0776]]).
:::

::: short
"The minimum for full duplex is three wires: TX, RX and a common ground. TX and RX are separate so each direction has its own wire. Ground is the reference for the logic levels, so I always count it. If you only need data one way you can use two. Add RTS and CTS for hardware flow control and you're at five. RS-485 variants use differential pairs instead, but it's the same framing. Compared with SPI, which needs four plus a chip select per device, UART is very cheap in pins, but it's point-to-point."
:::

::: long
"The standard answer is three wires: TX, RX and ground. Let me justify each. TX from device A goes to RX on device B, and RX on A goes to TX on B, so each direction gets its own wire. That's why UART is full duplex: both devices can talk at the same time without arbitrating. Ground is the third wire, and I always count it, because every voltage on those data lines is relative to ground. If the two boards don't share a reference, a 3.3 V high on one side isn't guaranteed to be read as high on the other.

You can drop to two wires if the link is one-directional. A GPS module that only streams position fixes needs only its TX connected to the MCU's RX, plus ground.

You can go up, too. Hardware flow control adds RTS and CTS, so five wires. That's useful if one side has a small buffer, like a Bluetooth module, and needs to be able to tell the host to pause. A full RS-232 serial port is a nine-pin connector, but most of those pins, like DTR, DSR, DCD and RI, are modem leftovers and almost never wired in modern gear.

If the link runs over RS-485 for long distances, the data lines are differential pairs. One pair makes a half-duplex bus, two pairs make full duplex, and in both cases the bytes and framing are the same UART frames.

Finally, remember it's point-to-point. If I wanted to talk to five devices I'd either need five UARTs or switch to something like RS-485 with addressing, SPI or I2C."
:::

::: terms
- **TX**: transmit output pin of a device.
- **RX**: receive input pin of a device.
- **GND**: common reference. Required, even though it carries no data.
- **RTS / CTS**: request-to-send and clear-to-send, the two hardware flow-control wires.
- **DE / RE**: RS-485 driver-enable and receiver-enable pins used to switch a half-duplex transceiver.
- **Full duplex**: both directions simultaneously, which needs separate wires per direction.
- **Differential pair**: two wires (A/B) carrying one signal as a voltage difference, as in RS-485.
- **Null modem**: a cable that crosses TX/RX so two DTE devices can talk.
:::

::: exceptional
**An average answer** says "two wires, TX and RX".

**An exceptional answer**:
- Says "three, TX, RX and ground" and explains *why ground is a required wire* even though it carries no data.
- Offers the variants without being asked: 2 for simplex, 5 with RTS/CTS, 9-pin RS-232, differential RS-485.
- Notes TX and RX are one direction each, which is exactly why UART is full duplex without arbitration.
- Compares with SPI and I2C pin counts, and flags the cost: point-to-point.
- Mentions the practical gotcha: a "4-pin header" may include VCC, and its voltage must match before anything is connected.
:::

::: mistakes
- **"Two wires" without mentioning ground.** TX and RX are two *signal* wires, but the link needs a third (ground) to work reliably.
- **Counting the clock.** UART has none. If an answer includes SCLK it is describing SPI or a USART in synchronous mode.
- **Confusing UART with I2C.** I2C has two wires (SDA and SCL) shared by many devices; UART has TX/RX per link.
- **Assuming RS-232 has three pins in total.** The DB-9 connector has nine, but the minimal useful set is three: 2 (RXD), 3 (TXD), 5 (GND).
- **Forgetting flow control.** A module that needs CTS from the host will stall with a two-wire connection.
- **Forgetting power and level.** The header's VCC and the signal voltage must be compatible; a 5 V adapter on a 3.3 V MCU can damage the pin.
:::

## What each wire does

Take two devices, A and B. For A to send to B there must be a conductor carrying A's signal. For B to send to A, there must be another, since a single wire can only be driven by one device at a time without extra rules. That gives TX and RX per device.

**Why ground matters physically.** A logic receiver compares its input voltage with an internal threshold that is referenced to its own ground pin. If the two grounds sit at different potentials (long cable, different supplies, a noisy return path), the received "1" is shifted by that difference. A mere 1 V of ground offset eats most of the margin of a 3.3 V LVCMOS link, where $V_{IH}$ is about 2.0 V and $V_{IL}$ about 0.8 V (typical, device-dependent). Two boards powered from the same USB port share ground through the cable; two boards on separate supplies with only TX/RX connected do not.

## Counting variants

**Two wires: simplex.** A GPS module streaming NMEA needs its TX connected to the MCU's RX plus ground. The module's RX stays unconnected or used only for configuration.

**Five wires: hardware flow control.**

**RS-232 DB-9 (DTE view).** Pin 2 = RXD, 3 = TXD, 5 = GND, 7 = RTS, 8 = CTS, and 1, 4, 6, 9 = DCD, DTR, DSR, RI. Most modern hardware only wires 2, 3, 5 and sometimes 7, 8.

**RS-485.** Half duplex: one pair (A, B), plus ground/shield. All devices on the same pair take turns, with a transceiver controlled by DE/RE from a GPIO. Full duplex RS-485 uses two pairs. The UART peripheral still has its TX and RX pins, but they connect to the transceiver's driver input and receiver output instead of to the other device.

## Compare with the other buses

| Bus | Signal wires (plus GND) | Scaling with devices |
|---|---|---|
| UART | 2 (TX, RX) | one link per pair of devices |
| I2C | 2 (SDA, SCL), shared | up to the address space; no extra wires per device |
| SPI | 4 (SCLK, MOSI, MISO, CS) | +1 chip select per extra device |

UART is cheapest for one link but does not scale unless you use RS-485 or a switch. See [[q0737]] for the three-way comparison and [[q0753]] for I2C.

## How long can these wires be?

TTL-level UART is meant for on-board or short-cable use: a metre or so at 115200 baud is comfortable, and longer runs need slower rates or better drivers because the cable capacitance and noise pickup eat the edges. RS-232's voltage swing and slew-rate limits make runs of several metres routine at 9600 to 115200 baud. RS-485 differential signalling is the long-distance choice, with the rule of thumb of up to about 1200 m at low speed and shorter as the rate climbs toward 10 Mbit/s.

> [!UNCERTAIN]
> The distance and speed figures above are widely quoted rules of thumb. The real limit depends on cable capacitance, termination, driver and receiver parts, and noise. Check the transceiver datasheet and the standard rather than quoting a number as a guarantee.

## What a wire count tells you about the design

Every extra wire is a connector pin, a PCB trace, an MCU pin and one more thing to test. That is why interviewers like this question: it shows whether you think about the system cost of an interface. If an MCU board has a debug UART, a GPS and a modem, you need three UART peripherals and three TX/RX pairs, and a quick budget of pins and peripheral instances is the first step of the design, long before software. Also consider pin multiplexing: an MCU often offers several alternate pin choices for each UART, and the wrong pairing can collide with other peripherals on the same package.

## Voltage and power wires

Plenty of "UART cables" have extra conductors: a 6-pin header on a typical USB-serial adapter has GND, CTS, VCC, TXD, RXD, RTS. The VCC pin is power for the target and often selectable at 3.3 V or 5 V. If you never use VCC, leave it disconnected when the target has its own supply; two supplies tied together can fight.

## Practical worked case

An MCU board with a GPS module and a Bluetooth module has three devices to link. Each needs its own UART: GPS needs RX only (MCU pin RX, plus ground): 1 signal pin. Bluetooth with flow control uses TX, RX, RTS, CTS: 4 pins. Debug console uses TX only (the PC never sends anything): 1 pin. Total 6 MCU pins and three UART peripherals. If the MCU has only two UARTs, you cannot do this without a software UART or multiplexer. That's the real cost of "cheap" point-to-point wiring.
:::

::: applications
- **Debug header**: GND, TX, RX (and sometimes VCC) for a USB-serial cable on a dev board.
- **GPS or sensor modules** streaming to an MCU over a single TX-to-RX wire plus ground.
- **Bluetooth/Wi-Fi modules** with RTS/CTS for buffer-limited links.
- **Industrial Modbus RTU over RS-485**: two-wire half-duplex twisted pair.
- **PC COM ports** (DB-9 RS-232) used for lab equipment, with 3 wires used.
:::

::: assumptions
- I treat "wires" as signal wires plus the ground return, and I state that the user may or may not count ground.
- I assume asynchronous mode. In synchronous USART mode there is also a clock pin.
- I assume point-to-point TTL UART. RS-485 and RS-232 are mentioned as physical-layer variants with the same framing.
- Single-wire half-duplex UART exists (TX and RX share one pin with open-drain, for example in some smart-card or servo buses); it needs 1 data wire plus ground, and the bus needs a way to arbitrate direction.
:::

::: followups
### Can UART work over just one wire?
Yes, in a half-duplex variant: a single bidirectional data line plus ground, with an open-drain output and a pull-up, as used by some servos and smart cards. Only one side talks at a time, and the protocol must define who. It is less common than standard TX/RX.

### Do I always need the ground wire?
Yes for a reliable link. Logic levels are measured against ground; without it, there is no defined reference. If boards share ground through another path (USB shield, chassis), the link may seem to work, but that path adds noise and DC offset. For long runs or isolation, use RS-485 or an isolator, which carry their own reference.

### How many UARTs does a typical MCU have, and what if I run out?
Small MCUs have one or two; mid-range ones have four to eight. If you run out: use an external UART bridge IC over SPI or I2C, a software ("bit-banged") UART at low baud, or consolidate onto RS-485 multi-drop. Software UARTs are usually limited to 9600 to 38400 baud and consume CPU.

### Harder: two boards with separate power supplies and only TX/RX connected: why might it still work on the bench?
There is often an unintended ground return, such as both boards' USB shields to the same PC or the scope's ground clip. It works until the return path changes. A proper design adds a ground wire (or isolation with a digital isolator) so the link doesn't depend on accidents.
:::
