::: basics
### In plain words
ROM means read-only memory. Its contents are fixed at manufacture, or can be changed only in special ways, so in normal operation the processor just reads from it. It keeps its data without power. It works like a lookup table: you give an address and it returns the stored value. Inside a microcontroller, ROM often holds the very first code that runs after reset.

### Picture it
Think of a printed phone book. You look up a page number (the address) and read what is printed there. You cannot change what is printed, and the book does not forget when you turn the lights off. A notebook is different: you can write in it, but its contents are not fixed. In ROM the data is physically built into the chip.

### Words you need
- **Non-volatile** ([[q0826]]): keeps its contents when the power is off.
- **Address**: the number that selects one stored value.
- **Mask ROM**: a ROM whose contents were fixed in the factory when the chip was made.
- **PROM, EPROM, EEPROM**: versions that can be programmed once, erased with UV light, or erased electrically ([[q0828]]).
- **Boot ROM**: the factory-fixed ROM that holds the first code to run after reset.

### The simplest example
Picture a tiny ROM with four locations holding 5, 9, 12 and 7. Give it address 2 and it returns 12, every time, with or without power. In a microcontroller, the boot ROM runs after reset and may let you load a program into flash over a serial port. Because it is fixed in the factory, it is reliable and cheap, but a bug in it cannot be fixed. Many people loosely call flash "ROM" too.

That is the whole idea. The rest of this page shows how a ROM is physically a lookup table, walks through the family from mask ROM to flash, and sizes a sine table.
:::

::: why
Boot behaviour, security, and cost all trace back to ROM. The first instructions a processor executes often come from a ROM that cannot be erased or corrupted, which makes the chip recoverable and trustworthy. ROM is also the simplest way to understand how memory works: it is a combinational logic function stored as a truth table. Interviewers use it as a quick check that you know the memory vocabulary ([[q0826]], [[q0828]]).
:::

::: concepts
- **Non-volatile memory** ([[q0826]]): keeps data without power.
- **Address decoding**: $n$ address lines select one of $2^n$ words.
- **Truth table as memory**: a ROM implements any combinational function of its address inputs.
- **Mask ROM**: data fixed by a photomask at manufacturing.
- **PROM / OTP**: one-time programmable by blowing fuses or antifuses.
- **EPROM / EEPROM / flash**: erasable variants ([[q0828]]).
:::

::: answer
"ROM stands for read-only memory. It's non-volatile memory whose contents are fixed at manufacturing, or can only be written in special circumstances, so in normal operation the processor just reads from it.

You can think of it as a lookup table: the address goes into a decoder that selects one row, and each bit of the stored word is either connected or not connected to the output, so the data is physically built into the chip. A classic mask ROM literally has a transistor at some crossings and none at others, decided by the photomask.

There's a family of variations. PROM can be programmed once by the user by blowing fuses. EPROM can be erased with UV light and reprogrammed. EEPROM and flash can be erased and reprogrammed electrically, so today people often say 'ROM' loosely for any flash that holds firmware, even though it isn't read-only in the strict sense.

In a microcontroller, ROM is used for the boot code: the very first instructions that run after reset, like a built-in bootloader that lets you program flash over UART or USB. Because it's mask-defined and can't be overwritten, it's reliable and cheap. The downside is that you can't fix a bug after the chip is made."
:::

::: technical
**Definition.** ROM is memory whose content is determined at fabrication or programmed once, and which supports read operations only during normal use. It is non-volatile.

**Structure.** A ROM of $2^n$ words of $m$ bits is a decoder plus an array:
1. The $n$-bit address drives a decoder with $2^n$ word lines (one is active).
2. Each of the $m$ bit lines has a pull-up (or precharge); a transistor or diode connects a word line to a bit line wherever the stored bit is, say, 0 (NOR-type arrangement).
3. When a word line is high, bit lines with a connected device are pulled low; others stay high.

Total capacity is $2^n \times m$ bits. Example: 12 address lines and 8-bit words gives $4096\times 8$ = 32 kbit = 4 KB.

**Family tree.**

| Type | Programmed | Erasable | Notes |
|---|---|---|---|
| Mask ROM | at fab (photomask) | no | cheapest at volume; long lead time |
| PROM / OTP | by user once (fuse/antifuse) | no | prototyping, calibration, keys |
| EPROM | by user (UV erasable) | UV light through quartz window | legacy |
| EEPROM | electrically | byte-wise | ([[q0828]]) |
| Flash | electrically | block-wise | firmware storage today |

**Timing.** Access time (address to valid data) is typically tens of ns for on-chip ROM.

**Use in MCUs.** Boot ROM, factory calibration tables, protocol lookup tables, and (on mask-ROM MCUs) the entire application.
:::

::: long
"ROM is read-only memory. It's non-volatile, and in normal operation it's only read.

Under the hood a ROM is a lookup table. The address bits go into a decoder, which activates exactly one word line. Along that word line, transistors are either present or absent at each bit-line crossing. If a transistor is present, it pulls that bit line low when the word line is selected; if it's absent, the bit line stays high through a pull-up. So the stored pattern is literally the layout of the chip. A mask ROM has that pattern set by a photomask at the factory, which makes it cheap in volume, and very reliable since nothing can be corrupted.

The downside is inflexibility: if you find a bug, you need a new mask, which costs weeks and a lot of money. So there's a family of more flexible parts. PROM or OTP can be programmed once by blowing fuses or antifuses. EPROM can be erased with ultraviolet light through a quartz window. EEPROM is electrically erasable byte by byte, and flash is electrically erasable by block. Many people say 'ROM' loosely to mean any flash that holds firmware, even though it's technically rewritable.

In a microcontroller, the most important ROM is the boot ROM. After reset the CPU starts executing from it, and it might check boot pins, load firmware from flash, or provide a serial bootloader, which makes the chip recoverable even if the flash is blank. That's why I'd say ROM is used for the code that must always be there and that nothing should be able to overwrite."
:::

::: terms
- **ROM**: read-only memory; non-volatile and not rewritten during normal operation.
- **Mask ROM**: contents defined by a fabrication mask.
- **PROM / OTP**: programmable once by the user.
- **EPROM**: erasable by UV light.
- **EEPROM**: electrically erasable PROM ([[q0828]]).
- **Boot ROM**: factory ROM holding the first code executed after reset.
- **Word line / bit line**: the row-select and data-output lines of a memory array.
- **Decoder**: logic that turns an $n$-bit address into one of $2^n$ select lines.
:::

::: mistakes
- **"ROM can never be written."** Only mask ROM truly can't; PROM, EPROM, EEPROM and flash are programmable variants.
- **Saying ROM and RAM differ by "speed".** The difference is writability and volatility, not necessarily speed.
- **"RAM is volatile, ROM is slow."** On-chip ROM reads about as fast as SRAM or flash.
- **Believing flash is called ROM because it is read-only.** It is called that colloquially because it holds code and is mostly read.
- **Forgetting ROM is non-volatile** and implying it loses data at power-off.
- **Ignoring cost/lead-time trade-offs.** A mask ROM needs a new mask for any change.
:::

::: deep
## ROM as a lookup table

Any function from $n$ input bits to $m$ output bits can be implemented by a ROM with $2^n$ words of $m$ bits: the inputs are the address, and the stored word at each address is the function value. A 3-input, 2-output example is a full adder: addresses $\{A,B,C_{in}\}$ and outputs $\{Sum, C_{out}\}$ need $2^3 = 8$ words of 2 bits.

| Address (A B Cin) | Sum | Cout |
|---|---|---|
| 000 | 0 | 0 |
| 001 | 1 | 0 |
| 010 | 1 | 0 |
| 011 | 0 | 1 |
| 100 | 1 | 0 |
| 101 | 0 | 1 |
| 110 | 0 | 1 |
| 111 | 1 | 1 |

This is how sine tables, character generators, microcode stores and state-machine next-state tables were (and still are) built.

Capacity of this array: $4\times 4 = 16$ bits. An 8 KB boot ROM is $8192\times 8 = 65{,}536$ bits, a 13-bit address, and the same structure with bigger decoders and sense amplifiers. Notice that in a mask ROM the cell can be just one transistor (or even no transistor) with no storage node at all, so it is the densest and cheapest memory per bit, which is why large fixed data is still sometimes ROM.

## How a read actually happens electrically

In the NOR-style array, every bit line has a weak pull-up (or is precharged high before the access). A cell present at a crossing is a transistor whose gate is the word line and whose drain-source path pulls the bit line to ground. When the decoder raises one word line, every bit line with a transistor on that row discharges, and the others hold high. A sense amplifier then converts the bit-line level to a clean logic level.

The access time is dominated by the bit-line RC. Suppose a bit line spans 256 rows, with 2 fF of junction and wire capacitance per row: $C_{BL} = 256\times 2\ \text{fF} = 512\ \text{fF}$. A cell transistor that sinks 50 µA must move the bit line by, say, 0.2 V before the sense amp can decide:

$$t \approx \frac{C\,\Delta V}{I} = \frac{512\times10^{-15}\times0.2}{50\times10^{-6}} = 2.05\ \text{ns}.$$

Add the decoder delay (a few ns) and the output buffer, and a tens-of-ns access time follows naturally. Doubling the rows per bit line doubles the capacitance and roughly doubles this term, which is why large ROMs are split into banks, each with its own short bit lines and sense amps. Static power is the other cost: a bit line that is held low by a transistor while the pull-up still conducts burns current on every access, so real designs use precharge-and-evaluate instead of a resistive pull-up.

## Why a ROM can implement any logic, and when that is a bad idea

A ROM with $n$ inputs always costs $2^n$ words, whatever the function. A 16-input function would need 65,536 words, while a handful of gates might do. ROMs win when the function is irregular (a character font, an arbitrary mapping) or when it has to be changeable (a reprogrammable PROM), and lose when the function has structure (a 16-bit adder is far cheaper as logic). This is the same reasoning behind FPGA look-up tables: small ROMs (typically 4-6 inputs) whose contents are loaded at configuration.

## The family and how programming works

- **Mask ROM:** the connection pattern is a layer (contact or implant) on the mask set. Cost: mask set NRE, lead time of weeks, low per-unit cost. Use when volume is high and the code is certain.
- **PROM / OTP:** each crossing starts connected via a polysilicon fuse; programming blows selected ones with a current pulse (or the reverse with antifuses that short on programming). One time only. Common as small OTP blocks for chip IDs, trim values and secure-boot keys.
- **EPROM:** a floating-gate transistor programmed by hot electrons, erased by UV light (photoemission from the gate) through a quartz window; the window is why those packages were expensive.
- **EEPROM and flash:** floating-gate with electrical erase ([[q0826]], [[q0828]]).

Programming a fuse costs a bit of area: a fuse cell is several times bigger than a mask-ROM cell, so large OTP is expensive.

## Boot ROM: the most important ROM in your chip

When the processor leaves reset it needs valid code at a known address. Flash could be blank or corrupted, so many MCUs and SoCs have a small mask ROM at the reset vector that:

1. Reads boot-mode pins or fuses (for example BOOT0 on STM32).
2. Branches to application flash if valid, or
3. Runs a serial/USB bootloader that can program flash from a PC.
4. In secure SoCs, authenticates the next stage before running it.

Because it is in mask ROM, nothing can corrupt it, and because it is immutable it can be the root of trust. The cost is that bugs in it are permanent; there are famous examples of boot-ROM flaws that could only be fixed on new silicon, which is why teams review boot ROM extremely carefully. (Details of specific cases are not needed here.)

## Worked example: sizing a sine table

A DDS waveform generator needs a 256-point sine table with 10-bit outputs.
- Address: $\log_2 256 = 8$ bits.
- Word: 10 bits, so it fits in 16-bit storage (or pack it).
- Size: $256\times 10 = 2560$ bits = 320 bytes.
- Quarter-wave trick: store only 64 points (using symmetry) plus 2 bits of sign/mirror logic: $64\times 10 = 640$ bits, a 4x saving, at the price of a small amount of logic.

In an MCU you would simply declare `const uint16_t sine[256]` and the linker places it in flash/ROM, never RAM.

::: applications
- **Boot ROM** in microcontrollers and SoCs, holding the first-stage bootloader and sometimes USB/UART DFU code.
- **Mask-ROM MCUs** in toys, remote controls and appliances, where firmware is fixed and volume is high.
- **Lookup tables** for sine waves, CRC tables, font glyphs and gamma curves.
- **Microcode stores** in CPUs.
- **OTP memory** for chip IDs, trim/calibration data and encryption keys.
- **Retro and industrial parts** like EPROM-based cartridges, BIOS chips (now mostly flash).
:::

- Access times and sizes here are typical orders of magnitude.
- In **FPGAs**, "ROM" usually means a block RAM initialised at configuration and then only read.
- In a **PC**, "BIOS ROM" is nowadays flash so it can be updated.
- Security features (fuses, readout protection) differ per vendor.

::: followups
### What's the difference between ROM and RAM?
RAM is read/write and volatile (SRAM, DRAM); ROM is non-volatile and read-only in normal use. RAM holds changing data like variables and the stack; ROM holds fixed code and tables. Access time is not the defining difference: both can be as fast as tens of ns, although RAM is generally faster to write because ROM writes involve fuses, masks or high-voltage programming.

### Is flash a type of ROM?
Technically it descended from EEPROM, so it's in the ROM family in the sense of non-volatile, mostly-read memory. But it isn't read-only: it can be erased and rewritten, with limited endurance. Many people call program flash 'ROM' loosely, but in an interview I would say 'flash' and mention it's the modern replacement for EPROM and mask ROM in MCUs ([[q0826]], [[q0828]]).

### How would you store a fixed 1 KB lookup table in a microcontroller?
Declare it `const` so the linker puts it in flash and nothing is copied into RAM. On Harvard AVR parts use the program-memory access macros. Check the map file to confirm it landed in `.rodata` in flash. 1 KB costs 1 KB of flash and zero RAM.

### When would you choose a mask-ROM microcontroller over a flash one?
When the volume is very high (hundreds of thousands to millions), the firmware is final and well tested, and every cent counts. Mask ROM saves die area and test cost, but any bug means a new mask and months of delay. For prototypes and low volume, flash or OTP is the sensible choice.

### Harder: an attacker can read a device's flash with a programmer. How does the boot ROM help security?
A boot ROM can enforce readout protection, authenticate firmware signatures with a public key stored in OTP fuses before running anything, and decrypt images. Because it is mask-defined it can't be altered, so it is a root of trust. It cannot protect against bugs in the ROM itself, which is why the code is minimal and heavily reviewed.
:::
