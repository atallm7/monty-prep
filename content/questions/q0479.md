::: testing
Whether you can say **where** fast signals go and justify it with return paths, not slogans. The target answer: next to a continuous reference plane (ideally ground), on stripline between two grounds for the noisiest or longest runs, on a surface microstrip when via stubs or tuning matter, staying on one layer pair, and with a ground via when a signal changes layers. The interviewer also wants to see that you know the cost side: vias, stubs, skew.
:::

::: why
At edge rates of a nanosecond or faster, a trace is a transmission line, and its layer decides its impedance, delay, crosstalk, loss and radiation. Picking the wrong layer or crossing a plane gap is the most common reason a first-spin board with USB 3, DDR or Ethernet fails compliance or just doesn't link up. This is also what interviewers probe when they hear "I did a high-speed layout": *which layers, and what did you do at layer changes?*
:::

::: concepts
- **Transmission line behaviour**: when the trace delay is a fraction of the rise time, impedance and reflections matter. See [[q0475]].
- **Reference plane continuity**: the signal and its return form a loop. See [[q0478]], [[q0486]].
- **Microstrip vs. stripline**: field in air + dielectric vs fully buried. See [[q0477]].
- **Via effects**: capacitance, inductance and stubs. See [[q0515]].
- **Differential pairs**: routed on the same layer, same reference. See [[q0518]], [[q0519]].
- **Crosstalk**: depends on spacing and height to the plane. See [[q0490]].
:::

::: answer
"High-speed signals go on layers that sit directly next to a solid reference plane, preferably ground, and I try to keep each interface on one layer, or at most one layer pair, from end to end.

The cleanest choice is usually an inner stripline layer, with a ground plane on both sides. The field is fully contained, so there's less radiation and crosstalk, and it's well shielded from outside noise. For short links, like a USB pair from a connector to the chip, or for very fast signals where via stubs would hurt, I'd use the top layer as a microstrip over an unbroken ground plane.

What I avoid: routing a fast signal over a plane split or anti-pad slot, putting it next to another signal layer with no plane in between, or putting it next to a noisy power plane when I could use ground instead. If it has to change layers, I use a transition between layers that share the same reference plane, or I put a ground via right beside the signal via so the return current can hop planes.

And for a differential pair or a bus, every member goes on the same layers with the same via count, so the delays match."
:::

::: technical
**Layer choices**

| Option | Use when | Notes |
|---|---|---|
| Surface microstrip over ground | Short runs, connectors, very high rate (via stubs), RF | $t_{pd}\approx 6.0$ ps/mm; some radiation; faster than inner |
| Inner stripline between two grounds | Long runs, noisy nets, DDR, clocks | $t_{pd}\approx 6.9$ ps/mm; shielded; needs vias |
| Stripline between ground and power | Acceptable if the power plane is decoupled | Return splits between planes; layer changes need stitching capacitors |
| Next to another signal layer | Avoid, or route orthogonally | Broadside crosstalk |

**Layer transitions.** Each via adds roughly 0.5–1.5 nH of series inductance for a 1.6 mm barrel (Johnson & Graham approximation $L\approx5.08h[\ln(4h/d)+1]$ nH, $h$ and $d$ in inches: 1.3 nH for $h$=1.6 mm, $d$=0.3 mm) and some tenths of a pF of capacitance. The return current at a layer change must move from one reference plane to the other, so the nearest ground via (or decoupling cap when the references are ground and power) should be within about 1–2 mm.

**Via stubs.** A through via from L1 to L3 on a 1.6 mm board leaves roughly 1.0–1.4 mm of unused barrel. The stub resonates when it is a quarter wavelength: $f_{res}=c/(4\ell\sqrt{\varepsilon_r})$. At $\ell = 1.4$ mm and $\varepsilon_r=4.3$: 25.8 GHz. That is above the Nyquist frequency of a 10 Gb/s link (5 GHz) but already inside the edge spectrum of a 25 Gb/s link. Long stubs on 25 Gb/s+ channels are back-drilled or avoided with blind vias.

**Crosstalk spacing.** The rule of thumb is to space traces at least $3w$ (centre-to-centre; $2w$ edge-to-edge) from each other and more for clocks. See [[q0490]].

> [!UNCERTAIN]
> The via and stub numbers are first-order. Real via models depend on pad/anti-pad sizes, stackup and fab drilling tolerances. Use the transceiver vendor's channel guidance or a field solver for rates above a few Gb/s.
:::

::: short
"I route fast signals directly next to a solid ground plane, usually as an inner stripline between two grounds for long, noisy runs, or as a short microstrip on the top layer when via stubs would hurt. I keep each interface on one layer pair, with the same via count for every bit in a bus or pair. I avoid plane splits and adjacent signal layers with no plane between them, and at layer changes I put a ground via next to the signal via so the return current can follow."
:::

::: long
"My approach is: give the signal a clean, continuous reference and keep it on as few layers as possible.

First, the reference. A fast edge's return current runs in the plane right next to the trace, so I want that plane to be ground, solid, and close. That's why the usual spot is either the top or bottom layer, over an adjacent ground plane, or an inner layer between two ground planes. The inner stripline is better for emissions and for crosstalk, and it's the standard choice for long runs like memory buses. The surface microstrip is good for short connections and for very high data rates, because it avoids vias and their stubs, and it's the place where I can tune and probe.

Second, layers. I keep a signal group on one layer, or a pair of layers with the same reference plane, because every layer change adds a via with inductance and capacitance and potentially a stub. Differential pairs and buses get identical routing so delays match. Propagation is a little slower in stripline, about 6.9 versus 6.0 picoseconds per millimetre, so I don't mix layer types inside a group.

Third, layer changes. If the signal goes from a layer referenced to one ground plane to a layer referenced to another, the return current has to jump, so I put a ground via right next to the signal via. If the references are ground and power, I make sure there are decoupling capacitors close by to bridge them, though I'd rather avoid that.

And I don't put a fast net on a layer directly adjacent to another signal layer without a plane in between, or route it across any gap in its reference."
:::

::: terms
- **Reference plane**: plane providing the return path and impedance definition.
- **Stripline**: trace between two planes. **Microstrip**: trace over one plane.
- **Via stub**: the unused part of a via barrel beyond the layer where the signal leaves.
- **Back-drilling**: removing the stub by drilling from the far side.
- **Stitching via / return via**: a ground via beside a signal via carrying the return current.
- **Nyquist frequency**: half the data rate (5 GHz for 10 Gb/s NRZ).
- **Skew**: timing mismatch between lines of a bus or pair.
- **Anti-pad**: the clearance in a plane around a via.
:::

::: exceptional
An exceptional answer treats layer choice as a *return-path decision* and covers the whole path: the reference plane type (ground over power), the transition behaviour (return via or decoupling cap), the stub trade-off with a number, and group consistency (one layer type per interface). It acknowledges that the "best" layer depends on data rate: inner for emissions and crosstalk; surface for multi-GHz where stubs dominate. And it says to check the vendor's design guide (DDR, SerDes) because they specify the layers and via counts.
:::

::: mistakes
- **Routing high-speed signals on the layer next to the power plane** without realising the power plane is the return path, noisy and split.
- **Crossing a plane split or via-field slot.** The return current detours around it, which creates a big loop and common-mode noise.
- **Dropping through the board with long stubs on a multi-gigabit link** instead of using the shortest transition or back-drilling.
- **Mixing layers within a group** so delays differ.
- **Placing two high-speed layers adjacent, running parallel.**
- **Forgetting the return via** next to the signal via when layers reference different planes.
:::

## What a high-speed signal needs

Three things: a defined impedance, a defined return path and enough isolation from neighbours. All three come from the same geometry: the signal trace, its reference plane, and the distance $h$ between them.

## The return path on a layer change

When a signal goes through a via from a layer referenced to plane A to a layer referenced to plane B, the signal current flows through the via barrel. The return current is in plane A on one side and plane B on the other, and it must get from A to B *somewhere*. If A and B are both ground and they're stitched together by a via right next to the signal via, the return takes that hop with a tiny loop. If A is ground and B is a power plane, the hop happens through the nearest decoupling capacitor, which is a much poorer path at high frequency. If there's nothing nearby, the return current has to spread through the plane-pair capacitance, exciting plane resonances and radiating from the board edges.

Rules that follow:
1. Prefer to change between two layers that share the *same* reference plane, for example a top-layer signal over the L2 ground that dives to an inner layer whose upper reference is also L2. The return current then stays on one plane and doesn't need to hop. See [[q0476]] for stack arrangements.
2. Otherwise, put a ground via within ~1–2 mm of the signal via, one per signal via for the fastest edges.

## Via stubs

A through-hole via from L1 to L3 in a 1.6 mm board has a stub from L3 to L6 as long as 1.0–1.4 mm. The stub is an open-circuited quarter wave resonator:

$$f_{res}=\frac{c}{4\,\ell\,\sqrt{\varepsilon_r}}$$

A rule used in practice is to keep the resonance several times above the highest frequency of interest; the margin you need depends on the channel and the standard.

## Differential pairs and buses

For differential pairs ([[q0518]], [[q0519]]): both members on the same layer, same reference plane, same length of each type of segment, vias in pairs with matching ground vias. For parallel buses like DDR: every bit of a byte lane on the same layer, or switch layers at the same point. If the standard requires routing on different layers, the vendor's guide specifies length compensation for the different propagation delays (6.0 vs 6.9 ps/mm).

## Putting numbers on a real decision

**USB 2.0 high-speed (480 Mb/s) pair, 40 mm from connector to MCU, 4-layer board.** Rise time about 500 ps, knee 700 MHz. Top layer microstrip over L2 ground, 0.2 mm prepreg, 90 Ω differential; no layer changes. Stub-free. Simplest and best.

**DDR3 at 800 MT/s, two chips, 6-layer board.** Edges are on the order of a few hundred ps. Route on inner layers that have a ground neighbour (in an S/G/S/P/G/S stack, L3 sits between ground and power, so the SoC vendor's guide matters here), keep each byte lane on one layer, and match lengths within the lane. Follow the vendor's stackup and via rules, not mine.

**10 Gb/s SFP+ pair on an 8-layer board.** Top-layer microstrip from the cage to the SerDes if the path is short; if it must go inside, use blind or back-drilled vias and put ground vias around each signal via. Note that the standard sets the insertion-loss budget.

> [!INTERVIEW]
> "Where do you route high-speed signals?" is a trap for answers that stop at "inner layers." Finish the sentence: "...between two ground planes, kept on one layer pair, with a ground via at every transition, unless the data rate is high enough that the stub matters, in which case I'd stay on the surface."
:::

::: applications
- **USB 2.0/3.x**: top-layer differential pairs over ground; USB 3 pairs kept short, stub-free.
- **DDR3/DDR4/LPDDR**: inner stripline layers between planes, length-matched byte lanes per the vendor guide.
- **Gigabit Ethernet PHY to magnetics**: differential pairs over a solid ground, 100 Ω, short.
- **PCIe/SATA/SFP**: 85–100 Ω pairs; AC-coupling caps and connectors placed to avoid stubs.
- **HDMI/MIPI camera lanes**: matched pairs on the same layer, kept away from switching regulators.
:::

::: assumptions
- FR-4 multilayer, signals from ~100 MHz knee frequencies to a few GHz. Above ~10 Gb/s, laminate loss, glass weave skew and via modelling dominate and vendor guidance replaces rules of thumb.
- Reference planes are solid ground; the ground–power stripline case is allowed with proper decoupling.
- Numbers use $\varepsilon_r=4.3$ and IPC-2141-type approximations.
- If routing space is limited (2-layer or very small boards), the best you can do is route over unbroken ground on one layer; the rules about inner layers don't apply.
- Different standards impose specific layer or length rules: DDR memory has byte-lane groups, PCIe has lane-to-lane limits. Follow the standard.
:::

::: followups
### Why would you ever route a high-speed signal on the outer layer?
For short connections, for very high data rates where via stubs would dominate (the stub resonates at $c/(4\ell\sqrt{\varepsilon_r})$), for RF where I want to tune and probe, or when vias would burn too much area. The costs are more radiation and exposure, which I offset with a solid ground plane under it and often ground pour and via fencing beside it.

### What's the issue with a high-speed signal referenced to a power plane?
Power planes have splits, are noisy, and aren't a ground at DC. The return current must reach the source's ground through decoupling capacitors, which at high frequency have inductance. If the plane is well decoupled and unbroken, it works, but I'd treat ground as the default reference and use power-referenced layers only for slower signals or where the vendor allows it.

### What happens if I skip the ground via next to a signal via?
For layers sharing the same ground nothing much, because the planes are already tied. For layers referenced to different planes the return current has no short path, so the loop gets bigger, the impedance bumps, and the extra loop radiates into the plane cavity. With a 1 ns edge the extra loop can easily add a few nH.

### How would you know whether the via transitions are hurting on a prototype?
TDR on a test coupon or on the board shows impedance bumps at the vias; an eye diagram or S-parameters from a VNA show the insertion loss or resonance notches. Compare with the pre-layout simulation of the via model.

### Scenario: your 10 Gb/s link works on the bench but fails at temperature. Could layer routing play a part?
Yes: marginal channels are sensitive to loss and reflections that change with temperature (dielectric loss increases with temperature and humidity). A stub or discontinuity that left a small eye margin at room temperature can close it hot. I'd check the channel budget, look for stubs and gaps, and consider moving to a low-loss laminate or shortening the route.
:::

- Routes next to a continuous reference plane, preferably ground :: The reference is the defining requirement of a high-speed trace.
- Chooses inner stripline for long/noisy runs, with the shielding rationale :: Shows understanding of field containment.
- Knows when outer microstrip is better (short, very high rate, tuning) :: Shows awareness of via stub trade-offs.
- Keeps an interface on one layer or one layer pair with matched vias :: Prevents skew.
- Handles layer changes with return/ground vias or same-reference layers :: The key practical detail.
