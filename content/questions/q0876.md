::: basics
### In plain words
In a binary number, each bit has a weight that doubles from right to left. The most significant bit, MSB, has the biggest weight. The least significant bit, LSB, has the smallest weight, which is one. So significance means how much a bit is worth, not where it sits on the page.

### Picture it
Imagine a pile of coins worth 1, 2, 4, 8, 16, 32, 64 and 128. The biggest coin is worth more than all the smaller coins combined, because 64 plus 32 plus 16 plus 8 plus 4 plus 2 plus 1 is only 127. A binary number says which coins you hold. Taking away the biggest coin changes the total a lot. Taking away the smallest changes it by one.

### Words you need
- **Bit weight**: the amount a bit adds to the value, a power of two such as 1, 2, 4 or 128.
- **MSB**: the bit with the largest weight, normally written on the left.
- **LSB**: the bit with the smallest weight, 1, normally on the right. In an ADC datasheet it also means the smallest voltage step.
- **Two's complement**: the common way to store signed numbers, where the MSB has a negative weight and acts as the sign bit.
- **Bit order on a link**: whether a serial line sends the MSB or the LSB first.

### The simplest example
Take the byte 1010 0101, which is 0xA5. The bits that are 1 carry weights 128, 32, 4 and 1, so the value is 165. Flip the MSB and the value changes by 128, half the range. Flip the LSB and it changes by 1. For a 12-bit ADC on 3.3 V, one LSB is 3.3 divided by 4096, about 0.806 mV, and the MSB is worth 1.65 V. If a serial device sends 0x41 MSB first but you read it LSB first, you get 0x82. That is the whole idea. The rest of this page covers signed numbers, converters, bit order and register fields.
:::

::: why
Bit significance shows up in every low-level task: decoding a configuration register, sending a byte over a serial link, reading an ADC code, or reasoning about DAC glitches when the MSB flips. Mixing up MSB-first and LSB-first is a classic reason a first bring-up of a SPI or UART device returns garbage. It is also the vocabulary for the rest of the digital block: [[q0875]], [[q0893]], [[q0874]].
:::

::: concepts
- **Positional binary**: bit $i$ carries weight $2^i$, so the value is $\sum b_i 2^i$ ([[q0893]]).
- **MSB**: the bit with the largest weight, $2^{N-1}$ in an $N$-bit word, normally written on the left.
- **LSB**: the bit with the smallest weight, $2^0$, written on the right. In converters, "1 LSB" also means the smallest voltage step.
- **Two's complement sign bit**: the MSB has weight $-2^{N-1}$ and acts as the sign.
- **Bit order on a link**: MSB-first or LSB-first is a protocol choice ([[q0875]] covers byte order).
:::

::: answer
"MSB is the most significant bit, the bit with the biggest weight in a binary number, and LSB is the least significant bit, the one with weight one. In an 8-bit value like 1010 0101, the leftmost 1 is the MSB with weight 128, and the rightmost 1 is the LSB with weight 1. Flip the MSB and the value changes by half the range. Flip the LSB and it changes by one count.

It matters in a few places. In signed two's complement the MSB is the sign bit, so it's what tells you the number is negative. In an ADC or DAC, one LSB is the smallest step: for a 12-bit converter on 3.3 V that's about 0.8 millivolts, and the MSB is worth half of full scale, 1.65 V. On serial links the order you send bits matters: UART sends the LSB first, SPI is usually MSB first but configurable, so getting that wrong gives you a bit-reversed byte. And in registers, fields are described as bit ranges like [5:3], with the MSB of the field first. One thing I'd keep separate is byte order, which is endianness. MSB and LSB are about bits within a value."
:::

::: technical
**Weights.** For an $N$-bit unsigned word $b_{N-1}\ldots b_1b_0$:
$$X=\sum_{i=0}^{N-1} b_i\,2^i$$
MSB $=b_{N-1}$ (weight $2^{N-1}$), LSB $=b_0$ (weight 1). For 8 bits the weights are 128, 64, 32, 16, 8, 4, 2, 1. Example: $\texttt{0xA5}=1010\,0101_2=128+32+4+1=165$.

**Signed two's complement.** The MSB has weight $-2^{N-1}$: $X=-b_{N-1}2^{N-1}+\sum_{i<N-1} b_i2^i$. Range $-2^{N-1}$ to $2^{N-1}-1$. For 8 bits, $\texttt{0xFF}=-128+127=-1$.

**Converters.** $\text{LSB}=V_{FS}/2^N$ and the code maps to voltage as $V=\text{code}\cdot\text{LSB}$. The MSB is worth $V_{FS}/2$, the next bit $V_{FS}/4$, and so on. A 10-bit code 0b1011001110 (718) on a 3.3 V reference is $718\times3.22$ mV $=2.314$ V.

**Bit numbering.** Bit 0 is conventionally the LSB (little-endian *bit* numbering, used by ARM, x86, most MCU datasheets). Some older or network specs (IBM, certain protocol diagrams) number the MSB as bit 0, so always read the register diagram.

**Serial order.** UART: LSB first. SPI: configurable, often MSB first. I²C: MSB first for address and data bytes. So the character `A` ($\texttt{0x41}=0100\,0001_2$) appears on a UART line as 1,0,0,0,0,0,1,0 after the start bit.

**Fields.** A register field `[msb:lsb]` has width $\text{msb}-\text{lsb}+1$. Extract with `(reg >> lsb) & ((1 << width) - 1)`.
:::

::: long
"MSB and LSB stand for most and least significant bit. In an N-bit binary number, each bit has a weight of a power of two. The LSB is bit 0, weight one, and the MSB is bit N minus 1, with weight 2 to the N minus 1. For the byte 1010 0101, which is 0xA5 or 165, the MSB is the leftmost bit worth 128 and the LSB is the rightmost bit worth 1.

The reason it matters is that the two have wildly different impact. Flipping the LSB changes the value by one count, flipping the MSB changes it by half the range. That's why in a DAC, the MSB transition is where you see the biggest glitch, and in a SAR ADC the converter decides the MSB first because it's worth half of full scale. For converters, 'one LSB' is also the unit of resolution: a 12-bit ADC on 3.3 volts has a step of 3.3 divided by 4096, about 0.8 millivolts.

In signed two's complement the MSB is the sign bit with negative weight, so 0xFF in 8 bits is minus one, not 255.

On serial links, it decides the order the bits go out. UART sends the LSB first right after the start bit, and SPI is often MSB first, but the mode is configurable, and a mismatch gives you a bit-reversed byte. In register maps, fields are described as ranges like bits 5 down to 3, and you extract them with a shift and a mask.

Finally, I'd keep it separate from endianness: that's the order of bytes in memory, while MSB and LSB are bit significance."
:::

::: terms
- **MSB (most significant bit)**: highest-weight bit, $2^{N-1}$.
- **LSB (least significant bit)**: lowest-weight bit, $2^0$; also the converter step size $V_{FS}/2^N$.
- **Bit weight**: the power of two a bit contributes to the value.
- **Sign bit**: the MSB of a two's complement number, with weight $-2^{N-1}$.
- **MSB-first / LSB-first**: the order bits are transmitted on a serial link.
- **Bit field**: a contiguous group of bits in a register, written `[msb:lsb]`.
- **Mask and shift**: the operations used to extract or insert a field.
- **Endianness**: byte order, a different concept ([[q0875]]).
:::

::: exceptional
**An average answer** says "most significant bit is the leftmost, least significant is the rightmost".

**An exceptional answer**:
- Defines them by *weight*, with numbers: 128 versus 1 in a byte.
- Explains the sign bit in two's complement and the ADC "LSB = $V_{FS}/2^N$" usage.
- Names serial order: UART LSB first, SPI configurable, I²C MSB first, and the consequence of a mismatch.
- Mentions that bit 0 is usually the LSB but some specs number the other way.
- Separates bit significance from byte significance and gives the mask-and-shift snippet for a field.
:::

::: mistakes
- **Defining them by position only.** "Leftmost" is the written convention; the real definition is weight. On a serial link, the first bit received isn't necessarily the MSB.
- **Saying the LSB is always the first transmitted bit.** UART does this, SPI and I²C usually do the opposite.
- **Forgetting "LSB" means a voltage step in ADC/DAC datasheets.** "INL of 1 LSB" refers to $V_{FS}/2^N$, not to a bit position.
- **Treating the MSB as just another magnitude bit in signed numbers.** In two's complement it has negative weight.
- **Mixing up bit and byte significance.** MSB/LSB vs most/least significant byte: related ideas, different units ([[q0875]]).
- **Assuming bit 0 is the MSB.** Most MCU datasheets use bit 0 = LSB, but check the register map.
:::

::: deep
## Weights: where significance comes from

Binary is positional notation in base 2, exactly like decimal, only the weights are powers of two instead of ten. In 165 the "1" in the hundreds place is the most significant digit because it contributes 100, while the "5" contributes 5. In binary:

| Bit | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| Weight | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| 0xA5 | 1 | 0 | 1 | 0 | 0 | 1 | 0 | 1 |

$128+32+4+1=165$. Bit 7 is the MSB, bit 0 the LSB. What makes the MSB "most significant" is that it is worth more than all the lower bits combined plus one: $2^{N-1} > \sum_{i<N-1}2^i=2^{N-1}-1$. That is why a comparison of two unsigned numbers can start at the MSB and stop at the first difference, which is exactly how a digital comparator and a SAR converter work.

## Two's complement: a different weight for the MSB

For signed numbers the MSB's weight flips sign. For 8 bits:

$$X=-128\,b_7+64\,b_6+32\,b_5+\dots+b_0.$$

So 0xFF is $-128+127=-1$, 0x80 is $-128$, 0x7F is $+127$. The MSB therefore doubles as a sign indicator: if it is 1 the value is negative. To sign-extend an 8-bit value to 16 bits, copy the MSB into all the new upper bits: 0xF6 ($-10$) becomes 0xFFF6. This is why you cannot treat the top bit of a 12-bit ADC reading as just "bit 11" if the ADC is bipolar: its MSB is the sign.

## MSB and LSB in converters

An $N$-bit ADC with reference $V_{ref}$ divides the range into $2^N$ steps; one LSB is
$$\text{LSB}=\frac{V_{ref}}{2^N}.$$
For a 12-bit converter on 3.3 V, 1 LSB $=0.806$ mV, and the MSB corresponds to $V_{ref}/2=1.65$ V.

Figure: Step through the SAR search. The first decision is the MSB (is Vin above 1.65 V?), then the next bit (above 2.475 V?) and so on, each bit worth half of the previous one. The LSB is decided last and sets the resolution.

A worked conversion: a 10-bit ADC returns 0b1011001110. Weights: $512+128+64+8+4+2=718$. On a 3.3 V reference the voltage is $718\times3.3/1024=2.314$ V. If the MSB were stuck at 0 the reading would drop by 512 counts (1.65 V), the sort of error you see from a broken connection on the top data line, whereas a stuck LSB gives a harmless one-count (3.2 mV) error. A useful debugging fact: errors that are large and look like a half-scale step point to a high-order bit; errors that are tiny point to the low-order ones.

For DACs, the MSB transition (for example 0111 1111 to 1000 0000) switches the largest weights in opposite directions at once. Any mismatch between the MSB weight and the sum of the others shows up as a glitch and as a DNL error at that code, the "major carry" transition. Compare how the R-2R DAC in the lab handles it:

## Bit order on the wire

The word "first" is a protocol decision, independent of significance. The character `A` is 0x41 = 0100 0001. A UART sends the start bit (0), then bit 0 first through bit 7, then a stop bit. SPI in its most common setting sends bit 7 first.

```timing

 "hscale":1.1}
```
Figure: Both rows carry the same byte 0x41 (0100 0001). The UART row sends the 1 in bit 0 first (just after the start bit), then five zeros for bits 1 to 5, then a 1 for bit 6 and a 0 for bit 7. The SPI row sends the 0 of bit 7 first, then the 1 of bit 6, and the 1 of bit 0 comes last. Reading the SPI waveform as LSB-first would give 0x82 instead of 0x41.

If a receiver assumes the wrong order the byte comes out bit-reversed: 0x41 (0100 0001) reversed is 1000 0010 = 0x82. A tell-tale symptom is that every received value is a bit-reversal of the expected one. I²C sends each byte MSB first. Check the device datasheet and the MCU's SPI configuration (many MCUs have an LSBFIRST or bit-order option).

## Fields inside registers

Configuration registers are packed bit fields. Suppose a control register is 0xA5 with these fields: `MODE[7:6]`, `GAIN[5:3]`, `EN[2]`, `RES[1:0]`.

| Field | Bits | Width | Binary | Value |
|---|---|---|---|---|
| MODE | 7:6 | 2 | 10 | 2 |
| GAIN | 5:3 | 3 | 100 | 4 |
| EN | 2 | 1 | 1 | 1 |
| RES | 1:0 | 2 | 01 | 1 |

Extract: `GAIN = (reg >> 3) & 0x7;`. In general `(reg >> lsb) & ((1u << width) - 1)`. To write a field without disturbing the others: `reg = (reg & ~(0x7 << 3)) | (new << 3);`. Here the LSB of the field tells you the shift, and the width gives the mask.

## Real hardware notes

- **Bit numbering conventions.** Most MCU and FPGA documentation uses bit 0 = LSB. Some older or network documents (IBM-style, certain RFC diagrams) number from the MSB, so a packet field "bit 0" can be the high bit. Check the document's figure.
- **Left-justified vs right-justified data.** A 12-bit ADC result in a 16-bit register may be right-aligned (value in bits 11:0) or left-aligned (bits 15:4). A left-aligned value looks 16 times larger until you shift it. Know which one the part uses.
- **Truncating a word.** Dropping low bits (a right shift) loses resolution gracefully; dropping high bits (a mask) causes wrap-around.
:::

::: applications
- **ADC/DAC specifications**: resolution, INL and DNL are quoted in LSBs ([[q0874]]).
- **Register configuration**: setting gain, mode and enable fields in a sensor or PMIC over I²C/SPI.
- **Serial protocol debugging**: spotting bit-reversed data from an LSB/MSB-first mismatch on an oscilloscope or logic analyzer.
- **Signed sensor data**: sign-extending 12-bit or 14-bit IMU/ADC samples packed in 16-bit words.
- **Comparators and arithmetic hardware**: compare and carry logic that scans from the MSB down.
:::

::: assumptions
- Unsigned binary or two's complement integers. Sign-magnitude, one's complement and floating-point formats assign roles to the top bit differently.
- Bit 0 is the LSB. Some documents use the opposite numbering.
- "LSB" in converter contexts means a voltage step, which assumes an ideal uniform quantizer. Real parts quote INL/DNL relative to it.
- UART/SPI bit orders given are the typical defaults; SPI order is configurable and some UART-like devices (e.g. some RS-485 protocols) differ.
:::

::: followups
### How many volts is one LSB on a 10-bit ADC with a 5 V reference?
$5/2^{10}=5/1024=4.88$ mV. The MSB is worth $2.5$ V.

### How do you tell if a received byte is bit-reversed?
Compare against known values: 0x41 ("A") arriving as 0x82 is a reversal. On the scope, decode the same waveform both ways. Fix by setting the SPI bit order (for example the LSB-first bit) or the UART device on the other end to match.

### Why does a SAR ADC determine the MSB first?
It performs a binary search. Setting the MSB tests Vin against $V_{ref}/2$; the answer halves the remaining range, then the next bit tests the midpoint of what's left, and so on. Starting with the largest weight means each decision removes half of the uncertainty; N comparisons give N bits.

### What happens to a number when you right-shift it by one, and why does the MSB matter?
For unsigned values, a logical right shift divides by 2 and inserts 0 at the MSB. For signed two's complement you need an arithmetic shift that copies the sign bit into the MSB, otherwise $-8$ (0xF8) becomes 124 (0x7C) instead of $-4$ (0xFC).

### A 12-bit ADC sample is in the top 12 bits of a 16-bit register (left-justified). How do you recover the voltage?
Shift right by 4 (`code = reg >> 4`), then $V=\text{code}\cdot V_{ref}/4096$. Without the shift the value is $16\times$ too large. If bipolar, sign-extend from bit 11 after the shift.
:::

In converter contexts "LSB" is often used as a unit of voltage, which I mention as well.
