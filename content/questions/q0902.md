::: testing
Whether you can explain an ALU as **combinational logic with an operation-select input**, not just "the part that does math". The interviewer wants:

1. What it computes: add, subtract, AND/OR/XOR, shifts, comparisons.
2. How it is built: a bit-sliced adder plus logic gates and a multiplexer chosen by control bits.
3. The outputs besides the result: status flags (zero, negative, carry, overflow) and why they matter for branches.
4. A feel for speed: carry propagation is the critical path, so adders are designed around it.
:::

::: why
The ALU is on the critical path of almost every CPU: the clock period is often set by the execute stage. Understanding it connects digital-logic fundamentals (gates, full adders, two's complement) to architecture. Interviewers use it to test whether you can build something non-trivial from gates, and whether you know why a 64-bit add can be fast despite carry chains. In practice you'll also meet ALUs in microcontroller datasheets (flags, saturating arithmetic), DSPs (MAC units) and FPGAs (carry chains).
:::

::: concepts
- **Combinational logic**: output depends only on current inputs. See [[q0894]].
- **Full adder**: the bit slice that adds two bits and a carry. See [[q0894]].
- **Two's complement**: lets one adder do signed and unsigned addition and subtraction. See [[q0893]].
- **Multiplexer**: selects which operation's result goes to the output. See [[q0888]].
- **Status flags**: Z, N, C, V; summarize the result for conditional branches.
- **Critical path**: carry propagation limits speed. See [[q0901]].
:::

::: answer
"The ALU, the arithmetic logic unit, is the combinational block in the CPU that performs arithmetic and logic operations on its inputs. It takes two operands, plus a few control bits from the control unit saying which operation, and outputs a result and status flags. Typical operations are add, subtract, AND, OR, XOR, shifts, and comparisons.

Inside, it's built from bit slices. The heart is an adder made of full adders. Subtraction is done with two's complement: invert the second operand and set the carry-in to one, so the same adder does both. In parallel there are gates for AND, OR and XOR on each bit, a shifter, and then a multiplexer driven by the control bits picks which result goes out.

The flags matter too: zero if the result is all zeros, negative from the sign bit, carry from the top bit's carry-out, and overflow when a signed result doesn't fit. Conditional branches use them, like 'branch if equal' means 'subtract and check Z'.

The main design problem is speed. A ripple-carry adder passes the carry through every bit, so delay grows linearly with width, and a 64-bit ripple adder would be too slow. So real ALUs use carry-lookahead or prefix adders with delay growing like log of the width. The ALU is typically on the critical path that sets the CPU clock."
:::

::: technical
**Function.** $R = \text{op}(A,B)$ with op selected by control bits (e.g. 3 to 4 bits): ADD, SUB, AND, OR, XOR, SLT (set if less than), SLL/SRL/SRA (shifts). Outputs $R$ and flags.

**Adder.** Bit $i$: $s_i=a_i\oplus b_i\oplus c_i$, $c_{i+1}=a_ib_i+c_i(a_i\oplus b_i)$. Define generate $g_i=a_ib_i$ and propagate $p_i=a_i\oplus b_i$, so $c_{i+1}=g_i+p_ic_i$.

**Subtraction.** $A-B=A+\overline{B}+1$. Implement by XORing each $b_i$ with a SUB control line and feeding SUB as carry-in.

**Flags (n-bit, two's complement).** $Z=1$ iff $R=0$; $N=R_{n-1}$; $C=c_n$ (carry out; for subtraction, carry set means no borrow in Arm); $V=c_{n-1}\oplus c_n$ (signed overflow). Examples with 8 bits: $0x7F+0x01=0x80$ gives $N=1,V=1,C=0$ (signed overflow, since +127+1 does not fit); $0xFF+0x01=0x00$ gives $Z=1,C=1,V=0$ (unsigned carry-out, but signed -1+1=0 is fine).

**Delay.** Ripple-carry: $t\approx n\,t_{carry}$; with $t_{carry}\approx2$ gate delays and 20 ps per gate, a 32-bit add takes about $32\times40=1.28$ ns. A parallel-prefix (Kogge-Stone style) adder has depth about $\log_2 n$ prefix levels plus P/G generation and the sum XOR: about $(2+\log_2 n)\times20$ ps $=140$ ps for 32 bits (illustrative gate delays; real values depend on process and cell library).

**Larger functions.** Multipliers and dividers are usually separate multi-cycle or pipelined units, and floating-point has its own unit.
:::

::: long
"The ALU, or arithmetic logic unit, is the part of the CPU datapath that actually computes. It's purely combinational: two operand inputs, a few control bits from the control unit that select the operation, and outputs for the result and some status flags. The register file feeds it operands and its result goes back to a register, or is used as a memory address.

Inside, the core is an adder built from full adders, one per bit. Each full adder takes bits $a_i$ and $b_i$ and a carry-in, and produces a sum bit and a carry-out. Subtraction reuses the same adder: in two's complement, $A - B$ is $A$ plus the inverted $B$ plus one, so I XOR the B inputs with a subtract control line and feed that line in as the carry-in. In parallel, there are simple gates computing AND, OR and XOR bit by bit, a barrel shifter, and a comparator, and a multiplexer picks which of those results is the ALU output, controlled by the opcode bits.

The flags are useful: zero is a NOR across the result, negative is the top bit, carry is the carry out of the top bit and tells you about unsigned overflow, and signed overflow is the carry into the top bit XOR the carry out. Conditional branches are just flag tests after a subtract, so 'branch if equal' checks Z.

The design challenge is the carry. A ripple-carry adder passes the carry from bit to bit, so delay grows linearly with width. For 32 or 64 bits that's far too slow for a multi-GHz clock, so real designs use carry-lookahead or parallel-prefix adders where the delay grows with the log of the width. Since the ALU is often the slowest stage, it frequently sets the CPU's clock period."
:::

::: terms
- **ALU**: arithmetic logic unit performing arithmetic and bitwise operations.
- **Full adder**: adds two bits and a carry-in; outputs sum and carry-out.
- **Ripple-carry adder**: chain of full adders with the carry rippling bit to bit.
- **Carry-lookahead / prefix adder**: computes carries in parallel from generate and propagate signals.
- **Generate / propagate ($g_i,p_i$)**: bit $i$ generates a carry if $a_ib_i=1$; propagates one if $a_i\oplus b_i=1$.
- **Two's complement**: signed representation where subtraction is addition of the complement plus one.
- **Status flags (Z, N, C, V)**: zero, negative, carry, overflow indicators.
- **Barrel shifter**: combinational shifter that shifts by any amount in a fixed number of mux levels.
- **Saturating arithmetic**: clamp result to the max/min value instead of wrapping (common in DSPs).
:::

::: exceptional
**An average answer** says "it does arithmetic and logic operations".

**An exceptional answer**:
- Describes the structure: adder/subtractor, logic unit, shifter, result mux selected by control bits.
- Shows how subtraction reuses the adder (invert B, carry-in = 1) and gives the flag equations with a numeric example.
- Explains generate/propagate and why carry-lookahead or prefix adders are faster, with delay scaling ($n$ vs $\log n$).
- Notes the ALU is usually on the critical path and links it to pipeline stage balance and forwarding.
- Distinguishes carry (unsigned) from overflow (signed).
- Mentions where multiply, divide and floating-point live (separate units).
:::

::: mistakes
- **Mixing up carry and overflow.** Carry = unsigned overflow ($c_n$). Overflow = signed overflow ($c_{n-1}\oplus c_n$). $0xFF+1$ sets carry but not overflow; $0x7F+1$ sets overflow but not carry.
- **Saying the ALU has memory.** It is combinational; registers and the PC hold state around it.
- **Thinking subtraction needs a separate subtractor.** Two's complement lets the adder do it with an XOR on B and carry-in 1.
- **Believing a 64-bit adder is 64 times slower than a 1-bit adder.** Prefix adders make it roughly $\log_2 n$ levels deep.
- **Putting multiplication and division inside the simple ALU.** They are separate, multi-cycle or pipelined units in most CPUs.
- **Forgetting the subtract carry convention.** On Arm, carry set after a subtract means no borrow; on some other ISAs it means borrow.
:::

::: deep
## Building the bit slice

A full adder adds three bits: $a$, $b$ and carry-in $c$. Using the truth table ([[q0894]]) you get the sum as three-input parity and the carry as the majority function:
$$s=a\oplus b\oplus c,\qquad c_{out}=ab+c(a\oplus b).$$
With $p=a\oplus b$ (propagate) and $g=ab$ (generate), $c_{out}=g+pc$. The sum is $s=p\oplus c$. This is the formulation that carry-lookahead is built on.

## One adder, add and subtract

In two's complement, $-B=\overline{B}+1$, so $A-B=A+\overline{B}+1$. Put an XOR gate on each $B$ input with a control signal SUB; when SUB = 1 each bit is inverted, and SUB also drives the carry-in. One control wire turns an adder into an adder/subtractor. Because two's complement addition is bit-identical for signed and unsigned operands, the same hardware serves both; only the **interpretation of the flags** differs.

## Flags and what they mean

Compute on 8 bits (I verified these in code):

| Operation | Result | N | Z | C | V | Meaning |
|---|---|---|---|---|---|---|
| 0x7F + 0x01 | 0x80 | 1 | 0 | 0 | 1 | +127 + 1 overflows signed range; unsigned 128 fits so no carry |
| 0xFF + 0x01 | 0x00 | 0 | 1 | 1 | 0 | unsigned wrap (carry); signed -1 + 1 = 0 fine |
| 5 - 7 (A + ~B + 1) | 0xFE | 1 | 0 | 0 | 0 | negative result; C = 0 means a borrow occurred |
| 0x80 - 1 | 0x7F | 0 | 0 | 1 | 1 | -128 - 1 overflows signed |

The rules: $Z=\overline{r_{n-1}+\dots+r_0}$, $N=r_{n-1}$, $C=c_n$, $V=c_{n-1}\oplus c_n$ (equivalently, both operands have the same sign but the result has a different one). Conditional branches then combine flags: "equal" is $Z$, "unsigned lower" is $\overline{C}$ after a subtract on Arm, "signed less than" is $N\oplus V$. This is how `if (a < b)` becomes `cmp; blt`.

## The carry problem and faster adders

In a ripple-carry adder the carry out of bit 0 must ripple through all bits. If each stage takes about two gate delays (AND then OR in $c_{i+1}=g_i+p_ic_i$), the worst case delay is $2n\,t_g$.

Carry-lookahead expands the recurrence so that all carries are functions of the $g$ and $p$ bits directly:
$$c_1=g_0+p_0c_0,\quad c_2=g_1+p_1g_0+p_1p_0c_0,\quad c_3=g_2+p_2g_1+p_2p_1g_0+p_2p_1p_0c_0,\ \dots$$
Terms get wider with bit position, so practical designs group bits (4-bit lookahead blocks, cascaded) or use **parallel-prefix** networks (Kogge-Stone, Brent-Kung, Sklansky) that combine $(g,p)$ pairs in a tree with the associative operator $(g,p)\circ(g',p')=(g+pg',pp')$. Depth is $\log_2 n$ levels.

The prices of prefix adders are area, wiring and power. Kogge-Stone has minimal depth but the most wires; Brent-Kung uses fewer cells with about $2\log_2 n-1$ levels. Designers pick based on the target frequency and area budget. In FPGAs the tools use dedicated fast carry chains, so a plain `+` in RTL maps to a hardware ripple chain that is already fast.

## The rest of the ALU

- **Logic unit**: bitwise AND, OR, XOR, NOR per bit, cheap and fast (one gate per bit).
- **Shifter**: a barrel shifter uses $\log_2 n$ mux layers (shift by 1, 2, 4, 8, 16 for 32 bits) so any shift amount takes a fixed delay.
- **Comparator / SLT**: subtract and look at the sign and overflow bits ($N\oplus V$).
- **Result mux**: picks the adder, logic or shifter output based on the opcode. Putting this mux after the slowest unit is a timing consideration.
- **Saturation and DSP features**: DSP ALUs clamp results on overflow instead of wrapping, which is important in audio and control code.

Multipliers and dividers are generally separate units. A 32×32 multiplier uses a tree of adders (Wallace or Dadda) and takes a few cycles pipelined; division is iterative and takes tens of cycles on many cores.

## Real hardware behavior

The ALU plus its input-bypass multiplexers and the result-forwarding wire is the **execute-stage critical path** in most pipelines; if the multiplexer-ALU-bypass loop is $t_{loop}=250$ ps, the clock cannot be faster than about 4 GHz (given register overhead, less). That is why high-frequency CPUs sometimes pipeline the ALU into two cycles (and lose back-to-back dependent issue), or split a wide adder into narrower slices that complete in staggered cycles. Power-wise, an adder's dynamic energy depends on switching activity: toggling high-order bits during a carry ripple, adding glitches, is a known source of ALU power in ripple adders, and part of why unequal path delays matter for energy as well as timing.

> [!INTERVIEW]
> If asked to "design a 1-bit ALU", draw AND, OR and a full adder feeding a 4:1 mux, with an invert-B input for subtraction and the carry chain between slices. State the select codes (00 AND, 01 OR, 10 ADD), and mention SLT needs the MSB's sum (XORed with the overflow bit, so it is the true sign of A - B) fed back to bit 0.
:::

::: applications
- **CPU execute stage**: every integer instruction passes through an ALU; address generation for loads/stores also uses an adder.
- **Microcontroller cores (Cortex-M, AVR)**: ALU flags drive conditional branches in firmware loops.
- **DSP cores**: saturating ALUs with multiply-accumulate units for filters and control loops.
- **FPGAs**: DSP slices and carry chains implement wide ALUs and counters.
- **Address and counter logic**: program-counter incrementers and index registers are specialized adders.
:::

::: assumptions
- **n-bit two's complement integers**; floating-point arithmetic uses a different unit with mantissa and exponent handling.
- **Gate-delay numbers are illustrative.** Actual carry delay depends on process, cell library and loading; the $n$ vs $\log n$ scaling is the reliable part.
- **Flag conventions vary by ISA.** Arm sets carry after subtract to mean "no borrow"; x86 sets CF to mean borrow; RISC-V has no flags at all and compares in the branch instruction itself.
- **A combinational ALU in a single cycle**; some designs spread an ALU across two cycles.
- **Multiplier/divider excluded** from the basic ALU, per most textbooks.
:::

::: followups
### How does the ALU subtract?
It adds the two's complement: $A-B=A+\overline{B}+1$. XOR each bit of B with a SUB control line and use SUB as the carry-in, so the same adder does both.

### What's the difference between the carry flag and the overflow flag?
Carry flags unsigned overflow: a carry out of the top bit. Overflow flags signed overflow: operands of the same sign give a result of the opposite sign, computed as $c_{n-1}\oplus c_n$. Example: 0xFF+1 gives carry but no overflow; 0x7F+1 gives overflow but no carry.

### Why is a ripple-carry adder slow, and how do you speed it up?
Each bit must wait for the carry from the previous bit, so delay is linear in $n$. Carry-lookahead computes carries directly from generate/propagate bits, and parallel-prefix adders do it in about $\log_2 n$ levels. With 20 ps gates a 32-bit ripple adder is about 1.28 ns versus about 140 ps for a prefix adder.

### Design a 4-bit ALU supporting ADD, SUB, AND, OR.
Four 1-bit slices, each with AND, OR, a full adder, an XOR on B controlled by a SUB line, and a 4:1 mux selecting AND, OR, ADD/SUB result. Chain the carry between slices with carry-in of bit 0 = SUB. Control encoding for example: 00 AND, 01 OR, 10 ADD, 11 SUB (SUB = control bit pattern 11 and ADD uses carry-in 0). Add Z as a NOR of the four result bits.

### Why would a CPU designer pipeline the ALU into two cycles?
At very high clock frequencies the add plus bypass loop doesn't fit in one cycle. Splitting it saves frequency but makes dependent instructions wait an extra cycle, so it is only done when frequency gains outweigh the lost IPC.
