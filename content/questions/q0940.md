::: testing
Whether you know what the word "random" **does and does not** mean, and can contrast random-access with sequential-access memory. The interviewer wants:

1. The precise definition: any address can be accessed in (approximately) the same time, independent of the previous access, rather than "unpredictable" or "arbitrary data".
2. Examples on both sides: SRAM/DRAM/ROM (random) vs tape, shift registers/FIFOs and disks (sequential or semi-random).
3. The hardware reason: an address decoder directly selects a cell; there is no moving medium or serial chain to traverse.
4. Honest nuance: real DRAM and flash are *not* perfectly uniform (row buffers, banks, caches, pages).
5. Why it matters to software and system design: arrays, pointer chasing, access patterns.
:::

::: why
The name "RAM" is one of the most misunderstood terms in computing. Getting it right shows you understand what a memory array physically is, and the nuance (that real memories reward sequential or local access) is exactly the knowledge that makes code and hardware fast: caches, DRAM row-buffers, SSD page reads and HDD seeks are all about the gap between idealized random access and real cost. It also gives you a clean way to explain why the CPU can jump to any instruction or variable address and why a tape drive cannot.
:::

::: concepts
- **Address decoding**: an $n$-bit address selects one of $2^n$ locations through a decoder/mux tree. See [[q0939]].
- **Sequential-access memory**: reaching a location requires passing through the preceding ones (tape, shift register, FIFO).
- **Access time (latency) vs throughput**: uniform latency does not mean equal bandwidth for all patterns.
- **Locality**: real hardware makes nearby/sequential accesses cheaper than distant ones. See [[q0936]].
- **Row buffer / page mode**: why DRAM is only approximately random. See [[q0939]].
- **Non-volatile vs volatile**: orthogonal to random access (ROM and flash are random-access but non-volatile). See [[q0826]].
:::

::: answer
"Random access means you can read or write any location directly, and it takes about the same amount of time no matter which address you pick or which one you accessed last. 'Random' doesn't mean the data or the order is unpredictable; it means the access order is arbitrary and unconstrained, the hardware doesn't care.

It's contrasted with sequential access, like a magnetic tape: to get to the 1,000th byte you have to wind past the first 999, so the access time depends on where the head is and where the data is. A hard drive is in between, because it has to move the head and wait for the platter to rotate.

The reason RAM can do this is how it's built. An address goes into a decoder that activates exactly one word line, and the selected cells drive the bit lines, so the time depends on the circuit, not on how far away the address is. The same would be true of ROM or flash reads.

In real systems it's only approximately true. DRAM has row buffers, so reading another address in the same open row is faster than opening a new row, and caches make recently used addresses faster. So software still benefits from locality, but the point is the hardware gives you direct access to any byte."
:::

::: technical
**Definition.** A memory is *random access* if the access time $t_{acc}$ is independent of the address and of the previous address accessed: $t_{acc}(a_i \mid a_{i-1}) \approx \text{const}$ for all $a_i, a_{i-1}$.

**Mechanism.** For $N = 2^n$ words, an $n$-bit address drives a row decoder (to a one-hot word-line) and a column mux. Decoder depth is $\log_2 N$ gate stages, and the word-line/bit-line RC depends on the array geometry, not on which cell is selected (all cells have the same distance class, or the design is timed for the worst-case cell). So worst-case timing is the same for every address.

**Sequential / semi-random media.**
- *Tape*: $t \propto$ distance between consecutive accesses (seconds to minutes).
- *Hard disk*: $t \approx t_{seek} + t_{rot} + t_{transfer}$; for 7200 rpm, average rotational latency $= \tfrac12\cdot\frac{60}{7200}$ s $=4.17$ ms; with ~8 ms average seek, random 4 KB reads take ~12 ms ⇒ ~82 IOPS ⇒ 0.34 MB/s, versus ~150 MB/s sequential, a ~450x gap.
- *Shift register / FIFO*: data comes out in the order it went in.
- *SSD/NAND*: pages are directly addressable (random read at ~tens of µs), but writes are page-programmed and blocks must be erased first.

**Real RAM is only approximately uniform.** DRAM: a *row hit* costs just the CAS latency, e.g. DDR4-3200 CL22: $22\times 0.625\,\text{ns} = 13.75$ ns; a *row miss* adds precharge and activate, about $3\times 13.75 \approx 41$ ns. Add caches in front and the observed time depends strongly on history.

**Not about volatility.** ROM, NOR flash and FRAM are random-access but non-volatile. "RAM" is a historical name for read/write random-access memory, to distinguish it from ROM and from sequential media.
:::

::: short
"Random access means any address can be read or written in about the same time, independent of where you accessed last, because an address decoder selects the cell directly. It doesn't mean the data is random. It's contrasted with sequential access like tape, where reaching a location means winding past everything before it, and semi-random media like hard disks, where seek and rotation depend on position. Real DRAM isn't perfectly uniform because of row buffers and caches, but the hardware still gives direct access to any byte."
:::

::: long
"Random access means that I can access any location in the memory directly, and the time it takes doesn't depend on which location I pick or where I was before. The word 'random' is about the order of access being arbitrary, not about the data being unpredictable.

The easiest way to see it is by contrast. A tape drive is sequential: the data is laid out along the tape, so to read byte one million I have to wind past all the bytes before it, and the time depends on how far the head has to travel. A hard disk is in between: the head has to seek to the right track and wait for the platter to rotate under it. On a 7200 rpm drive the rotation alone averages about 4 ms, and with seek, a random 4 KB read takes around 12 ms, which is roughly 80 operations a second, versus streaming at 150 MB/s when reading sequentially. That's a gap of several hundred times.

RAM avoids this with its structure. An n-bit address goes through a decoder that raises exactly one word line, the cells on that row drive the bit lines, and a column mux picks the bits. The delay is set by the decoder and the wires, the same for every address, so any location costs the same.

That's also true for ROM and many flash reads, so random access has nothing to do with being volatile.

In practice it's idealized. DRAM has row buffers: a read to the already-open row takes roughly the CAS latency, around 14 ns for DDR4-3200, while a different row needs a precharge and activate first, about three times that. And caches mean recently used addresses are much faster. So hardware offers direct access, but software still gets the best performance from locality."
:::

::: terms
- **Random access**: access time independent of address and of previous access.
- **Sequential access**: data reachable only by passing through intervening data (tape, shift register).
- **Access time / latency**: time from address presented to data available.
- **Seek time / rotational latency**: HDD head-positioning and platter-rotation delays.
- **Address decoder**: logic that converts an address into a one-hot select.
- **Row hit / row miss (DRAM)**: access to the currently open row vs one that requires closing and opening another.
- **IOPS**: input/output operations per second, a measure of random-access performance.
- **Locality**: the tendency to access nearby or recent addresses.
:::

::: exceptional
An average answer says "you can access any location in the same time". An exceptional answer:

- Corrects the misreading of "random" and ties the definition to the **hardware** (decoder, uniform path).
- Gives concrete **contrasting numbers**: HDD ~12 ms random vs 150 MB/s sequential (~82 IOPS ⇒ 0.34 MB/s vs 150 MB/s), tape minutes.
- Notes that **RAM isn't perfectly uniform**: DRAM row-buffer hit vs miss (14 vs ~41 ns), banks, caches, NUMA.
- Separates **latency from bandwidth**, and random access from volatility.
- Connects to software: array indexing is O(1) because memory is random-access, while linked-list traversal pays the miss penalty of dependent random accesses.
:::

::: mistakes
- **"Random" means the contents are random or the access is unpredictable.** It means the order is arbitrary; any order costs about the same.
- **RAM is the only random-access memory.** ROM, NOR flash and SRAM-based register files also are.
- **Assuming perfectly equal time for all addresses in real systems.** Caches, DRAM rows, banks, NUMA nodes and page faults all make it uneven.
- **Equating random access with volatility** (RAM vs ROM). Random access and volatility are independent properties.
- **Thinking an SSD is sequential-only.** NAND pages are randomly readable; it is the erase-before-write block structure that limits random writes.
:::

::: deep
## What the word really claims

Let a memory have $N$ words and let $t(a_{prev}, a)$ be the time to access $a$ right after $a_{prev}$. The memory is random-access if $t$ is (to first order) independent of both arguments. Compare:

| Memory | $t(a_{prev}, a)$ depends on... | Example numbers |
|---|---|---|
| SRAM / register file | nothing (decoder + wire delay) | ~1 ns |
| DRAM | whether $a$ is in the open row; bank | 14 ns (row hit) to ~41 ns (row miss) at DDR4-3200 |
| NAND flash read | page granularity, but not distance | ~50 to 100 µs |
| HDD | distance (seek) and angle (rotation) | 1 to 15 ms |
| Tape | distance along the tape | seconds to minutes |
| Shift register / FIFO | order of insertion | fixed order |

## How the hardware achieves uniform time

An $n$-bit address is split into row and column bits. Take a 1 M x 8 SRAM ($n=20$): 10 row bits drive a 10-to-1024 decoder that raises one word-line; 10 column bits select 8 of 1024 bit-line pairs through a column mux. Three observations:

1. **No traversal**: the signal path from address pins to the selected cell is a decoder tree of depth about $\log_2 N = 20$ for a flat decoder (or fewer stages with pre-decode), plus word-line and bit-line RC, which are the same order for every cell by geometry. Designers time the memory for the *worst-case* (farthest) cell, so every access takes the same time at the interface.
2. **Cost of directness**: a decoder and wire for each row. This is why random-access memories cost more per bit than serial memories such as tape or a shift register, and why large arrays are divided into banks (shorter lines, smaller decoders).
3. **Time-multiplexed addressing in DRAM**: to save pins, DRAM sends the row address, then the column address on the same pins. That breaks pure uniformity: the activate (RAS) step is slow, but once a row is open, other columns in it are cheap.

## Worked example: HDD vs RAM, quantified

A 7200 rpm disk: one revolution = $60/7200 = 8.33$ ms, so average rotational latency is half of that, 4.17 ms. With an average seek of 8 ms, a random 4 KB read takes about $8 + 4.17 = 12.2$ ms (plus negligible transfer). That is $1000/12.2 \approx 82$ operations per second, i.e. $82\times4\ \text{KB} \approx 0.34$ MB/s. Streaming the same disk sequentially (no seeks) gives about 150 MB/s, a factor of $150/0.34 \approx 450\times$ in favour of sequential.

For DRAM: a row miss at DDR4-3200 CL22 (precharge + activate + CAS, each ~13.75 ns) is about 41 ns, and a row hit is 13.75 ns: only a 3x spread. For the same 4 KB, DRAM random access is thousands of times faster than the HDD, which is why a paging fault to disk is so costly.

## Where "random access" meets software

- **Arrays**: `a[i]` is address `base + i*size`, then one random access: O(1) because memory is random-access. A tape-like medium would make array indexing O(n).
- **Linked lists / pointer chasing**: each next address depends on the previous load, so every node is a dependent random access. If the nodes are scattered, each load can be a cache miss costing ~80 ns, making a 10,000-node traversal ~0.8 ms versus ~10 µs for a contiguous array scan (at ~1 ns per cached access). Same random-access hardware, very different outcomes.
- **Databases / filesystems**: B-trees and log-structured designs exist because random I/O on HDDs was ~450x worse than sequential; on SSDs the gap shrinks to maybe 3x to 10x in throughput but remains.

## Real-hardware caveats

- **NUMA**: in multi-socket servers, memory attached to another CPU takes longer: random access is "uniform" only within a socket.
- **Page walks**: with virtual memory, a TLB miss adds several dependent memory accesses before the real one ([[q0943]]).
- **Refresh**: a DRAM access that collides with a refresh waits hundreds of ns: tail latency.
- **Flash**: NOR flash is truly random-read (execute-in-place); NAND must read whole pages (e.g. 4 to 16 KB) so "random byte read" costs a page read.

> [!INTERVIEW]
> If asked "is RAM really random-access?", answer yes at the programmer's abstraction (any address, no seeks), then add that physically DRAM has row hits vs misses, caches and NUMA, so access *pattern* still matters for performance. That shows you know the idealization and where it breaks.
:::

::: applications
- **CPU instruction and data memory**: branches and pointer dereferences jump anywhere, which requires random-access program/data memory.
- **Lookup tables in DSP and FPGA block RAM**: any entry read in one cycle.
- **MCU SRAM and flash XIP**: execute-in-place requires flash that is random-readable (NOR).
- **Hash tables and databases in DRAM**: rely on O(1) random access.
- **Contrast cases**: magnetic tape backup, FIFO/shift-register buffers for streaming ADC data, sequential UART or SPI flash streaming.
:::

::: assumptions
- I treat "random access" as the standard computer-architecture meaning: uniform-time direct addressing. Some texts use "direct access" for disks to mean "can jump to a location but with variable time".
- DRAM timing numbers are for DDR4-3200 CL22 as a representative case; other speed grades and generations differ.
- The HDD numbers (8 ms seek, 7200 rpm) are typical desktop-class; enterprise and laptop drives differ.
- "Same time" is meant at the memory-interface level, ignoring caches, refresh and bank conflicts, which an interviewer may or may not want you to bring up; mention them briefly.
:::

::: followups
### Is an SSD random access?
Reads, yes: any page can be read directly in tens of microseconds with no mechanical positioning, so there is no seek penalty like an HDD. But writes are not symmetric: NAND is programmed in pages and erased in much larger blocks, so random small writes cause write amplification, garbage collection and slower sustained performance. So reads are random-access; writes are constrained.

### Why isn't DRAM latency perfectly uniform?
DRAM is organised in banks of rows; an access must activate (open) a row into a row buffer, then select columns, then precharge to switch rows. A row hit (~14 ns) is much cheaper than a row miss (~41 ns). Bank conflicts, refresh and the memory controller's scheduling add more variation.

### What's the difference between "random access" and "direct access"?
Some authors use "direct access" for devices like disks where you can address a block directly but the time varies with position, and reserve "random access" for uniform-time devices. In common usage "random access" is the uniform-time idealization, and disks are described as "semi-random" or "direct-access".

### Why is a linked list slower than an array if both are in RAM?
Both use random-access hardware, but array elements are contiguous, so spatial locality means one 64-byte cache line serves 16 ints, and hardware prefetchers see the stride. List nodes are scattered, so each hop is a dependent load that may miss all the way to DRAM (~80 ns). 10,000 nodes can be ~0.8 ms vs ~10 µs for the array, an ~80x gap.

### Harder: how would you design a memory that guarantees truly uniform access time for hard real-time use?
Use SRAM or tightly-coupled memory rather than DRAM/caches, so there are no row misses, refresh collisions or cache replacement effects; or constrain the controller (closed-page policy, fixed refresh slots, bank-privatized access) so the worst-case latency is bounded and known. You trade peak performance for predictability, which is why real-time MCUs use TCM or scratchpad.
:::
