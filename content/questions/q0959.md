::: basics
### In plain words
A multiplexer, or mux, is a digital switch that passes exactly one of several inputs to a single output. A control input, called the select, chooses which one. It is the hardware version of an if statement. Chips use muxes everywhere.

### Picture it
Think of a railway junction. Several tracks arrive, one track leaves, and a lever decides which arriving track is connected to the outgoing one. Flip the lever, and a different track feeds the output. One caution: if the lever moves at the wrong instant, the output can flicker, which matters only if it drives a clock (the beat that paces a chip).

### Words you need
- **Select line**: the control input that chooses which data input reaches the output.
- **One-hot**: a signal with exactly one bit set.
- **Gates**: tiny logic circuits. An inverter flips 0 and 1, AND gives 1 only if all inputs are 1, and OR gives 1 if any input is 1.
- **Inferred latch**: an unwanted memory element created when code forgets to set the output on some path.
- **Glitch**: a very short wrong pulse on a signal that should stay steady.
- **Parameter**: a setting in RTL (hardware description) code, such as data width, so one block serves many uses.

### The simplest example
A 2:1 mux has data inputs A and B and a select S. The output is $Y=\bar S A + S B$, read as "(not S) AND A, OR S AND B", so S = 0 passes A and S = 1 passes B. If A = 1 and B = 0, then Y = 1 when S = 0, and Y = 0 when S = 1. In gates, that is one inverter, two ANDs and an OR. A 4:1 mux is three 2:1 muxes. In general an N:1 mux needs $N-1$ of them in $\log_2 N$ levels. That is the whole idea. The rest of this page covers a transistor-level mux, latch-free RTL, and the glitch hazard.
:::

::: testing
Whether you can take a tiny, familiar block and design it at **several levels** without being prompted: a truth table and Boolean equation, a gate or transistor schematic, and synthesizable RTL. The interviewer is also listening for the details that separate someone who has actually written Verilog from someone who memorized a diagram:

1. You ask what is needed first: number of inputs, data width, one-hot or binary select, timing budget.
2. Your RTL is parameterized and has no accidental latch (a missing `else` or `default`).
3. You can scale from 2:1 to N:1 and say what it costs in delay and area.
4. You know the classic hazard: a plain AND-OR mux can **glitch** when the select switches while both data inputs are 1.
:::

::: why
Muxes are the most common building block in digital design. Every register-file read port, every ALU operand select, every bus fan-in, every clock-select and every FPGA look-up table is a mux or a tree of them. Because it is so simple, interviewers use "design a mux" to see how you structure an open-ended design problem, and to check whether your RTL habits (parameters, `default` cases, no latches, no glitches on clocks) are sound. It also leads naturally into follow-ups on transmission gates, one-hot encoding and hazards, all of which show up in real timing and power work.
:::

::: concepts
- **Selection by a control input**: a mux with $n$ select bits chooses one of $2^n$ data inputs. See [[q0888]] for the definition.
- **Boolean algebra**: a 2:1 mux is $Y = \bar S\,A + S\,B$, a sum of products that maps directly to gates. See [[q0889]] and [[q0890]].
- **Combinational logic in RTL**: `assign` or `always_comb` with full assignment on every path, otherwise synthesis infers a latch. See [[q0956]] for RTL basics.
- **Propagation delay and hazards**: unequal path delays in the select logic can produce a brief wrong output. See [[q0885]].
- **CMOS implementation**: transmission gates and AOI cells give very different transistor counts and speeds. See [[q0890]].
- **Parameterization**: width and input count as parameters so one module serves many places. See [[q0961]].
:::

::: answer
"I'd start by asking what kind of mux: how many inputs, how wide is each input, and whether the select is binary or one-hot. Let me assume a 2:1 mux first and then generalize.

A 2:1 mux has data inputs A and B, a select S, and an output Y that equals A when S is 0 and B when S is 1. The equation is Y equals not-S times A, plus S times B. In gates that's one inverter, two ANDs and an OR. In RTL it's a single line: `assign y = sel ? b : a;`, and I'd make the width a parameter so I can reuse it for buses.

For N inputs I'd use an array index, `y = d[sel]`, or a `case` with a `default` so there's no latch. In hardware that becomes a tree of 2:1 muxes, log2 of N levels deep, or a flat AND-OR if the select is already one-hot, which is faster because there's no decode step.

One thing I'd mention is that a naive AND-OR mux can glitch when S switches and A and B are both 1, because the inverted select arrives late. That's harmless on data going into a flip-flop but dangerous if the mux output is a clock, so for clock muxes you use a glitch-free design with enables synchronized to each clock. In CMOS I'd build it with transmission gates, six transistors for a 2:1, instead of gates."
:::

::: technical
**Specification.** $2^n$ data inputs $D_0\ldots D_{2^n-1}$, $n$ select bits, one output $Y = D_{\text{sel}}$.

**2:1 truth table and equation.**

| S | A | B | Y |
|---|---|---|---|
| 0 | 0 | x | 0 |
| 0 | 1 | x | 1 |
| 1 | x | 0 | 0 |
| 1 | x | 1 | 1 |

$$Y = \bar S A + S B$$

**4:1 mux.** $Y = \bar S_1\bar S_0 D_0 + \bar S_1 S_0 D_1 + S_1\bar S_0 D_2 + S_1 S_0 D_3$. Equivalent to three 2:1 muxes: two selected by $S_0$ in the first level and one selected by $S_1$ in the second.

**Cost of an N:1 mux.** A binary tree needs $N-1$ 2:1 muxes and $\log_2 N$ levels of delay. A flat one-hot AND-OR needs $N$ AND gates and one $N$-input OR, with delay set by the OR tree, but needs a one-hot select (a decoder in front costs the same delay again).

**RTL (synthesizable SystemVerilog).**

```verilog
module mux2 #(parameter int W = 8) (
  input  logic [W-1:0] a, b,
  input  logic         sel,
  output logic [W-1:0] y
);
  assign y = sel ? b : a;
endmodule

module muxn #(parameter int W = 8, parameter int N = 4) (
  input  logic [W-1:0]         d [N],
  input  logic [$clog2(N)-1:0] sel,
  output logic [W-1:0]         y
);
  always_comb y = d[sel];   // out-of-range sel gives X in simulation
endmodule
```

**Pitfalls.** An `if` without `else`, or a `case` without `default` inside `always_comb`, creates a latch. A priority `if/else if` chain synthesizes to a priority mux (chain of 2:1 muxes), which is slower than a parallel `case` when the conditions are mutually exclusive.

**Hazard.** For $A=B=1$ the function must hold at 1 as $S$ changes, but the AND terms hand off through an inverter delay, so $Y$ can dip low briefly (a static-1 hazard). Adding the consensus term $AB$ fixes it: $Y = \bar S A + S B + AB$.
:::

::: long
"First I'd clarify what's needed: how many inputs, how wide, binary or one-hot select, and whether this is on a critical path. Then I'd build it up.

Start with a 2:1 mux. The output is A when S is zero and B when S is one, so Y equals S-bar times A plus S times B. As gates that's one inverter, two ANDs and an OR. As CMOS I could use two transmission gates driven by S and S-bar, which is only six transistors with the inverter, compared with fourteen for a NAND-NAND version, and it's also faster because the signal goes through one pass gate.

For four inputs I can write the full sum of products, or just stack three 2:1 muxes: two in the first level on S0 and one in the second on S1. In general an N-input mux is N minus one 2:1 muxes and log2 N levels deep. If the select is already one-hot, for example from an arbiter, I can skip the tree and do a flat AND-OR: AND each data input with its select line and OR the results. That's one AND delay plus an OR tree.

In RTL I'd write it parameterized for width and number of inputs. For two inputs it's a ternary assign; for more, an array indexed by the select inside an always_comb block. The thing I check is that every path assigns the output, so synthesis doesn't infer a latch, and I'd add a default in any case statement.

Last, hazards. With A and B both one, flipping S can glitch the output low for one inverter delay, because the not-S branch turns on after the S branch turns off. If the output feeds a flip-flop that's fine because it settles before the clock edge, but on a clock path it creates a runt pulse. Clock muxes need a proper glitch-free structure, with the select synchronized to each clock domain before it's used. I'd verify with an exhaustive testbench, since a small mux has few enough input combinations to test them all."
:::

::: terms
- **Select line**: the control input(s) that choose which data input reaches the output.
- **Data selector / multiplexer**: a combinational block that routes one of $2^n$ inputs to a single output.
- **Demultiplexer (demux)**: the inverse, routing one input to one of $2^n$ outputs.
- **One-hot select**: exactly one select line is 1; allows a flat AND-OR with no decode.
- **Transmission gate**: parallel NMOS and PMOS pass transistors that pass both logic levels without a threshold drop.
- **Static-1 hazard**: a momentary 0 on an output that should stay at 1, caused by unequal path delays.
- **Inferred latch**: unintended storage created when a combinational block does not assign an output on every path.
- **Priority mux**: a chain of conditions where earlier ones win, as from an `if / else if` chain.
- **Glitch-free clock mux**: a clock selector whose enables are synchronized and gated so switching never produces a runt pulse.
:::

::: exceptional
**An average answer** draws the 2:1 gate diagram and writes the equation.

**An exceptional answer**:
- Opens with requirements (width, N, select encoding, timing) rather than jumping to gates.
- Walks 2:1 to 4:1 to N:1 and states the scaling: $N-1$ muxes, $\log_2 N$ levels, versus flat one-hot AND-OR.
- Writes parameterized RTL with a `default` or full assignment and names the latch pitfall.
- Mentions a transistor-level implementation (transmission gate, 6T) and why it is smaller and faster than NAND-NAND (14T).
- Raises the static-1 hazard unprompted, explains the consensus term, and notes that data muxes tolerate it while clock muxes do not.
- Says how they would verify: exhaustive test for a small mux, assertions for one-hot selects on a big one.
:::

::: mistakes
- **Forgetting the `else` or `default`.** The synthesis tool adds a latch holding the old value. Assign a default at the top of `always_comb`.
- **Using a priority `if/else if` chain for a plain N:1 select.** It builds a serial chain of muxes. Use `case` or an array index when the conditions are exclusive.
- **Calling a mux a "decoder".** A decoder turns $n$ bits into $2^n$ one-hot lines and has no data inputs.
- **Saying the glitch is a bug on any data mux.** A glitch on a signal that settles before the capturing clock edge is harmless. It only matters on clocks, resets and asynchronous inputs.
- **Using a transmission-gate mux to drive a long wire directly.** The pass gate has on-resistance and no gain, so a buffer is needed after several stages.
- **Ignoring out-of-range select values.** With 3 inputs and a 2-bit select, the fourth code must be defined (a default or "don't care") or the simulation produces X.
:::

::: deep
## Start from the function

A mux is the hardware version of an `if` statement. Two data inputs, one select:

| S | Y |
|---|---|
| 0 | A |
| 1 | B |

Writing Y as a function of all three inputs gives the sum of products $Y = \bar S A + S B$. Each product term is "this input AND the select that enables it". The OR combines the enabled one with the disabled one (which is 0). That structure, enable-AND-then-OR, is what every wider mux repeats.

## Scaling up: the tree and the flat form

For four inputs there are two natural structures.

**Tree.** Use three 2:1 muxes. The first level selects between $D_0/D_1$ and between $D_2/D_3$ using $S_0$. The second level selects between those results using $S_1$. Delay is two mux delays; cost is three muxes.

**Flat sum of products.** Decode the two select bits into four lines, AND each with its data input and OR everything. The decode costs one gate delay, then one AND, then a four-input OR.

For $N$ inputs, the tree has $N-1$ muxes and $\log_2 N$ levels. Doubling $N$ adds one level of delay and doubles the area. That is why a 64:1 mux in a register file is usually built from 4:1 or 8:1 stages: each stage is a single complex gate rather than a chain of 2:1 muxes.

| Inputs N | 2:1 muxes in a binary tree | Levels |
|---|---|---|
| 2 | 1 | 1 |
| 4 | 3 | 2 |
| 8 | 7 | 3 |
| 16 | 15 | 4 |
| 64 | 63 | 6 |

When the select signals are already one-hot (an arbiter grant, a state machine's one-hot state), the flat AND-OR form skips the decoder entirely. This is common on shared buses.

## RTL: how to write it so it synthesizes well

```verilog
// 2:1, W bits wide
assign y = sel ? b : a;

// 4:1 with explicit case and a default
always_comb begin
  case (sel)
    2'd0: y = d0;
    2'd1: y = d1;
    2'd2: y = d2;
    2'd3: y = d3;
    default: y = '0;     // never reached, but keeps the block fully assigned
  endcase
end

// One-hot AND-OR mux, N inputs
always_comb begin
  y = '0;
  for (int i = 0; i < N; i++)
    y |= {W{sel_oh[i]}} & d[i];
end
```

Three habits matter:

1. **Assign every output on every path.** A default at the top of the block or in the `case` stops the latch.
2. **Choose parallel over priority.** `case` expresses "exactly one of these", while `if / else if` expresses "first match wins" and costs a serial chain unless the tool can prove the conditions are exclusive.
3. **Make width and count parameters.** The same module then serves a 1-bit select, a 32-bit data bus, or an 8-input register read port. See [[q0961]].

> [!TIP]
> If the select can only be one of three values but the field is two bits, say what should happen for the fourth code. Either define it (`default`) or deliberately mark it a don't-care (`'x`) so synthesis may optimize; don't leave it accidental.

## Transistor level: why transmission gates win

A NAND-NAND 2:1 mux needs three NAND2 gates (4 transistors each) plus an inverter for S: $3\times4 + 2 = 14$ transistors. A **transmission-gate** mux uses one NMOS and one PMOS in parallel per input. When S selects A, the gate pair on A is on and the pair on B is off.

```circuit
 {"t":"wire","pts":[[8,2],[11,2],[11,5]]},
 {"t":"term","at":[0,8],"label":"B","side":"left"},
 {"t":"wire","pts":[[0,8],[3,8]]},
 {"t":"SWclosed","a":[3,8],"b":[8,8],"label":"TG_B (on if S=1)"},
 {"t":"wire","pts":[[8,8],[11,8],[11,5]]},

 {"t":"wire","pts":[[11,5],[14,5]]},
 {"t":"term","at":[14,5],"label":"Y","side":"right"}

```
Figure: Switch-level picture of the mux. With S = 1, the B pass gate conducts and the A pass gate is open, so Y = B. Each real switch is an NMOS+PMOS pair driven by S and its complement, so the whole mux is 4 transistors plus a 2-transistor inverter for S-bar: 6 in total.

The transmission gate passes both a strong 0 (through the NMOS) and a strong 1 (through the PMOS), so there is no threshold-voltage drop. Its limits: it has no gain, so it relies on whoever drives A and B, and the output must be buffered if many stages are chained or the load is large. In a multi-bit bus the S-bar inverter is shared, so the cost per bit approaches 4 transistors.

## The glitch

Take $A = B = 1$ so $Y$ should be a steady 1 whichever way $S$ points. When $S$ falls, the $S\cdot B$ term turns off immediately, but $\bar S\cdot A$ only turns on after the inverter delay. In between, both terms are 0.

```timing
{"signals":[
 {"name":"S","wave":"1.0....."},
 {"name":"S̄ (after INV)","wave":"0..1...."},
 {"name":"S·B","wave":"1..0...."},
 {"name":"S̄·A","wave":"0...1..."},
 {"name":"Y","wave":"1...01..","color":"red"}
],"marks":[{"t":4,"label":"glitch"}],"hscale":1.2}
```
Figure: A = B = 1 throughout. S̄ lags S by one inverter delay and each AND adds another, so S·B drops before S̄·A rises. For one gate delay the OR sees two zeros and Y glitches low. A consensus term A·B (always 1 here) holds the OR high through the hand-off.

For a mux in a data path this runt disappears long before the next clock edge, so synthesis tools do not bother. If the mux **is** the clock path, a glitch is a false clock edge, so clock-select logic is built with a small FSM and enables that are synchronized to each source clock and only change while that clock is low (see [[q0957]] and [[q0946]] for clock divider and clock domain context).

## Where a mux hides in other blocks

- A **look-up table (LUT)** in an FPGA is a $2^k$:1 mux whose data inputs are configuration bits and whose select lines are the logic inputs. A 4:1 mux with data inputs $0,0,0,1$ is an AND gate; with $0,1,1,0$ it is XOR.
- A **register file** read port is a $R$:1 mux per bit, where $R$ is the number of registers.
- A **flip-flop with enable** is a 2:1 mux feeding the D input: select between the old Q and the new data.
- A **barrel shifter** is $\log_2 W$ stages of 2:1 muxes, each shifting by a power of two.

A worked check: a 32-bit-wide, 8-input mux built as a binary tree uses $7\times 32 = 224$ two-to-one muxes. With transmission-gate cells at 4 transistors per bit-mux (select inverters shared) that is $224\times4 = 896$ transistors, plus a few select inverters. A flat NAND-NAND version at 14T per 2:1 would use about $224\times14 = 3136$. The numbers are order-of-magnitude, because standard-cell libraries have dedicated 4:1 and 8:1 mux cells and the tool decides.

## Verification

A mux is small enough to test exhaustively: for a 2:1 mux with 1-bit data there are 8 input combinations; for a 4:1 with 1-bit data, $2^6 = 64$. For wide buses use randomized data with a self-checking reference (`assert (y === d[sel])`) and add an assertion that one-hot selects are in fact one-hot. A good testbench also flips the select in the middle of a cycle in gate-level simulation with delays, to expose hazards that RTL simulation hides.
:::

::: applications
- **Register file read ports** in a CPU: one $R$:1 mux per bit selects the addressed register.
- **ALU operand select and forwarding paths** in a pipeline: a mux picks between the register value and a forwarded result ([[q0909]]).
- **FPGA look-up tables**: every logic LUT is a mux tree whose leaves are programmed bits.
- **Clock selection** on an SoC (for example choosing between a crystal and a PLL output), done with a glitch-free clock mux.
- **Analog multiplexers** (such as an 8:1 CMOS analog switch IC in front of an ADC) share one ADC between several sensors, using the same transmission-gate idea.
- **Data buses with tri-state replacement**: on-chip, a one-hot AND-OR mux is used instead of tri-state buffers, which are avoided in most ASIC flows.
:::

::: assumptions
- **Combinational, zero-delay RTL.** The ternary and case forms assume ideal behavior; gate-level delays introduce the hazard described above.
- **Binary-encoded select.** If the select is one-hot, a flat AND-OR is smaller and faster, and a binary-index `d[sel]` would force an unnecessary encode.
- **Fully static CMOS cells.** A transmission-gate mux needs buffering and has a different delay model from NAND-based logic; some libraries avoid it for noise or characterization reasons.
- **Single-bit vs bus.** Per-bit cost differs once select inverters are shared across a wide bus.
- **FPGA targets.** A 4:1 mux often fits in one LUT6 along with extra logic, so hand-optimized gate structures are pointless there. The tool maps it.

If the interviewer asks for a *mux using only NAND gates*, use four NAND2s: one as the inverter (NAND with both inputs tied to S), then $Y = \overline{\overline{A\bar S}\;\overline{B S}}$. If they ask for a mux *using only transistors*, give the transmission-gate version.
:::

::: followups
### Build a 4:1 mux from 2:1 muxes. How many do you need and what is the delay?
Three 2:1 muxes: two in the first level controlled by $S_0$ and one in the second level controlled by $S_1$. Worst-case delay is two 2:1-mux delays. In general an $N$:1 tree uses $N-1$ muxes and has depth $\log_2 N$. For 16:1 that is 15 muxes and 4 levels.

### How would you implement a 2:1 mux using only NAND gates?
$Y = \overline{\overline{A\bar S}\cdot\overline{BS}}$. You need $\bar S$ (a NAND with both inputs tied to S), then NAND(A, S̄), NAND(B, S), and a final NAND of those two. That is four NAND2s, or 16 transistors, which is why a transmission-gate cell at 6 transistors is attractive.

### How can a mux implement an arbitrary logic function?
Use the inputs as the select lines and tie the data inputs to constants taken from the truth table. A 4:1 mux with $S_1S_0 = AB$ and data inputs $0,1,1,0$ is an XOR. By Shannon expansion a $2^n$:1 mux implements any $n$-input function, and with the last variable fed to the data inputs it implements any $(n+1)$-input function. This is exactly how FPGA LUTs work.

### Your mux output is used as a clock and the design fails randomly. What's going on?
Probably a glitch or a runt pulse when the select switches, or the select changes while one of the source clocks is high so the output produces a truncated pulse. Fix: use a glitch-free clock mux, where each source has its own enable that is synchronized into that clock's domain and only changes on its falling edge, and one clock is turned off before the other is turned on. Static timing analysis needs the clocks defined as exclusive or asynchronous.

### What if the select signal comes from another clock domain?
Then the select is an asynchronous input to the mux. For data muxes you must synchronize a single-bit select first (two flip-flops). For a multi-bit select you cannot just synchronize each bit, because bits can arrive in different cycles and briefly select a wrong input; use a Gray code, a handshake, or register the data before the crossing. See [[q0887]] on metastability.

### Why would a synthesis tool turn your `if/else if` chain into something slower than a `case`?
`if / else if` means the first true condition wins, so the tool builds a priority structure, effectively a series of 2:1 muxes where late-arriving conditions sit at the front. If you know the conditions are exclusive, a `case` (with `unique case` in SystemVerilog) lets the tool build a parallel, balanced mux with less depth.
:::

::: interpretations
"Design a mux" is deliberately open. The safest reading is a **2:1 mux** at gate level, then generalize to N:1 and show RTL. Some interviewers want a **transistor-level** mux (transmission gates), others want a **parameterized RTL** module, and some want the **glitch-free clock mux**. Ask which depth they want, or cover all three briefly and let them pick where to dig. "Mux" is short for multiplexer. The related questions [[q0888]] (what is a mux?) and [[q0958]] (arbiters, which drive muxes) sit nearby.
