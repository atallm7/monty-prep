::: basics
### In plain words
A DAC (digital-to-analog converter) turns a binary number into a voltage. It is the opposite of an ADC. Each bit of the number switches on a share of the reference voltage. The top bit adds half, the next adds a quarter, and so on, and the shares are added together.

### Picture it
Imagine mixing a drink from measuring cups. There is a cup worth 1/2 liter, one worth 1/4, one worth 1/8. Each bit of the number is a yes-or-no instruction: pour this cup or not. The total in the jug is the output. The code 101 means pour the half and the eighth cups. The jug always ends a little short of a full liter, because the smallest cup is never poured twice.

### Words you need
- **Code**: the binary number you give the DAC.
- **Reference voltage** ([[q0808]]): the voltage that sets the full-scale size of the output.
- **LSB**: the smallest step of the output, the reference divided by $2^N$.
- **R-2R ladder**: a network of resistors with values R and 2R that divides voltage into the binary shares.
- **Reconstruction filter**: a low-pass filter that smooths the staircase output into a smooth voltage.

### The simplest example
Take a 3-bit DAC with a 3.3 V reference. There are $2^3 = 8$ codes, so one step is 3.3 / 8, about 0.41 V. Code 0 gives 0 V. Code 5 (binary 101) gives 5 × 0.4125 V, about 2.06 V. The biggest code, 7, gives about 2.89 V, one step short of 3.3 V. The output between updates is a staircase, so it usually needs a buffer and a filter.

That is the whole idea. The rest of this page shows how the R-2R ladder makes the binary shares, why buffering matters, and where glitches come from.

::: why
DACs generate every analog thing a digital system outputs: bias voltages, reference levels, audio, waveform generators, motor-speed setpoints, LED current setpoints, and the DAC inside every SAR ADC ([[q0810]]). Understanding the ladder and its error sources tells you why a 12-bit MCU DAC isn't really 12-bit accurate, why its output needs a buffer, and why you hear clicks at certain code transitions. It pairs directly with [[q0808]] (the reverse operation) and leads to the design and precision questions ([[q0821]], [[q0822]]).
:::

::: concepts
- **Binary weighting**: bit $k$ contributes $2^{k-N}V_{ref}$ to the output.
- **Superposition and Thevenin**: how a ladder sums contributions ([[q0008]]).
- **Op-amp buffer / summing amplifier**: isolates the ladder or sums currents ([[q0124]]).
- **LSB and full scale**: $V_{LSB}=V_{ref}/2^N$, max output $V_{ref}(1-2^{-N})$.
- **Zero-order hold**: a DAC output is a staircase held for one update period.
- **Reconstruction filter**: low-pass that smooths the staircase ([[q0813]]).
:::

::: answer
"A DAC takes an N-bit digital code and produces a voltage proportional to it: $V_{out}=V_{ref}\cdot\text{code}/2^N$. Each bit switches a binary-weighted contribution, the MSB gives half the reference, the next a quarter, and so on, and they're summed.

The most common way to do this is an R-2R ladder. It's a string of resistors with value R in series and 2R legs, and each leg is switched to either the reference or to ground by one bit. The nice property is that from any node, the rest of the ladder to the right always looks like 2R, the same as the node's own leg, so the node sees R to ground and each stage halves the previous stage's contribution. The result is exactly the binary-weighted sum, using only two resistor values, which is much easier to match than a set of 1, 2, 4, 8 up to 2048 ohms.

For three bits with a 3.3 V reference the outputs step through 0, 0.41, 0.83, up to 2.89 V, one LSB, 0.41 V per code. In real DACs there's a buffer on the output because the ladder has an output resistance of R, and the output is a staircase, so a low-pass filter smooths it.

Other architectures: binary-weighted resistors or currents, a resistor string with a switch tree that's monotonic by construction, current-steering for high speed, and PWM plus an RC filter for the cheap case, which is how many microcontrollers fake a DAC."
:::

::: technical
**Ideal transfer function.** $N$-bit unsigned code $D=\sum_{k=0}^{N-1}b_k2^k$:

$$V_{out}=V_{ref}\frac{D}{2^N},\qquad V_{LSB}=\frac{V_{ref}}{2^N},\qquad V_{FS}=V_{ref}\left(1-2^{-N}\right)$$

**R-2R ladder (voltage mode).** For a 3-bit ladder with legs $2R$ switched to $V_{ref}$ or ground, and a $2R$ terminator to ground at the LSB end:

1. At the LSB node: the leg $2R$ (driven by $b_0V_{ref}$) and the terminator $2R$ to ground. Thevenin: $V=b_0V_{ref}/2$, $R_{th}=R$.
2. Add the series $R$: $R_{th}=2R$, same voltage.
3. At the next node, the $2R$ leg ($b_1V_{ref}$) in parallel with that $2R$ source: $V=\tfrac12(b_1V_{ref}+b_0V_{ref}/2)$, $R_{th}=R$.
4. Repeating gives $V_{out}=V_{ref}\left(\frac{b_2}{2}+\frac{b_1}{4}+\frac{b_0}{8}\right)$ with output resistance $R$.

So from every node the ladder to its right looks like $2R$ (and, with the node's own $2R$ leg in parallel, the node sees $R$ to ground), each bit is attenuated by a factor of 2 per stage, and it takes only two resistor values.

**Binary-weighted summing amplifier.** Resistors $R, 2R, 4R,\dots,2^{N-1}R$ from each bit to the virtual ground of an inverting op-amp with feedback $R_f$: $V_{out}=-R_fV_{ref}\sum b_k/(2^{N-1-k}R)$. For 12 bits the resistor ratio is 2048:1 and the MSB resistor needs about 0.02% accuracy ($2^{-N}$), so it is impractical beyond 8 bits.

**Other architectures.**

| Type | Idea | Strength | Weakness |
|---|---|---|---|
| R-2R ladder | Two resistor values, binary division | Compact, good matching | Glitches at major carry, output impedance $R$ |
| Binary-weighted | Switchable currents/resistors | Simple, fast | Matching across a huge ratio |
| Resistor string | $2^N$ equal resistors, switch tree selects a tap | Inherently monotonic | $2^N$ resistors, slow at high $N$ |
| Current-steering | Switchable current sources into a load | Very fast (GS/s) | Needs matched currents, thermometer coding for the MSBs |
| PWM plus filter | Duty cycle sets average | Needs only a timer and RC | Slow, ripple versus speed trade-off |
| Delta-sigma | 1-bit oversampled stream plus filter | 16 to 24 bits at low rate (audio) | Latency, not for fast DC steps |

**Dynamic behaviour.** The output is a zero-order-hold staircase: after each update it settles (RC of ladder and load, amplifier slew) and holds. At a major carry such as 011...1 to 100...0, many bits switch at once and unequal switching times produce a **glitch**, a brief spike whose energy is specified in nV·s. A deglitching sample-and-hold or segmented (thermometer) MSBs reduce it ([[q0814]]).

**Loading.** An unbuffered R-2R has output resistance $R$, so a load $R_L$ scales the output by $R_L/(R+R_L)$: error $R/(R+R_L)$. A load 100 times $R$ gives about 1%. Use a unity-gain op-amp buffer.
:::

::: long
"A digital-to-analog converter takes an N-bit number and produces a voltage proportional to it: the output is the reference times the code over $2^N$. So a 12-bit DAC with a 3.3 V reference has about 0.8 millivolts per code.

The idea is superposition: each bit adds a contribution that is half of the one above it. The MSB gives half the reference, the next bit a quarter, and so on.

The standard way to do that is the R-2R ladder. It's a chain of series resistors of value R with a 2R leg at each node, and each leg is switched by one bit to either the reference or ground. The reason it works is that when you look to the right from any node, the rest of the ladder is exactly 2R, matching the node's own leg, so a signal injected at one node gets divided by two as it travels to the next. That means each bit's contribution is half the previous one, which is precisely binary weighting, and you did it with just two resistor values, which is much easier to match than a set of resistors ranging from R to 2048 R.

For example, with 3 bits and 3.3 V: code 100 gives half of 3.3, 1.65 V; code 111 gives 7/8, 2.89 V; one LSB is 0.41 V.

In practice a few things matter. The ladder has output resistance R, so a load pulls the output down and you put a buffer op-amp after it. The output is a staircase that's held between updates, so for smooth waveforms you add a low-pass reconstruction filter. And at the big code changes, like 011 to 100, many switches change at the same time, and mismatch in their timing produces glitches.

Other architectures include a resistor string, which is monotonic by construction, current-steering for very high speeds, and sigma-delta for audio. And on a small microcontroller without a DAC, you can use PWM and an RC filter to get an analog voltage."
:::

::: terms
- **LSB**: the step size, $V_{ref}/2^N$.
- **Full-scale output**: the maximum code's output, $V_{ref}(1-2^{-N})$.
- **R-2R ladder**: a resistor network with resistors R and 2R that performs binary division.
- **Monotonic**: output never decreases when the code increases.
- **Glitch / glitch energy**: transient spike at a code transition, often at a major carry.
- **Settling time**: time for the output to reach within a given error band after a code change.
- **Zero-order hold**: output held constant between updates, forming a staircase.
- **Reconstruction filter**: low-pass filter that removes the staircase's image components.
- **Segmented DAC**: MSBs in thermometer code, LSBs binary, trading area for glitch and DNL.
:::

- **Derives the R-2R** with a Thevenin argument (each node sees R to ground) rather than just naming it, and gives a numeric 3-bit example.
- Explains **why R-2R over binary-weighted**: only two values, much easier matching than a 2048:1 ratio.
- Mentions **output impedance and buffering**, the **staircase and reconstruction filter**, and **glitches at major carry**.
- Names **other architectures** with one line on when each is used.
- Ties it to **embedded practice**: on-chip DACs have limited drive, so buffer them; or use PWM with a filter.
:::

::: mistakes
- **Saying max output equals $V_{ref}$.** It is $V_{ref}(1-2^{-N})$, one LSB short.
- **Loading an R-2R ladder directly.** Output resistance $R$ forms a divider with the load; buffer it.
- **Assuming a 12-bit DAC is accurate to 12 bits.** Resolution is not accuracy ([[q0822]]).
- **Thinking binary-weighted resistors scale.** A 12-bit set spans 2048:1 and the MSB needs 0.02% matching.
- **Ignoring the staircase.** Without a reconstruction filter, a DAC's output has images at multiples of the update rate.
- **Forgetting the reference.** The reference sets full scale, and its noise appears directly in the output.
:::

## The idea in one picture

An $N$-bit code is a sum of powers of two. If each bit controls a voltage (or current) of the right weight, summing them gives a voltage proportional to the code. Everything about DAC architectures is about how to make those weights accurately and sum them.

**Derivation by Thevenin reduction, from the LSB end.**

| Step | Network | Thevenin voltage | Thevenin resistance |
|---|---|---|---|
| 1 | $b_0$ leg ($2R$) with $2R$ terminator | $b_0V_{ref}/2$ | $R$ |
| 2 | add series $R$ | $b_0V_{ref}/2$ | $2R$ |

| 4 | add series $R$ | same | $2R$ |
| 5 | node 2: add $b_2$ leg | $\tfrac12\big(b_2V_{ref}+\tfrac12(b_1V_{ref}+b_0V_{ref}/2)\big)$ | $R$ |

Step 5 simplifies to

$$V_{out}=V_{ref}\left(\frac{b_2}{2}+\frac{b_1}{4}+\frac{b_0}{8}\right)=V_{ref}\frac{D}{8}$$

Output resistance is $R$. For $N$ bits the same argument gives $V_{ref}D/2^N$.

## Why R-2R rather than binary-weighted resistors?

A binary-weighted DAC uses resistors $R, 2R, 4R, \dots$ (or currents into a summing amplifier). It works, but:

| | Binary-weighted | R-2R |
|---|---|---|
| Resistor values needed | $N$ different, spanning $2^{N-1}:1$ | 2 values |
| 12-bit ratio | 2048:1 | 2:1 |
| MSB accuracy needed | about $2^{-N}=0.024\%$ at 12 bits | same relative matching, but only between equal-type resistors |
| Layout | Hard to keep the same process behaviour across a huge ratio | Units of $R$ replicated: good matching |

R-2R still needs resistors matched to roughly $2^{-N}$ relative accuracy for the MSBs, but it is easy to build them from identical unit resistors (2R is two R in series), which tracks across temperature and process.

## Output loading and buffering

The ladder looks like an ideal source $V_{ref}D/2^N$ in series with $R$. A load $R_L$ reduces the output by $R_L/(R+R_L)$. With $R=10$ kΩ and $R_L=10$ kΩ the output halves; to keep the error under 0.5 LSB at 12 bits you'd need $R_L>R\cdot2^{13}=82$ MΩ, i.e. effectively infinite. So a unity-gain op-amp buffer is nearly always used. The same buffer can supply gain if the output range needs scaling, $V_{out}=(1+R_2/R_1)V_{ref}D/2^N$.

## The staircase and the reconstruction filter

A DAC outputs a new level each update period $T_s$ and holds it: a zero-order hold. In the frequency domain the hold has a $\text{sinc}(f T_s)$ response, which droops by 3.9 dB at $f_s/2$, and the staircase has images of the signal around $f_s,2f_s,\dots$. A low-pass reconstruction filter removes the images. For audio the DAC runs oversampled (96 kS/s or more) so the filter can be gentle.

## Where it goes wrong: glitches

At the code change 011 to 100, all three bits flip. If the MSB switch turns on slightly before the others turn off, the output briefly goes to 111 (about $V_{ref}\cdot7/8$), a spike many LSBs tall for a few nanoseconds. The product of height and width is the **glitch energy**, in nV·s. Fixes: a sample-and-hold deglitcher after the DAC ([[q0814]]), a segmented architecture with thermometer-coded MSBs (only one more segment switches at a time), or a filter.

## Other architectures in a sentence each

- **Resistor string:** $2^N$ equal resistors and a switch tree choose one tap; monotonic by construction, DNL tiny, but $2^N$ resistors. Used for low-to-medium resolution on-chip DACs.
- **Current-steering:** each bit steers a binary-weighted current to the output; high speed, used in video and RF DACs.
- **PWM plus filter:** a timer produces a duty cycle $D$; an RC filter averages it to $V_{ref}D$. Resolution = timer counts, ripple versus settling is the trade-off ([[q0821]]).
- **Delta-sigma DAC:** an oversampled 1-bit stream with noise shaping, then a filter; audio standard.
:::

::: applications
- **Microcontroller analog outputs**: 8 to 12-bit DAC peripherals for bias, set-points and audio beeps.
- **Audio codecs and music players**: oversampling delta-sigma DACs with 16 to 24 bits.
- **The DAC inside a SAR ADC**: a capacitor array doing the same binary summation ([[q0810]]).
- **Waveform and function generators**: direct digital synthesis with a high-speed current-steering DAC.
- **LED and laser current control**: DAC sets the reference of a current regulator.
- **Industrial 4–20 mA and 0–10 V outputs**: precision DAC plus output driver.
- **Programmable power supplies**: DAC sets the feedback or reference of a regulator.
:::

::: assumptions
- An **ideal, unsigned, unipolar voltage-output DAC** with a stable reference, ideal switches and ideal matching. Real parts have offset, gain error, INL, DNL ([[q0822]]).
- R-2R analysis assumes ideal switches (zero on-resistance) and a **voltage-mode** configuration; a current-mode R-2R (reference into the ladder end, op-amp virtual ground at the output) changes the output resistance and the effect of switch resistance, but the binary-weighting principle is the same.
- A **zero-order hold** output, not an impulse train.
- **Bipolar and offset-binary DACs** shift and scale the output ($\pm V_{ref}$), but the core logic is unchanged.
- The interviewer may mean a *specific* DAC (R-2R, most likely). If asked "how does a DAC work?" without detail, lead with the generic idea and draw the R-2R.
:::

::: followups
### What's the output of a 12-bit DAC with a 2.5 V reference at code 1000?
$2.5\cdot1000/4096=0.6104$ V. One LSB is $2.5/4096=0.610$ mV. Full scale is 2.4994 V.

### Why does the R-2R ladder need a buffer?
Its output resistance is $R$ (for example 10 kΩ). Any load draws current through that resistance and pulls the output down by $R_L/(R+R_L)$, and any capacitive load slows settling. A unity-gain op-amp buffer isolates the ladder and delivers the current.

### What's the difference between DNL and monotonicity for a DAC?
DNL is the deviation of each step from 1 LSB. A DAC is monotonic if every step is positive, which is guaranteed if DNL > −1 LSB everywhere. A DNL of −0.5 means a step was only half an LSB; −1 means the output didn't change; below −1 means the output went backward.

### How would you make an analog output from a microcontroller with no DAC?
PWM from a timer with an RC low-pass: the average voltage is $V_{DD}\cdot D$. With a 16 MHz timer and 12-bit resolution the PWM frequency is 3.9 kHz, so a single RC needs a long time constant to get below an LSB of ripple, hence a 2nd-order or active filter. Or use an external R-2R network on GPIOs ([[q0821]]).

### Harder: when you step a DAC from 0x7FF to 0x800 on a 12-bit R-2R, the scope shows a spike. Why, and how do you fix it?
It's the major-carry glitch: the MSB switches slightly earlier than the lower 11 bits (or slower), so for a few nanoseconds the code is momentarily 0xFFF (or 0x000). Fixes: segment the MSBs in thermometer code, add a deglitching S/H, make the switches' delays match, or put an RC/low-pass on the output (a filter spreads the glitch but doesn't remove its energy).
:::
