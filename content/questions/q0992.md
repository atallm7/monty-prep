::: basics
### In plain words
A trigger tells the scope when to start each sweep of the screen. Without one, every sweep starts at a random point in the signal, so a repeating waveform smears or scrolls. With an edge trigger you pick a voltage level and a direction, rising or falling. Each sweep then starts at exactly that crossing, so all sweeps line up and the picture holds still.

### Picture it
Imagine timing runners on a track, and you start a stopwatch each time one crosses the same marker, going the same way. If you overlay all the laps, they line up neatly because each begins at the same place. If you started the stopwatch at random moments, the laps would not line up. A trigger is that marker. A scope can also keep data from before the marker.

### Words you need
- **Trigger level**: the voltage the signal must cross to start a sweep.
- **Slope**: whether the crossing is rising or falling.
- **Auto, normal, single mode**: auto always shows something, even without a trigger. Normal only updates when a real trigger happens. Single captures one event, then stops.
- **Holdoff**: a pause after a trigger during which new triggers are ignored, useful for bursts of pulses.
- **Pre-trigger**: the part of the capture recorded before the trigger event.

### The simplest example
Look at a 1 kHz sine wave. Set an edge trigger at 0 V, rising. Each sweep begins when the signal crosses 0 V going up, which happens every 1 ms. All the sweeps overlay, and you see a steady sine.

Now debugging: a microcontroller resets now and then. Trigger on the reset line falling, in single mode, and put the supply voltage on a second channel. Place the trigger late on the screen so most of it shows history. Now you can see whether the supply dipped just before the reset.

That is the whole idea. The rest of this page adds noise handling, holdoff, and special triggers for rare glitches.
:::

::: testing
Whether you can actually *drive* a scope to catch the thing you care about. Anyone can say "a trigger makes the waveform stable." The interviewer wants to hear the settings (source, level, slope, mode, coupling, holdoff), the common trigger types beyond edge (pulse width, runt, timeout, serial), and a practical procedure for a noisy signal or a rare glitch. Hidden sub-skills: reasoning about signal timing, knowing the difference between auto, normal and single mode, and using pre-trigger history as a debug tool.
:::

::: why
The trigger is the difference between a scope that is useful and one that shows a smear. In real debug, you rarely look at a nice repeating square wave: you hunt for a 30 ns glitch that appears once a second, or the moment a rail droops before a reset, or the first byte of an SPI frame. Setting a good trigger is how you make the instrument look where the problem is. Interviewers ask because it shows if you have used the scope for debugging rather than reading a clean clock.
:::

::: concepts
- **Time reference**: a trigger defines $t=0$ for each acquisition so repeated sweeps overlay. See [[q0991]] for how the circular buffer enables pre-trigger viewing.
- **Comparator and hysteresis**: the trigger is a comparator on the signal against a level, with hysteresis to ignore noise.
- **Edge slope**: rising or falling crossing of the level.
- **Noise and bandwidth**: the trigger path has its own bandwidth and sensitivity, and noise near the threshold causes false triggers.
- **Signal timing**: pulse widths, periods and bursts decide holdoff and which advanced trigger to use.
- **Digital protocols**: serial triggers match bit patterns, addresses, errors. See [[q0994]] for multi-channel use.
:::

::: technical
**Basic edge trigger parameters**
- **Source**: a channel, external trigger input, or line (mains) reference.
- **Level**: threshold voltage. Best placed on the steepest, cleanest part of the edge, and outside the noise band. Setting it at the very top of a ringing signal causes double triggering.
- **Slope**: rising, falling, or either.
- **Coupling**: DC (all), AC (blocks DC so the level is relative to the mean), HF reject (low-pass the trigger path), LF reject (high-pass, ignore mains hum), noise reject (increase hysteresis).
- **Mode**: *Auto* free-runs after a timeout if no trigger, so you always see something. *Normal* only updates when triggered, so you see nothing if the condition isn't met. *Single* arms once, captures one record when triggered, then stops.
- **Holdoff**: after a trigger the scope ignores new triggers for a set time, so multi-edge bursts do not retrigger partway through.

**Advanced triggers**
| Trigger | Fires when | Typical use |
|---|---|---|
| Pulse width | Pulse is shorter/longer/equal to a limit | Narrow glitches, stuck lines |
| Runt | Pulse crosses one threshold but not the other | Weak drivers, bus contention |
| Window | Signal enters or leaves a voltage band | Rail excursions |
| Timeout | No edge for longer than T | Missing clock or heartbeat |
| Setup/hold | Data changes inside a window around a clock edge | Digital timing violations |
| Pattern/logic | Combination of channels is true | State of a parallel bus |
| Serial (I²C, SPI, UART, CAN…) | Address, data, start, error | Protocol debugging |
| Sequence (A then B) | Event B after event A with delay | Cause-and-effect |

**Placement**: the horizontal delay sets what fraction of the record is pre-trigger. A 10 Mpts record at 20% pre-trigger keeps 2 Mpts of history before the event.

**Jitter and noise**: trigger-level noise $v_n$ on a slope $dv/dt$ gives timing jitter $\Delta t\approx v_n/(dv/dt)$. A 5 mV noise on an edge slewing at 1 V/ns gives 5 ps; on a 1 V/µs ramp it gives 5 ns. Trigger on the steepest edge available.
:::

::: long
"A trigger is how the scope decides where to start drawing. Without one, every sweep begins at an arbitrary moment, so a repeating signal smears or rolls across the screen. With a trigger, each sweep starts when something specific happens, so all the sweeps overlay and the waveform looks frozen.

The simplest one is the edge trigger. I choose the source channel, a voltage threshold and a slope. For a 3.3 volt logic clock I'd put the level around 1.5 volts, in the middle of the edge and well above the noise, and trigger on rising. If the signal is noisy or has ringing, I move the level to the steepest clean part of the edge, turn on noise reject or HF reject, or raise the hysteresis, so the scope doesn't trigger twice on one edge.

Then there are modes. Auto mode is the default for exploring because it will free-run if nothing triggers, so I always see a trace. Normal mode only displays when the trigger condition is met, which is better when I'm waiting for a particular event. Single mode arms once, captures one record, and stops. That's what I use for a power-up or a one-off glitch.

Holdoff matters for bursty signals. If I have a burst of eight pulses and then a gap, an edge trigger will land on a random pulse in the burst. Setting the holdoff longer than the burst but shorter than the gap makes it trigger on the first pulse.

For real debug I go beyond edges. A pulse-width trigger catches a 20 nanosecond glitch in a stream of 1 microsecond pulses. A runt trigger finds pulses that don't reach full amplitude. A timeout trigger fires if a clock stops. Serial triggers can fire on an I²C NACK. And because the scope keeps data from before the trigger, I can trigger on the symptom, like a reset line going low, and look backwards at the supply."
:::

::: terms
- **Trigger level**: the voltage threshold the signal must cross.
- **Slope**: direction of the crossing (rising or falling).
- **Hysteresis**: a gap between the rising and falling thresholds of the trigger comparator that rejects noise.
- **Auto / Normal / Single**: free-run fallback, wait-for-trigger, and one-shot modes.
- **Holdoff**: dead time after a trigger during which new triggers are ignored.
- **Pre-trigger**: the portion of the record captured before the trigger event.
- **Runt pulse**: a pulse that fails to reach the full logic threshold.
- **Trigger coupling**: DC, AC, HF reject, LF reject or noise reject on the trigger path.
- **Trigger jitter**: variation in the trigger timing due to noise on the edge, $v_n/(dv/dt)$.
:::

::: exceptional
**An average answer** says "it stabilizes the waveform; set level and slope."

**An exceptional answer**:
- Explains why: each sweep needs a consistent time reference, so sweeps overlay.
- Names auto vs normal vs single and when each is used.
- Gives a concrete recipe for a noisy or bursty signal (level on steep part, noise reject, holdoff longer than the burst).
- Knows at least three non-edge triggers and a use case for each.
- Mentions pre-trigger history and triggering on a symptom, then viewing the cause.
- Quantifies jitter as $v_n/(dv/dt)$ and chooses the steepest edge.
:::

::: mistakes
- **Setting the level outside the signal.** The scope never triggers (normal mode shows nothing; auto mode free-runs and the picture rolls).
- **Using auto mode and trusting a "stable" display.** In auto mode the scope may be free-running and displaying garbage that happens to look stable. Check the trigger indicator.
- **Triggering at the peak of a noisy edge**, leading to double or random triggering. Use the steepest part of the edge.
- **Forgetting holdoff on bursts**, so the display jumps among pulses of the burst.
- **Using single mode with the time base too fast** or the trigger position wrong, so the interesting event falls outside the window.
- **Triggering on the wrong channel** or using the wrong slope for the event.
:::

## Why a trigger exists

A scope draws repeating sweeps. If each sweep starts at an arbitrary phase of a 1 kHz sine, the traces land at different horizontal positions and the screen shows a blur. If every sweep starts when the signal rises through 0 V, the traces overlap and you see a clean sine.

Physically the trigger is a comparator: its output flips when $v(t)$ crosses a level $V_{th}$. Hysteresis $V_H$ means it flips high at $V_{th}+V_H/2$ and low at $V_{th}-V_H/2$, which prevents multiple triggers from noise sitting on the threshold.

## The recipe for a normal edge trigger

1. **Pick the source** you are looking at (or the channel that carries the *cause*).
2. **Set the level** in the steepest, cleanest part of the edge: for logic, about half the swing (1.65 V for a 3.3 V signal). Many scopes have an "auto level" or "set to 50%" button.
3. **Choose the slope** that corresponds to the event.
4. **Choose the mode.** Auto to explore; Normal to wait for a specific event; Single for one-shots.
5. **Adjust horizontal position** so the trigger point sits where you want history: left of center for post-event details, right of center to see what led up.
6. **Check the trigger indicator** (Trig'd / Armed / Ready). If it says Auto or flashes without a stable image, your trigger conditions are not being met.

Trigger-level noise gives jitter: $\Delta t = v_n/(dv/dt)$. For a 3.3 V edge with 2 ns rise time the slope is about $3.3\times0.8/2\,\text{ns}=1.3$ V/ns, so 5 mV of noise gives ~4 ps. The same noise on a slow 3.3 V ramp over 1 ms (3.3 V/ms) gives 1.5 µs. This is why you trigger on edges, not slow wandering voltages, whenever you have the choice.

## Trigger coupling and noise rejection

| Coupling | Effect | Use |
|---|---|---|
| DC | Trigger on the raw signal | Logic and DC-level signals |
| AC | Series capacitor blocks DC, trigger level relative to mean | Signals with changing DC offset |
| HF reject | Low-pass the trigger path | Noisy signal with slow wanted content |
| LF reject | High-pass the trigger path | Remove hum and drift |
| Noise reject | Wider hysteresis | Small noise near threshold, at some cost in sensitivity |

## Holdoff

## Beyond edges: finding the weird stuff

- **Pulse width.** Say the line normally pulses 1 µs high. Trigger on "width < 100 ns" to catch the runt-ish glitch. Combine with single mode and a long record to find a once-an-hour event.
- **Runt.** The pulse crosses the low threshold but never reaches the high threshold; classic for contention between two drivers or a slow, weak rail.
- **Timeout.** Fire if no edge for 5 ms. Used to catch a stalled clock or heartbeat, at the moment it stops.
- **Setup/hold.** Trigger when data changes within a window around the clock edge, which catches the one violation in billions.
- **Serial.** Trigger on I²C "address 0x48 + NACK", SPI on a particular word, UART on a framing error, then decode the bytes and look at the physical waveform.
- **Sequence (A then B).** Arm on a power-good signal falling, then trigger on a reset line asserting within 10 µs.

## Triggering on the symptom, viewing the cause

The trick that makes triggers a debugging tool: trigger on the *effect* (reset pin goes low, I²C NACK, error flag) and set the trigger position to 80–90% so most of the screen is pre-trigger history. Put the supply rail on channel 2. You then see exactly what the supply did in the microseconds before the failure. This is cause-and-effect analysis that no multimeter can do.

> [!TIP]
> If you cannot trigger on the thing you want to see, trigger on something that happens near it, even on a different channel or the external input, then use the horizontal delay to look at the thing itself.

## Real-hardware behavior

- **Trigger path bandwidth and sensitivity.** The trigger circuit has its own specs. A scope may display a 200 MHz signal fine but have a trigger that only works reliably up to 100 MHz or needs a minimum amplitude (e.g. 1 division).
- **Dead time.** After a trigger the scope processes and re-arms. If the glitch happens during dead time you miss it. High waveform-capture rates and segmented memory reduce this.
- **Mains hum triggers.** "Line" trigger syncs to the mains frequency, useful for power-line-related noise.
- **External trigger input** has different impedance and range (often ±5 V or less), so check limits before connecting.
:::

::: applications
- **Capturing the supply droop that causes an MCU reset**: trigger on the reset line, look at pre-trigger on the rail.
- **Catching a glitch on a clock or enable line**: pulse-width trigger, single mode.
- **Decoding a failed I²C transaction**: trigger on NACK or on a specific address.
- **PWM and motor drives**: trigger on a gate signal and look at current/voltage on another channel; holdoff for burst-mode switching.
- **Boot sequencing**: single-shot capture of multiple rails ramping, triggered on the first enable.
- **Timing margin checks**: setup/hold trigger on a memory interface.
:::

::: assumptions
- Assumes a **modern digital scope** where the trigger and acquisition are separate paths and pre-trigger data is available. On an old analog scope there is no pre-trigger viewing without a delay line.
- Assumes the signal has some **identifiable event** (an edge or pulse) to trigger on. For truly random noise there is no good trigger, and you might use averaging or an FFT instead.
- Numerical examples assume 3.3 V logic. For 1.8 V logic, level choices scale accordingly.
- The jitter formula assumes noise small relative to the edge swing and a linear edge.
- Menu names and exact options differ by vendor, but the concepts are identical.
:::

::: followups
### My signal is noisy and the trigger is jittery. What do I do?
First, move the level to the steepest part of the edge, which minimizes $v_n/(dv/dt)$. Then turn on noise reject or raise the hysteresis, use HF reject if the noise is above the signal band, or add bandwidth limiting on the channel. If it is still bad, probe the signal better (shorter ground, lower-noise setup), because the noise might be real coupling.

### How do I capture a glitch that happens once an hour?
Use single or normal mode with a pulse-width (or runt) trigger tuned to the glitch, and make sure the sample rate is fast enough for its width. Segmented memory lets me keep many triggered records without the scope stopping at the first one. If I need hours, I'd use a very high waveform capture rate with persistence or the scope's "stop on violation" masks.

### What is the difference between auto and normal trigger mode?
In auto mode, if no trigger arrives within a timeout, the scope triggers itself and shows a free-running (unsynchronized) trace, so you always see something. In normal mode the screen only updates when a real trigger occurs, which is what you want when the signal is rare or you want to be sure each display is a valid triggered capture.

### Why trigger on a different channel than the one you're measuring?
Because the cause and the symptom are often on different nets. I trigger on the symptom (e.g. a reset line asserting) because it's clean and unambiguous, and I put the suspect signal (the supply rail) on another channel with the trigger position late in the record so I see its history.

### What if the scope won't trigger on a 100 mV signal at 500 MHz?
The trigger path may not have enough sensitivity at that frequency; scopes specify minimum trigger amplitude (e.g. 0.5–1 division, rising with frequency). I'd increase the vertical scale sensitivity so the signal fills more of the screen, switch off any trigger bandwidth limiting, probe with a better probe (active), or trigger on a divided-down or cleaner version of the signal, like an enable or an external clock.
:::
