# Review of batch b51 (q0894–q0913)

Reviewer checks: I recomputed every number, worked example and quiz answer with `node`. That covers the K-map cover and POS, which I brute-forced over all 16 inputs; the FSM next-state equations; the Mealy/Moore and PC timing traces; the RISC-V encodings; and all the CPI, Amdahl, AMAT, DVFS and cache-geometry arithmetic. I rendered the q0902 schematic and screenshotted all 16 embedded sims against their captions. `validate-content` reports 0 errors and no warnings for these ids.

- **q0894** OK.
- **q0895** The technical section said the POS form had "the same number of literals" as the SOP. It is actually 6 vs 7, which the deep dive and the kmap-lab sim both confirm, so I corrected it.
- **q0896** OK. The 101 detector table, D1/D0 equations and trace are verified.
- **q0897** OK. The Mealy/Moore timing traces are verified cycle by cycle.
- **q0898** OK.
- **q0899** Corrected the Cortex-M pipeline depth: "3 to 8 stage" became "2 stages on M0+, 6 on M7". Softened the unsourced "10 to 100 times more energy-efficient" claim for accelerators, and changed "many times" to "several times" to match the technical section.
- **q0900** Corrected the register count: A64 has 31 GPRs, not 32.
- **q0901** Rewrote the cache-lab caption. The sim defaults to 2-way, so the caption now tells the reader to select 1-way for the conflict demo, and it describes what the sequential trace actually shows (87.5% hits).
- **q0902** The SLT tip in the ALU design note said only "feed back the MSB". It now says the MSB must be XORed with overflow to give the true sign. The schematic is electrically correct.
- **q0903** The page claimed "the ISA requires alignment for branches" in a sentence that also covered x86, which has no such rule. It now says RISC-V requires 2/4-byte alignment and x86 has none.
- **q0904** The interrupt timing diagram reused the loop example's addresses but resumed at 0x0C after 0x08, which is a `jal` there, so the trace was impossible. I made it a separate straight-line example at 0x100–0x114 and clarified the caption.
- **q0905** The control-FSM edge for a 3-cycle jump was labelled `jal`, but `jal` writes a link register. Relabelled it as a jump with no link. The pipeline-lab caption called the "alu" program "independent instructions"; it is actually a dependent chain covered by forwarding, so I fixed that.
- **q0906** Corrected the Cortex-M0/M3/M4 pipeline to "3-stage (M0+ is 2)". Fixed the same "independent instructions" caption error.
- **q0907** OK. All UART/DMA/Amdahl/break-even numbers are verified.
- **q0908** The cache-lab "stride" caption was wrong. It blamed conflict misses and said adding ways would help. The sim shows 0% hits from compulsory plus capacity misses, with a flat hit-rate-vs-ways chart. Rewrote the caption to match.
- **q0909** The timing-diagram caption claimed all five stages were busy with four instructions, which cannot happen. Corrected it. The applications section said "3 stages in M0/M0+"; changed to "3 in M0, 2 in M0+". Fixed the "independent" wording in the sim caption.
- **q0910** The comparison table listed BTFN on an alternating branch as "50% or worse"; a static scheme gets exactly 50%. Also fixed "third cycle after its fetch" to "its third pipeline cycle (two cycles after fetch)".
- **q0911** Changed embedded interrupt latency from "microsecond range" to "often well under a microsecond on a Cortex-M" (12 cycles at 48 MHz is 0.25 µs). Corrected the title of the Yiu book.
- **q0912** OK.
- **q0913** OK. All five RISC-V hex encodings are verified.

Remaining concerns (minor, not errors):
- Pages q0900, q0905 and q0906 use one illustrative stage-delay set (IF 250 ps, 50 ps overhead). Page q0909 uses a different one (IF 200 ps, 20 ps overhead). Each page is internally consistent, but a reader comparing pages may notice.
- Several prereq/concept links point to q0886 ("What is a register") for flip-flop background. That is acceptable but not ideal.
