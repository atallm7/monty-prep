# QA review: batch b24 (q0402–q0419)

I recomputed every number and quiz answer with `node`. I screenshotted every figure and sim in the running app and re-shot each edited figure, and re-rendered every edited schematic. I checked sim params against catalog.json and checked each caption against the sim source (dc-motor-lab, encoder-lab, flyback-protection, servo-lab, pwm-lab, h-bridge-lab, mosfet-lab, gate-drive, timer-lab, multiphase-buck). I re-ran the self-simulated solenoid model myself with a flux-linkage time-stepping script in Node, using the stated parameters (24 V, 12 Ω, 20 g, 1.2 N + 100 N/m, L(g) = 30 mH + 0.21 mH·m/(g + 1.5 mm)). The validator reports 0 errors.

**Most serious:**
- **q0405:** the quadrature state sequence was backwards relative to its own timing diagram and to the encoder sim (A leads B means 00→10→11→01). The +1/−1 table was inverted as well.
- **Wrong solenoid simulation numbers (q0406, q0415):**
  - **q0406:** impact velocity was stated as 2.27 m/s. That was a 0.5 ms sample taken before impact; the true value at arrival is about 2.7 m/s.
  - **q0415:** the "72 V + hold, plain diode" release figures (18.3 ms / 32.9 ms) and the from-hold clamp release (2.9 ms) did not match the model. Re-simulated: 10.7 ms / 28 ms and about 1 ms. Closure times were refined to 12.8, 10.1, 7.5 and 6.2 ms.
  - The current waveforms and position curves did reproduce.
- **q0408:** the brush-drop error was quoted as "3–6 rpm per 0.1 V". At Ke = 0.02 it is about 48 rpm per 0.1 V.
- **q0411:** "slow decay" voltage, the plugging multiple and the stall-heating explanation were physically wrong (it claimed V/R peaks with a 1 ms L/R at 20 kHz).
- **q0410:** the caption gave the wrong brake-current direction.

## Remaining concerns
- **Solenoid model plausibility (q0406, q0407, q0415):** the numbers are plausible for a large (48 W, intermittent-duty) DC solenoid at 24 V. However, the inductance model has no saturation, so the force near closure is high (hundreds of N at 4 A). The 72 V impact velocity (about 6.7 m/s) is therefore an overestimate; the text now says so. The pages flag the model as illustrative.
- **Plot renderer:** y-axis titles overlap tick labels on several plots.
